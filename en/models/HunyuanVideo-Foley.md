## Basic Information

### Name

HunyuanVideo-Foley (Tencent Hunyuan Video Foley model, full name "HunyuanVideo-Foley: Multimodal Diffusion with Representation Alignment for High-Fidelity Foley Audio Generation")

### Publishing Organization/Company

Led by Tencent Hunyuan, jointly with Zhejiang University and Nanjing University of Aeronautics and Astronautics. Author list: Sizhe Shan (单思哲, first author), Qiulin Li, Yutao Cui, Miles Yang, Yuehai Wang, Qun Yang, Jin Zhou, Zhao Zhong. The project homepage is maintained by szczesnys. It is positioned as the companion model that fills in the "sound" component following HunyuanVideo (video generation) within Tencent Hunyuan's open-source matrix; it shares the brand with the HunyuanVideo series but not the model architecture.

### Release Date (technical report/paper/open-source date)

Submitted to arXiv on August 23, 2025 (arXiv:2508.16930v1, UTC 07:30:18); officially open-sourced on GitHub / HuggingFace on August 28, 2025, releasing inference code and XXL model weights; an XL version of the weights and offload low-VRAM inference support were added on September 29, 2025. It has since entered a maintenance/iteration phase, with no v2 paper revision observed.

### Type (model/dataset/toolchain/benchmark)

A model (with a complete inference toolchain attached). The core is a text-video-to-audio (TV2A) sound-effect generation model, i.e., given video + text description, it generates Foley sound effects synchronized with the visuals. It is not a video generation model itself, but a companion model for the "dubbing/sound-effects" stage that pairs with video generation models. It also comes with an in-house audio VAE (DAC-VAE, 48kHz). No dataset is released, and no evaluation benchmark is released (evaluation reuses others' Kling-Audio-Eval, MovieGen-Audio-Bench, VGGSound-Test).

### Degree of Openness (whether weights/code/data/pipeline are each open-sourced)

Moderate openness, a typical "open weights and inference, closed training and data" pattern.
【Weights】Open source. HuggingFace tencent/HunyuanVideo-Foley provides two variants: XXL (default, hunyuanvideo_foley.pth, requiring about 20GB VRAM for regular inference, 12GB in offload mode) and XL (hunyuanvideo_foley_xl.pth, 16GB / 8GB offload). The weights of the in-house 48kHz DAC-VAE audio autoencoder and the Synchformer sync-feature extractor configuration are also open.
【Code】Inference code is open source (infer.py for batch inference, gradio_app.py for the web interaction UI, hunyuanvideo-foley-xxl.yaml configuration file), based on HuggingFace diffusers. Training code is not open source.
【Data processing pipeline】Only about one paragraph of process description is given in Section 3.1 of the paper — the order of the seven stages and some threshold values (8-second segmentation, 80% silence ratio, 32 kHz effective sample rate) are given specific numbers, but no cleaning scripts, model configurations, prompts, or stage-by-stage statistics are disclosed. Reproducibility sits at the level of "know what was done, don't know how to tune the parameters."
【Data】The 100,000-hour TV2A dataset is not open sourced at all, and its raw sources are also undisclosed.
【License】tencent-hunyuan-community community license (not a standard OSI open-source license); the HuggingFace model card sets extra_gated_eu_disallowed: true, explicitly restricting access for users in the EU region. This is a consistent practice across the Tencent Hunyuan model series; commercial use must comply with the community license terms.

### Whether Simultaneous Audio-Video Generation Is Supported, and How (native joint/cascaded/MoE fusion)

Not supported — this is the key to understanding this work's positioning. HunyuanVideo-Foley is the "back half" of a cascaded paradigm: the video already exists (it can be real footage, or a silent video generated by a model such as HunyuanVideo), and the model's task is to add sound effects to it. So strictly speaking it belongs to V2A / TV2A (Text-Video-to-Audio) unidirectional conditional generation, rather than the native joint generation seen in UniVerse-1, MOVA, or Ovi.
【Division of labor versus joint-generation models】Joint-generation models must simultaneously solve "what the video looks like" and "what the sound is"; this model only solves the latter, so all model capacity and data budget can be invested in audio-side fidelity and synchronization precision — this also explains why its audio quality metrics (PQ 6.59, MOS-Q 4.14) are markedly higher than contemporaneous joint-generation models.
【Architectural implementation】A hybrid multimodal diffusion Transformer of about 3 billion parameters: a front section of 18 MMDiT layers (multimodal dual-stream blocks, where audio and video tokens go through their own parameter branches but share one joint self-attention pass), followed by a back section of 36 unimodal audio DiT layers (pure audio single-stream blocks that refine audio detail). Hidden dimension 1536, 12 attention heads.
【Three condition-injection pathways, each different】(1) Video semantics — a SigLIP-2 visual encoder extracts frame features, which are concatenated with the audio latent and deeply fused via joint self-attention; (2) Text semantics — encoded by a CLAP text encoder and injected via cross-attention (deliberately routed differently from video; the paper states this is meant to resolve "modal competition," i.e., to prevent the dominant visual condition from drowning out the text condition); (3) Frame-level sync signal — Synchformer extracts frame-level sync features, injected via an adaLN + gated modulation pathway, which does not participate in attention computation.
【Interleaved RoPE】Audio tokens and visual tokens are interleaved along the time axis before rotary position encoding is applied, so that audio and visual tokens at the same instant are positionally adjacent to each other in the encoding, reinforcing frame-level synchronization dependence. Ablation shows that removing it worsens DeSync from 0.78 to 0.79 and changes CLAP by 0.30, with the impact mainly on temporal alignment.
【Audio representation】An in-house DAC-VAE, 48 kHz sampling rate, replacing DAC's original RVQ discrete quantization block with a continuous variational autoencoder using a Gaussian distribution + KL regularization, outputting a 128-dimensional continuous latent at a latent frame rate of 50 Hz.

## Data Scale and Distribution

### Training Data Scale (number of video clips/hours/tokens, pretraining vs. SFT split) ⚠️

【Final output】Approximately 100,000 hours (~100k hours) of text-video-audio triplet (TV2A) data — this is the core number presented as the paper's first major contribution in the abstract ("a scalable data pipeline curating 100k-hour multimodal datasets through automated annotation").
【Accounting note】Only an hour count is given; the number of clips is not disclosed. Assuming fixed 8-second segmentation, 100,000 hours roughly corresponds to about 45 million clips — a rather large scale, which also explains why the paper emphasizes the pipeline's "scalability" rather than its fineness.
【No pretraining/SFT split】The entire TV2A main model has only a single training stage; the full 100,000 hours of data participate all at once — there is no scale split between pretraining and SFT, and no annealing stage over a high-quality subset.
【Independent data for the audio autoencoder】The DAC-VAE is trained separately for 700k steps using "about 100,000 hours of audio data." The paper does not clarify whether this 100,000 hours of audio is the same batch's audio track as the 100,000-hour TV2A data — inferring from the numerical coincidence and the process order, it is plausibly the same source or heavily overlapping, but there is no explicit statement. [Uncertain]
【Correspondence with training compute】Main model: 128 H20 GPUs, effective batch size 2048, 200k training steps; VAE: 32 H20 GPUs, batch size 256, 700k steps. Neither GPU-days nor total training duration is disclosed.
【Scale positioning】100,000 hours is a top-tier scale in the V2A track: for reference, the public dataset VGGSound is only about 550 hours (per the paper's stated usage), and AudioSet is about 5,800 hours; i.e., this work's self-built data scale is about 180x that of VGGSound. Relative to contemporaneous Kling-Foley and MMAudio, this data-scale advantage is one of the main factors the paper attributes its audio-quality lead to.

### Data Source Composition (proprietary/public datasets/web crawling/licensed procurement/synthetic data) ⚠️

The paper is extremely reserved in disclosing data sources — this is the biggest information gap on the data side of this work:
【Self-built TV2A data (100,000 hours)】Described only as "collected audio-visual data," without stating whether it was web-crawled, drawn from Tencent's own content library (Tencent Video/Weishi, etc.), commercially procured, or a mix of all three, and without giving any platform names or a content-source list. Given that Tencent itself owns large-scale video content assets, and that the paper deliberately avoids describing sources, it is inferred that the data is primarily from proprietary/licensed content libraries supplemented by web collection, but there is no evidence to support this. [Uncertain]
【Explicitly named public datasets (used only for evaluation or VAE evaluation, not primary training)】VGGSound (the paper mentions about 550 hours, used as VGGSound-Test evaluation), AudioCaps, WavCaps, AudioSet (used for DAC-VAE reconstruction-quality evaluation), Song Describer (music reconstruction evaluation), LibriTTS (speech reconstruction evaluation). These datasets appear in the paper mainly in the evaluation stage; it is not explicitly stated that they are included in the 100,000-hour main training set.
【Synthetic data】No model-synthesized audio or video content is used. The only "synthetic" component is that all captions are automatically generated by the GenAU model (synthetic annotation rather than synthetic content).
【Licensed procurement】Not mentioned.
【Comparison with similar work】UniVerse-1 explicitly lists a YouTube content-category list and Pexels; MOVA also gives a source composition; HunyuanVideo-Foley talks entirely about the process without discussing sources at all — a "disclose the method, hide the raw material" strategy that is fairly common in work led by commercial companies.

### Data Compliance and Provenance (proportion of licensed data, rights-cleared datasets, C2PA, etc.) ⚠️

Neither the paper nor the model card discusses the compliance and provenance of the training data: no proportion of licensed data is given, no rights-cleared dataset is declared, no C2PA or any output-side audio watermark/provenance marking is mentioned, no music copyright risk is discussed (even though the pipeline explicitly includes a music-detection stage, indicating that music content does indeed exist in the data), and speaker/voice privacy is also not discussed.
【The observable compliance posture is on the model side, not the data side】A tencent-hunyuan-community community license is used instead of a standard open-source license such as Apache-2.0, and extra_gated_eu_disallowed: true is set on HuggingFace, explicitly excluding users in the EU region — the latter is generally interpreted as a way to sidestep the EU AI Act's training-data-summary disclosure obligation and compliance review for general-purpose AI models. This setting itself is an indirect signal about uncertainty in data compliance — if the training data sources were entirely clean, geographic exclusion would typically not be necessary.
【Risk points】The copyright risk for sound-effect generation models is generally lower than for video/music generation (Foley sound effects are mostly generic acoustic events with low originality of expression), but the presence of a music-detection stage in the pipeline indicates that the raw data does contain music, and if it is not thoroughly removed there is a music-copyright exposure surface. The paper offers zero discussion of this. [Uncertain]

### Clip Duration Distribution and Segmentation Strategy ⚠️

【Strict fixed 8-second length】This is the most distinctive feature of this work's duration strategy — all training clips are uniformly fixed at 8 seconds ("chunk them into 8-second intervals"), with no variable-length design, no length bucketing, and no curriculum arrangement between short and long clips.
【Two-level segmentation logic】Scene detection algorithms first perform shot segmentation on the raw long video to obtain semantically complete shot segments; the shot segments are then chunked into fixed 8-second blocks. That is, "segment by content first, then by duration" — different from UniVerse-1's approach of "scene-split then discard <5 seconds, keep variable length": HunyuanVideo-Foley does not discard but instead forcibly normalizes.
【Rationale for choosing 8 seconds】The paper does not explain why 8 seconds was chosen. Three plausible reasons can be inferred: (1) it is close in magnitude to the durations of mainstream V2A evaluation benchmarks (VGGSound clips are 10 seconds, as is MovieGen-Audio-Bench), which facilitates evaluation alignment; (2) 8 seconds × 50 Hz latent frame rate = 400 audio latent tokens, a training-friendly sequence length; (3) 8 seconds is enough to cover the complete acoustic envelope of most Foley events (footsteps, door switches, collisions, etc.) while avoiding synchronization drift over long sequences. [Uncertain]
【The boundary problem created by segmentation is not discussed】A hard 8-second cut will truncate acoustic events that span the boundary (e.g., a 12-second-long rain sound cut into an 8-second piece plus a 4-second remainder); the paper does not state how the remainder is handled — whether it is discarded, zero-padded, or concatenated with the next segment, none of this is described. [Uncertain]
【Inference-time duration】The open-source implementation supports sound-effect generation for videos of arbitrary length, but training only ever saw 8-second samples; how long videos are handled (segment-then-generate then concatenate?) is not explained in the paper.

### Resolution/Aspect-Ratio Distribution and Bucketing Strategy ⚠️

The paper does not discuss video resolution, aspect ratio, or bucketing strategy at all — this is a structural characteristic determined by the nature of the V2A task: visual information only serves as conditioning input, and after being encoded by SigLIP-2 into fixed-dimension semantic feature vectors, the original resolution is flattened out post-encoding, so there is no constraint of the kind seen in video generation models where "training resolution determines output resolution," and hence no need for resolution bucketing or aspect-ratio alignment.
【Actual constraints】The only processing on the visual side is the fixed input size of the SigLIP-2 visual encoder (typically a 224×224 or 384×384 square crop/resize), plus the input specification for Synchformer. The paper does not disclose the specific SigLIP-2 variant used (so400m / base / large) or the input resolution. [Uncertain]
【Frame rate】The paper does not state the sampling frame rate of video frames — this is fairly critical for synchronization precision (Synchformer's frame-level sync-feature density is directly affected by the sampling frame rate), but neither the main text nor the appendix gives a number. [Uncertain]
【No visual-quality bar in the cleaning funnel】Notably, the entire cleaning pipeline contains no filtering condition targeting video image quality whatsoever (no minimum resolution, no bitrate constraint, no aesthetic score, no blur/compression-artifact detection) — all quality gatekeeping is concentrated on the audio side. This forms an extreme contrast with UniVerse-1's strict visual bar of "resolution ≥1080p + bitrate ratio ≥600 + DOVER ≥0.6," the direct reason being that this model does not generate the picture, so image quality does not affect output fidelity — visual semantics only need to be recognizable. This is a reasonable simplification derived from the task's shape.

### Category/Domain Distribution and Mixture Strategy (proportional control and concept balancing across people, actions, scenes, styles, etc.) ⚠️

【Core mechanism: managing distribution via categorical tags, without publishing distribution numbers】This is the most worth-recording, and also the most vaguely stated, part of this work's data side. The paper explicitly states: it uses "speech-music detection and audio classification models" to tag each retained clip with categorical tags, with the goal of "enabling effective management of category distribution," claiming this "ensures balanced representation in the training dataset."
【Key omission】The paper states that distribution management was done, yet gives none of the following: what the taxonomy is (how many categories? what are the category names? based on the AudioSet 527-class ontology or a custom scheme?), the actual proportion of each category, what the target mixture is, or by what means balance is achieved (upsampling low-frequency categories? downsampling high-frequency categories? or simply capping overrepresented categories at a threshold?). So this is a field with "mechanism but no data" — readers can only confirm that the team was aware of long-tail and category-imbalance issues and took measures, but cannot know the specific form or effectiveness of those measures. [Uncertain]
【Why this stage matters】The natural distribution of sound-effect data is extremely long-tailed: speech, background music, and traffic noise account for the vast majority of duration, while true Foley event sounds (footsteps, page-turning, pouring water, chopping) make up a very low proportion. Without active intervention, a model trained on 100,000 hours of data would strongly skew toward generating ambient background noise and music rather than precise event sounds. The paper places "category distribution management" as the final stage of the pipeline (after all quality filtering), indicating it is the final gate that determines data composition, its importance disproportionate to the scarcity of information disclosed about it.
【Indirect evidence: coverage of generalization ability】Both official and third-party reporting emphasize the model's generalization ability across video types such as "people, animals, natural scenery, cartoon animation," which can be viewed as circumstantial evidence of category coverage breadth, but this is a qualitative description.
【Relationship to evaluation categories】The Kling-Audio-Eval used for evaluation has its own category taxonomy (built by the Kuaishou Kling team), but the paper does not state whether the training data's category management was designed with reference to that taxonomy.

### Audio Category Distribution and Mixture (proportions and control strategy for speech/Foley/music/ambient sound/silence) — a dimension unique to AV models ⚠️

Audio category is the core organizing dimension of this work's data processing (rather than video category), but likewise there is mechanism without numbers:
【Classification tools】Two model types used in series: (1) a speech-music detection model, doing coarse-grained speech / music / other discrimination; (2) an audio classification model, doing finer-grained acoustic-event classification. Neither is named as a specific model (it is not stated whether it is PANNs, AST, BEATs, EAT, or an in-house model), and the number of categories is not given. [Uncertain]
【Handling of silence: a proportional threshold rather than a binary judgment】Clips whose silence ratio exceeds 80% are discarded. This design detail is worth noting — a continuous proportional metric ("silence ratio") is used rather than a binary "does it contain silence" criterion, and the threshold is set fairly loosely (allowing up to 80% silence). The reason for the loose setting can be inferred as: in Foley scenarios, a large share of samples naturally take the shape of "long stretches of quiet + a brief burst of event sound" (such as a single door-closing sound in an empty room); a tighter threshold would mistakenly kill the most typical Foley training samples. The 80% figure is effectively used only to remove near-totally-silent clips — it is a fallback rule rather than a quality filter. Compared with UniVerse-1's binary approach of "directly discard silent clips using volume/energy/zero-crossing rate," this is more attuned to the characteristics of the Foley task. [Uncertain: the specific calculation method of the threshold, such as the energy floor used for silence determination and the time resolution, is not stated]
【Speech and music: detected but not necessarily discarded】The paper only says speech-music detection is performed and tags are applied — it does not say that detected speech or music is then discarded. This implies speech and music data are likely retained in the training set, only participating in mixture control via categorical tags — a third route different from both MOVA (retain only speech) and UniVerse-1 (route by presence/absence of speech): full-category retention + tag-based mixture control. For the Foley task, retaining a modest amount of speech and music helps the model learn "when it should not generate sound effects" and acoustic layering in mixed scenes — but too much dilutes the learning signal for Foley event sounds; getting the mixture right is exactly the problem "category distribution management" is meant to solve, which unfortunately is not disclosed. [Uncertain]
【Ambient sound/event sound】No proportion is given separately.
【Comparison of orientation with UniVerse-1】UniVerse-1 gives an explicit three-way mixture (speech 15.4% / general 40.0% / public datasets 44.5%); HunyuanVideo-Foley, with 13x the data scale, gives not a single proportion number. This is a place where this work is clearly weaker than comparable work in data disclosure.

### Narrative Structure Distribution (single-shot vs. multi-shot, average clip duration, shot-count distribution, whether native audio track is present) ⚠️

【Predominantly single-shot, determined by the segmentation strategy】The pipeline first uses scene detection to split shots, then cuts into 8-second blocks, so the vast majority of training clips fall within a single shot. But unlike UniVerse-1 ("split then discard clips <5 seconds"), this work normalizes shot segments into 8-second blocks — if a shot is longer than 8 seconds it will produce multiple blocks from the same shot; if shorter than 8 seconds, the handling is not stated (it may be discarded, or it may be concatenated with an adjacent shot, producing a cross-shot sample). The paper does not clarify this. [Uncertain]
【Average clip duration】Strictly fixed at 8 seconds, so there is no distribution to speak of.
【Shot-count distribution】Not applicable (single-shot by design).
【Whether a native audio track is present】Mandatory. The first step of the pipeline is to discard videos without an audio track ("eliminate videos lacking audio streams") — a one-vote-veto condition, so all training data carries a native synchronized audio track. This is a fundamental requirement for the V2A task — the model is precisely learning the mapping "picture → its true accompanying sound"; samples with post-added or replaced audio tracks would introduce incorrect supervision signals.
【Narrative structure does not constitute a training dimension】8-second single-shot clips do not carry narrative structure, and this work does not deal with shot-transition sound effects, acoustic transitions across scene changes, or other narrative-level audio design — this is the boundary of capability between a Foley model and full film sound design. The paper does not discuss sound-effect coherence in long videos or multi-shot scenarios.

### Language/Accent Distribution (the data basis for multilingual lip-sync capability) ⚠️

The paper does not discuss language or accent distribution at all, and this basically does not constitute a relevant dimension for this work:
【Determined by task positioning】HunyuanVideo-Foley's goal is to generate Foley sound effects (foley dubbing), not dialogue speech. The model does not do TTS, does not do lip sync, and does not accept line-of-dialogue text as input, so there is no data requirement for multilingual lip sync.
【Speech's role is to be recognized rather than generated】The role of the speech-detection stage in the pipeline is to tag clips containing speech for category-mixture control, not to train speech-generation ability. Ideally, the model should learn to generate ambient and action sounds in scenes where someone is talking, without synthesizing the dialogue itself.
【Language of the text condition】The text prompt is processed by the CLAP text encoder; CLAP's training corpus is predominantly English, so the model's text-condition understanding ability should be predominantly English. The paper does not state whether Chinese prompts are supported, nor does it evaluate multilingual prompts. Open-source community practice generally recommends using English descriptions. [Uncertain]
【Conclusion】Language/accent distribution is a not-applicable dimension for this work; the missing information does not constitute a substantive disclosure defect.

## Cleaning Pipeline

### Overall Structure of the Cleaning Funnel (number of filtering stages, order) ⚠️

A seven-stage sequential funnel, overall narrowing in a "presence → segmentation → audio quality → cross-modal alignment → classification/annotation" structure. Its most distinctive feature: all quality filtering is concentrated on the audio side, with zero quality bar on the visual side; and the most expensive cross-modal alignment detection is placed after quality filtering and before annotation — a typical "cheap first, expensive later" cost-optimization ordering.
【Stage 1: audio-track presence check】Discard videos without an audio stream (eliminate videos lacking audio streams). The most front-loaded one-vote veto, with the lowest cost and possibly the largest elimination volume (many web videos are silent or have music-only tracks).
【Stage 2: scene detection + fixed-length segmentation】Scene-detection algorithms perform shot segmentation on the raw video, which is then normalized into fixed 8-second blocks. This stage performs no elimination, only a shape transformation (converting variable-length long videos into fixed-length short clips), and is the prerequisite for all subsequent per-clip judgments.
【Stage 3: silence-ratio filtering】Compute the silence ratio for each 8-second clip; those exceeding 80% are discarded. A loose threshold, removing only near-silent clips.
【Stage 4: bandwidth detection】Detects the effective sample rate of the audio (effective sampling rate, i.e., the actual upper bound of spectral energy rather than the file-declared sample rate); only samples with an effective sample rate above 32 kHz are retained. This is a fairly strict and technically deliberate bar — it can identify "pseudo-high-definition" audio that is nominally 48 kHz but is actually upsampled from a low-bitrate source, in the same vein as UniVerse-1's use of a "bitrate-to-resolution ratio" to identify pseudo-HD video. A 32 kHz effective bandwidth corresponds to a 16 kHz audible-frequency ceiling, ensuring that high-frequency-rich Foley event sounds such as cymbals, glass shattering, and metal friction have sufficient spectral information. This bar matches the model's 48 kHz output specification directly and is a necessary consequence of "data bandwidth determines output bandwidth."
【Stage 5: audio aesthetics and signal-to-noise evaluation】The main metric uses the AudioBox-Aesthetics toolkit (from Meta, which outputs four dimensions: PQ production quality / PC production complexity / CE content enjoyment / CU content usefulness), supplemented by SNR as an auxiliary metric, to filter out high-quality audio clips. The paper does not give any concrete threshold value — this is the biggest information gap in this stage, since which of the four AudioBox scores are used and what each is capped at is entirely unknown. [Uncertain]
【Stage 6: audio-video alignment verification】Two parallel paths: ImageBind performs semantic-alignment detection (whether the picture content and the sound content semantically match), and AV-align performs temporal-alignment detection (whether sound events and picture events correspond on the time axis). This is the stage with the greatest methodological value in the entire pipeline, and also where this work differs from most V2A work — treating semantics and timing as two orthogonal dimensions checked separately. Again, no threshold is given. [Uncertain]
【Stage 7: classification/annotation and distribution management】A speech-music detection model + an audio classification model tag each surviving clip with category labels, which are then used to manage category distribution and achieve balanced representation. This is the only stage that does not eliminate but instead performs "mixture adjustment," and it is the final gate that determines data composition.
【Step 8 (parallel, not a filter): audio caption generation】The GenAU model generates a concise audio-content description for each clip, used as the text condition during training.
【Overall assessment】The process design closely follows the task's characteristics with clear trade-offs (strict on audio, loose on visual); Stage 4's bandwidth detection and Stage 6's two-dimensional alignment check are two highlights. But threshold disclosure is very incomplete — of the seven stages, only three give numeric values (8 seconds, 80%, 32 kHz), and the remaining four (aesthetics, SNR, ImageBind, AV-align) give no numbers at all, a level of transparency clearly lower than UniVerse-1's or MOVA's item-by-item threshold disclosure.

### Quantitative Funnel Retention Rates (input/output volume at each filtering stage and final retention rate, e.g. Apollo 27%) ⚠️

The paper gives no quantitative funnel data at all: it does not disclose the total volume of raw collected video (in hours or number of clips), does not give the input/output volume for any of the seven filtering stages, does not give the retention rate at each stage or overall, and does not give the primary reasons for elimination at each stage. Only the final output — approximately 100,000 hours — can be confirmed. The numerator is known, the denominator entirely absent, so it is not possible to compute an overall retention rate analogous to Apollo's 27% or MOVA's 26.39%.
【Strength of qualitative inference】Among the seven serial stages, at least four gates have substantive elimination power: no-audio-track removal (broad elimination scope among web videos), silence ratio >80% (fairly loose, elimination volume should be relatively small), effective sample rate >32 kHz (fairly strict — a large share of web-video audio tracks are nominally 44.1 kHz but have insufficient effective bandwidth after compression; this stage may have the highest elimination rate), AudioBox aesthetics + SNR (threshold unknown, strength unclear), ImageBind + AV-align alignment (threshold unknown). A holistic judgment suggests the overall retention rate should fall somewhere between single digits and the low twenties in percentage terms, implying the raw data scale might be in the hundreds of thousands to low millions of hours. But this is purely an inference, with no paper data to support it. [Uncertain]
【Significance of the disclosure gap】The paper lists "a scalable data pipeline" as its first of three contributions, yet gives no funnel data at all, so the "scalability" claim cannot be quantitatively verified — readers know neither how much raw data the pipeline processed nor the compute-cost share of each stage, and so have no way to judge this pipeline's efficiency advantage relative to comparable schemes. This is a substantive weakness in this work's argumentation.

### Shot Segmentation Method (PySceneDetect/in-house model/shot-aware splitting) ⚠️

【Method】"Scene detection algorithms" are used to detect and segment shot boundaries in raw long videos, after which the segmentation results are normalized into fixed 8-second blocks. The paper uses a generic plural term without naming a specific tool — it does not state whether it is PySceneDetect, TransNetV2, AutoShot, or an in-house approach, and does not give the detector type (content detection/adaptive detection) or threshold parameters. [Uncertain: the specific tool and parameters]
【Purpose of segmentation and its special relevance to the V2A task】In video generation models, the purpose of shot segmentation is to ensure visual-temporal coherence (avoiding scene jumps within training samples). In the V2A task, shot segmentation has an additional, more critical meaning on the audio side: shot changes often accompany abrupt changes in the acoustic scene (indoor→outdoor, close-up→wide-shot reverberation changes), and a cross-shot clip would present the model with the contradictory supervision signal of "one continuous piece of audio corresponding to two unrelated acoustic environments." So for V2A, shot segmentation is in effect a means of guaranteeing acoustic-scene consistency, no less important than visual coherence. The paper does not frame it this way, but the design is self-consistent in this respect.
【Relationship between segmentation and fixed length】Content-boundary-based cutting is done first, then fixed-length cutting — the two steps are separate. This differs from both UniVerse-1 (split then discard short clips, keep variable length) and MOVA (VAD-aware adaptive window) — this work performs no adaptive processing at all, purely mechanical fixed-length normalization, which is simple but may produce truncation at event boundaries.
【Segmentation is not jointly decided with audio event boundaries】Segmentation is driven entirely by visual scene cut points and does not reference audio-side event onset/offset. This means a complete acoustic event may be cut in the middle by an 8-second boundary, and the model will see incomplete samples with "an onset but no decay" or "no onset, only a tail." For a Foley task that needs to model the acoustic envelope precisely, this is a potential data defect that the paper does not discuss.

### Quality Filtering (aesthetic scoring, clarity, OCR text filtering, black-bar/watermark/logo detection) ⚠️

This work's quality filtering exhibits strong asymmetry — multiple strict layers on the audio side, and complete pass-through on the visual side:
【Audio quality filtering (three layers)】
1) Effective sample rate / bandwidth detection: only samples with an effective sample rate >32 kHz are retained. Note it is "effective" rather than the file-declared value, i.e., confirmed via spectral analysis that there is real energy in the high-frequency band, able to identify and remove "pseudo-HD" audio disguised as upsampled from low-bitrate sources. This is a fairly deliberate criterion, and it corresponds directly to the model's 48 kHz output specification — if the training data bandwidth is insufficient, the model cannot learn to generate high-frequency detail.
2) AudioBox-Aesthetics audio-aesthetics evaluation: uses Meta's audiobox-aesthetics toolkit to give a perceptual-quality score to audio. The tool outputs four dimensions: PQ (Production Quality), PC (Production Complexity), CE (Content Enjoyment), CU (Content Usefulness). The paper does not state which of these dimensions are used or what the thresholds are. By comparison, MOVA explicitly gives a three-score threshold combination of PQ>5.0 / CU>4.5 / CE>2.5. [Uncertain]
3) SNR signal-to-noise ratio: used as a "supplementary metric" aiding the judgment, with no threshold given. [Uncertain]
【Visual quality filtering: none at all】The entire pipeline contains no criterion related to video image quality — no minimum resolution, no bitrate constraint, no aesthetic score (no DOVER, no LAION-Aesthetic), no clarity/blur detection, no black-bar detection, no watermark/logo detection, no OCR subtitle filtering.
【An analysis of the reasonableness of this trade-off】It looks aggressive, but is in fact consistent with the nature of the task: in this model, video only serves as conditioning input, and after being encoded by SigLIP-2 into semantic features, factors like image clarity, watermarks, and black bars barely affect the semantic judgment of "what acoustic event is happening in this frame." Spending compute on visual-quality filtering yields extremely low marginal benefit to output audio quality. In contrast, joint-generation models like UniVerse-1 must perform strict visual filtering (because they need to generate the picture); the difference between the two is one of task shape, not engineering standard.
【A noteworthy reverse risk worth flagging】Zero filtering on the visual side means the training data may be contaminated with a large number of samples of extremely poor image quality (heavy compression, extremely low resolution, strong watermark occlusion), for which the visual-semantic recognition itself becomes unreliable, potentially bringing noisy supervision to the model. An ideal approach would retain a low-cost criterion for visual-semantic recognizability (such as the confidence or entropy of SigLIP features), but the paper mentions no such design. [Uncertain]
【AudioBox's dual role】It is worth noting that AudioBox-Aesthetics serves both as a filter for training data and as a metric for the final evaluation (the PQ, PC, CE, CU scores in the main tables). This constitutes a degree of circularity — using a metric to filter data and then using the same metric to evaluate the result will systematically overestimate the model's performance on that metric. The paper does not discuss this potential evaluation bias.

### Motion Filtering (optical-flow/motion-score thresholds, removal of static and shaky footage) ⚠️

The paper describes no motion-filtering stage at all: no optical-flow computation, no motion-score threshold, no static-shot removal, no camera-shake detection.
【Why this work can skip it】Motion filtering serves in video generation models to ensure training data has sufficient dynamic information (avoiding the model learning to generate static frames). In the V2A task, "how much motion is in the picture" does not directly determine audio quality — a near-static scene (such as a slowly burning fireplace) can equally correspond to meaningful sustained sound effects. So motion intensity is not an effective screening dimension for this task.
【AV-align actually serves a similar function】This work uses AV-align for temporal-alignment detection, and this method itself relies on the temporal correspondence between visual events (abrupt changes in picture energy) and audio events (audio onsets). A completely static, event-free picture will naturally have a low AV-align score (no visual event to correspond to an audio event), so it will be indirectly eliminated at Stage 6. In other words, AV-align functionally partially covers the need to "remove content with no dynamics," and does so in a way better suited to the task than a plain motion score — what it filters out is not "static pictures" but "samples where the picture events don't line up with the sound events," and the latter is what V2A actually needs excluded. This is a reasonable design that substitutes a cross-modal criterion for a single-modal one, though the paper does not frame it this way. [Uncertain: this is an inference; the paper does not state that AV-align has this side effect]

### Deduplication Method (exact deduplication and embedding-based semantic deduplication recorded separately) ⚠️

The paper does not mention any deduplication stage at all: no file-hash/audio-fingerprint-level exact deduplication, and no embedding-based (audio or visual) semantic deduplication; the cross-source duplication problem is not discussed.
【Assessment of duplication risk in this task】The risk is objectively present and takes distinctive forms:
1) Same-source duplication — a single long video, after scene segmentation, produces multiple 8-second blocks; if the video's content has high internal repetitiveness (e.g., long fixed-camera recording), it will generate large numbers of near-duplicate samples; this work's segmentation strategy naturally amplifies this kind of duplication, yet no deduplication measure is applied.
2) Sound-effects-library duplication — a large amount of web video reuses the same batch of commercial sound-effects-library assets (the same explosion sound, the same footstep sound reused by thousands of videos); this kind of audio-track-level duplication is very easy to detect via audio fingerprinting, but if unaddressed will cause the model to overfit to specific sound-effect samples. This is a duplication risk unique to, and more severe in, the V2A task compared to video-generation tasks, since sound-effect asset reuse rates are far higher than picture asset reuse rates.
3) Background-music duplication — popular BGM tracks have very high reuse rates in short videos.
【Relationship to scale】At the 100,000-hour scale, even 10-20% duplication would not be easily noticeable, but it would substantively distort the category distribution (and category-distribution management is precisely a stage this work emphasizes) — if a certain sound-effect category is systematically amplified due to asset-library reuse, the distribution derived from label statistics will deviate from the true distribution of acoustic events. This creates a methodological tension between the "no deduplication" design and the "category distribution management" design, which the paper offers zero discussion of. [Uncertain]

### VLM/LLM as Data-Quality Judge (large multimodal model scoring and mismatch removal, the 2026 trend from shallow scorers toward large-model semantic judgment) ⚠️

HunyuanVideo-Foley's approach sits in an intermediate state between "traditional discriminative small models" and "large-model semantic adjudication" — it makes extensive use of specialized pretrained models for automated judgments, but no general-purpose VLM/LLM participates in quality adjudication at all:
【The list of models serving as "quality judges" (all specialized models, not general large models)】
- AudioBox-Aesthetics: four-dimensional audio-perceptual-quality scoring, the only "learned quality evaluator," replacing traditional hand-crafted audio metrics;
- ImageBind: cross-modal semantic-consistency judgment (degree of alignment between audio embedding and visual embedding);
- AV-align: temporal-alignment judgment;
- speech-music detection model + audio classification model: category judgment;
- SNR: a hand-crafted signal metric;
- bandwidth/effective-sample-rate detection: hand-crafted spectral analysis.
【The model serving as "annotator"】GenAU (audio captioning model), generating audio-content descriptions.
【What is absent】No general-purpose multimodal large model (no Qwen-Omni, no GPT-4o, no Gemini) participates in data quality checking, cross-modal consistency adjudication, or mismatch removal; no LLM is used for caption fusion, rewriting, or hallucination self-checking; no model performs a quality review of the captions generated by GenAU. The entire pipeline is a "specialized-model pipeline" rather than a "large-model pipeline."
【Relationship to the 2026 trend】Compared with MOVA (which uses GPT-OSS-120B for cross-modal consistency adjudication and hallucination self-auditing) — an approach that introduces general large models into the quality-checking stage — HunyuanVideo-Foley (August 2025) still remains at the shallow-scorer stage. It should be noted, however, that its ImageBind semantic-alignment detection already functionally shoulders the responsibility of "cross-modal mismatch removal" — only it does so via embedding similarity rather than language-based reasoning, at much lower cost but with far weaker interpretability and fine-grained judgment capability. At the scale of 100,000 hours (about 45 million clips), using a large model to adjudicate clip-by-clip is computationally infeasible — this is a hard constraint that scale places on method.
【Degree of automation】The paper's abstract explicitly describes the pipeline as built "through automated annotation," i.e., the entire process involves no human intervention.
【Hallucination and misjudgment protection】No detection or constraint targeting hallucination in GenAU captions is described, and the misjudgment rates of the various discriminative models or the results of any human verification are not stated. [Uncertain]

### Safety and Compliance Filtering (NSFW, copyright, face/privacy) ⚠️

Neither the paper nor the model card describes any safety or compliance filtering aimed at the training data: no NSFW content detection, no violence/gore content filtering, no copyrighted-content recognition, no face/voice privacy protection measures, and no description of sensitive-content category exclusion.
【An alternative risk control on the model side】Safety responsibility is shifted to the license and distribution layer rather than the data layer: the tencent-hunyuan-community community license is used (with usage-restriction clauses), extra_gated_eu_disallowed: true is set on HuggingFace to exclude the EU region, and model access requires a gated process. This is a posture of "substituting legal and distribution control for technical filtering."
【Risk-surface assessment】Compared with video generation or voice cloning models, the misuse risk of Foley sound-effect generation is generally lower — it generates generic acoustic events rather than recognizable human voices or likenesses, so the risk of deepfakes and identity impersonation is small. The main residual risks are: (1) if the training data does not remove violent/gory scene sounds, the model could be used to reinforce the immersiveness of violent content; (2) when cascaded with a video-generation model, realistic sound effects will significantly increase the credibility of a forged video, constituting a capability boost to the overall forgery chain; (3) there is no output-side audio watermark, so generated audio cannot be traced. The paper discusses none of these points.
【Degree of disclosure gap】Even accounting for the relatively low task risk, for an open-source model released by a large commercial company to mention no data-safety filtering at all still constitutes an under-disclosure. [Uncertain]

## Annotation Methods

### Captioning Model Used (in-house VLM/open-source model, model scale) ⚠️

The model configuration for the annotation stage is extremely minimal, in stark contrast to other works that routinely coordinate three or four large models:
【The sole captioning model: GenAU】Used to generate an audio caption for each 8-second clip; the paper describes it as providing "concise descriptions of the audio content." GenAU (Generative Audio Understanding, from the line of work "Taming Data and Transformers for Audio Generation") is a specialized audio-captioning model, far smaller in scale than general-purpose multimodal large models. The paper does not disclose the specific version or parameter scale used. [Uncertain]
【Key characteristic: only audio is captioned, not video】There is no video-captioning stage anywhere in the pipeline — no picture description is generated, no camera-motion description is done, and no visual tags are applied. This is directly determined by the shape of the task: during training, video is fed in directly as visual features encoded via SigLIP-2, requiring no language intermediary; the text condition's role is to supplement the desired sound characteristics, so only audio-side language description is needed. This makes this work's annotation cost far lower than video-generation work (it skips the most expensive step — video captioning).
【Condition encoders (not annotation models, but they determine how the captions get consumed)】
- Text: CLAP text encoder (Elizalde et al. 2023). Choosing CLAP over T5/umT5 is a deliberate decision — CLAP is an audio-text contrastive-learning model whose text embedding space is naturally aligned with audio semantics, giving it stronger representational power than a general-purpose text encoder for "text describing sound." The cost is that the CLAP text encoder has a relatively short context length (typically 77 tokens), unable to accommodate long, dense descriptions, which directly caps the maximum caption length.
- Vision: SigLIP-2 visual encoder, extracting frame-level semantic features.
- Sync: Synchformer, extracting frame-level sync features, routed through an independent gated-modulation pathway.
【No in-house annotation model】Entirely off-the-shelf open-source models are used, with no in-house captioner or tagger of any kind.
【Total annotation-model scale is far smaller than comparable work】Compared with MOVA (MiMo-VL-7B + Qwen3-Omni×2 + GPT-OSS-120B) and UniVerse-1 (Qwen2.5-Omni + Whisper), this work uses only GenAU alone — a necessary compromise on annotation cost at the 100,000-hour scale: the larger the scale, the lower the per-sample annotation budget can be.

### Caption Density and Degree of Structuring (short/long/dense descriptions, structured fields such as camera motion, style tags) ⚠️

【Density: a clearly low-density, short-description route】The paper qualitatively describes its caption shape as "concise descriptions," which is the opposite direction from the long, dense captions (dense captions) commonly pursued in the video-generation field.
【Why a short caption was chosen — three constraints】
1) Encoder constraint: the CLAP text encoder has a limited context length (about 77 tokens), physically unable to accommodate a long description;
2) Task constraint: the linguistic describability of audio content is inherently lower than that of visuals — "a burst of hurried footsteps, accompanied by distant rain" is already close to the information ceiling of what a human can give for an 8-second piece of audio; extending it further would only introduce speculative content;
3) Cost constraint: at an annotation volume of about 45 million clips across 100,000 hours, the generation cost of long captions is unaffordable.
【The sole structured field: the "high-quality" quality tag】This is the most ingenious part of this work's caption design, described in Appendix A.1: audio samples with a sample rate above 16 kHz have a "high-quality" tag appended to their caption; at inference time, this tag is appended to all input captions uniformly. Its mechanism is to let the model, during training, learn the association "high-quality tag ↔ high sample rate, rich high-frequency detail," and at inference time, forcibly applying the tag pulls the generation distribution toward the high-quality end, thereby "enhanced high-frequency detail preservation."
This is a typical "quality-conditioning" technique — similar approaches include MOVA's explicit attribute tag "This video has no subtitles." and aesthetic-score tagging in the image-generation field. Its value is: rather than discarding all low-to-medium quality data (which would lose data volume and diversity), the model is made to explicitly perceive a quality dimension and select toward it at inference time. This effectively defers "filtering decisions" to the inference stage, converging on the same idea as UniVerse-1's LQLS loss-isolation strategy (both are "don't discard low-quality data, control how it influences the model instead"), but with a simpler implementation path — it only requires adding a word to the caption.
【An inconsistency in thresholds worth noting】The criterion for the quality tag is sample rate >16 kHz, whereas the admission bar at Stage 4 of the cleaning funnel is effective sample rate >32 kHz. The two numbers differ, indicating the tag is drawn at a dividing line lower than the admission bar — this hints that the training data might contain samples with sample rates between 16-32 kHz (i.e., the funnel bar may not be strictly enforced on all data, or there may be another data-source bypass). The paper does not clarify this apparent contradiction. [Uncertain]
【Undisclosed】The average caption length, vocabulary statistics, complete examples, and the generation prompt are all undisclosed; there are no visual-side structured fields such as camera motion/style/shot type (since no video captioning is done). [Uncertain]

### Joint Audio-Video Caption Structure (whether both visual + auditory tracks are covered simultaneously, whether split into separate fields, e.g. LTX-2's full soundscape description, Script-a-Video's factorized streams, Foley-Omni's three-field scheme)

HunyuanVideo-Foley does not have a "joint audio-video caption" in the traditional sense — this is the most important conclusion in this field, and the reason behind it is methodologically significant:
【Only a language description of the audio track, no language description of the visual track】The caption scheme is single-track: the audio description generated by GenAU + the high-quality quality tag. The entire process generates no picture-description text whatsoever.
【Visual information enters the model as features, not language】This is the key design — visual semantics do not go through the language intermediary of "picture → text → text encoder," but are instead directly encoded by SigLIP-2 as visual features, entering joint self-attention together with the audio latent. That is, vision goes through a "feature pathway," text goes through a "language pathway," and the two are fused inside the model rather than at the annotation stage.
【The essential difference from a factorized schema】UniVerse-1's factorized streams (visual caption / speech content / ambient sound caption as three parallel fields) and MOVA's fused single caption both organize multimodal information within "language space"; HunyuanVideo-Foley instead organizes it within "representation space" — only information that cannot be inferred from visual features and needs to be explicitly specified by the user (desired sound characteristics, quality tier) is expressed in language.
【Why this is reasonable】For the V2A task, picture information is fully available (the video is right at hand during inference); converting it to text and back to features is lossy and redundant; the true function of the text condition is to supplement what the picture cannot determine (such as a sense of spatial distance implied by "coming from afar," or a timbral preference for "metallic quality"). So the role text plays in this model is "supplementation and control" rather than "description," and captions should naturally be short rather than dense.
【The modal-competition problem】The paper explicitly states that the multimodal DiT needs to "resolve modal competition" — visual conditioning carries a large amount of information and is strongly correlated with audio, easily dominating generation and rendering the text condition ineffective. Its solution is to route vision through joint self-attention (deep fusion) and text through cross-attention (an independent pathway), structurally separating the two channels to prevent text from being drowned out by vision. This is a solution to the "joint schema" problem at the architecture level rather than the annotation level, and is where this work's genuine contribution on this dimension truly lies.
【Limitation】Since there is no visual caption, there is no way to perform a cross-modal consistency check of "does the visual description match the audio description" — this function is entirely transferred to the ImageBind semantic-alignment detection in the cleaning stage (which determines consistency via embedding similarity rather than language comparison).

### Dialogue Transcription and Speaker Attribute Annotation (ASR transcription + speaker identity/language/accent/emotion) ⚠️

This work does not involve dialogue transcription or speaker-attribute annotation, and this is a clear design boundary rather than an oversight:
【No ASR】There is no speech-recognition stage anywhere in the pipeline — no Whisper or any ASR model is used, no dialogue content is transcribed, and no speech text is produced.
【The purpose of speech detection is classification only, not transcription】The speech-music detection model at Stage 7 of the pipeline only determines "is there someone speaking in this audio," with the output being a category label rather than text content, used for category-distribution management.
【No speaker attributes】Speaker identity, gender, age, timbre, accent, emotion, and speaking rate are not annotated; no speaker diarization is performed; no face detection is performed (there is no RetinaFace or any face-related model anywhere in the pipeline).
【No lip-sync detection】SyncNet is not used, and LSE-C/LSE-D are not computed — this is the most notable process difference from talking-head video-generation works such as UniVerse-1 and MOVA.
【Task boundary】The model's target output is Foley sound effects and ambient sound, not dialogue. The ideal behavior is: given a scene where someone is speaking, generate that scene's ambient and action sounds, and leave the dialogue to a dedicated TTS/dubbing stage. This aligns with the division of labor in real film post-production between "Foley artist, sound-effects engineer, dubbing actor" — this model is aimed at the Foley-artist function, not dubbing.
【An open question about actual behavior】The paper does not evaluate the model's behavior on scenes showing people talking — whether it generates vague speech-like sounds (babble), or whether it correctly maintains a vacancy where human voice should be, is undocumented. This is an important product-level question in practical use (fake generated speech would severely undermine usability), but neither the paper nor the evaluation benchmarks cover it. [Uncertain]

### Geometric and Structured Annotation (camera parameters, depth, 3D point tracks, action annotation, explicit state) ⚠️

The paper uses no geometric or structured annotation of any kind: no camera parameters, no depth maps, no 3D point tracks, no skeleton/pose estimation, no object-detection boxes, no optical-flow fields, no action annotation, and no physical-state annotation.
【The only "structured" information involving temporal structure: Synchformer's frame-level sync features】This is not an annotation but a model-internal conditioning feature — Synchformer extracts frame-level sync-related representations from the video frame sequence, injected into the DiT via adaLN and a gated-modulation pathway. What it encodes is temporal-structure information about "when did what change happen in the picture," functionally serving as a "visual event timeline," which is the core basis by which the model achieves precise audio-visual synchronization. But it exists as dense features rather than discrete annotations — it is not interpretable, not editable, and is not persisted as a dataset field.
【Why the V2A task does not need geometric annotation】The value of geometric annotation (camera parameters, depth, point tracks) in video generation is to control spatial structure and motion consistency. For sound-effect generation, the theoretically valuable geometric information would be "sound-source distance" (determining volume and reverb ratio) and "spatial orientation" (determining stereo imaging), but this model outputs mono/stereo audio and does not do spatial-audio modeling, so this kind of information is not exploited.
【An unexplored direction】If depth information were introduced to judge sound-source distance, or object detection introduced to localize the sounding body, it could theoretically improve spatial realism of the sound effects and accuracy in multi-source scenes. The paper does not explore this direction; it can be viewed as space for future work. [Uncertain: this is an analysis rather than content from the paper]

### Synthetic Data Construction (controlled perturbation/editing to construct training pairs, e.g. InstructAV2AV)

The paper constructs no synthetic data of any kind:
- No controlled perturbations are used to construct training pairs (no positive/negative sample pairs constructed via sound-effect substitution, time shifting, volume perturbation, etc.);
- No editing-based data construction (no InstructAV2AV-style audio-editing instruction pairs);
- No manual mixing synthesis (no manual pairing of clean sound-effect libraries with video footage to synthesize training samples — this is a feasible but unadopted route in the Foley field);
- No TTS or audio-generation-model self-produced data for self-distillation;
- No negative-sample construction for contrastive learning.
All training data is real, natively captured audio-video clips, and is mandatorily required to carry a native synchronized audio track.
【The only "synthetic" component】All captions are automatically generated by the GenAU model, which is synthetic annotation rather than synthetic content.
【The design closest to "construction": the high-quality tag】By artificially appending a quality tag to the caption and forcibly using it at inference time, a conditioning mechanism is constructed where "training distribution and inference distribution are deliberately offset" — during training the tag faithfully reflects sample quality, while at inference the high-quality tag is always used, steering generation toward the high-quality end of the distribution. This is not data synthesis, but it is an artificial construction of the data condition, and shares its underlying idea with the conditional manipulation of classifier-free guidance.
【A notable route not adopted】There is a classic data-construction route in the Foley field: using clean single sound effects from professional sound-effects libraries paired manually with video footage to synthesize "perfectly aligned, perfectly clean" training pairs. This work goes entirely down the real-data route; the benefit is realistic acoustic scenes and a natural multi-source mixing relationship, at the cost of not being able to obtain a completely clean supervision signal (real audio tracks always mix in irrelevant background sound). The paper does not discuss this trade-off.

### Degree of Human Involvement (manual annotation, manual quality checking, model pre-screening + human review) ⚠️

The degree of human involvement is close to zero — the paper's abstract explicitly characterizes the pipeline as built "through automated annotation":
【Training data side is fully automated】The seven-stage cleaning funnel (audio-track detection → scene segmentation → silence ratio → bandwidth detection → AudioBox+SNR → ImageBind+AV-align → classification/annotation) and caption generation (GenAU) are all determined automatically by models and thresholds; the paper mentions no manual annotation, manual spot-checking, or manual review stage, and does not describe how the various thresholds were calibrated (no mention of human verification or ablation experiments). [Uncertain: threshold-calibration method]
【The inevitability of scale】At about 45 million 8-second clips across 100,000 hours, even at 5 seconds of manual listening per clip, about 60,000 person-hours would be needed — full manual involvement is economically infeasible. This is consistent with its positioning as a "scalable pipeline" — the premise of scalability is precisely the absence of a human bottleneck.
【The only human involvement is on the evaluation side】The subjective evaluation stage uses human listening tests, producing three subjective opinion scores — MOS-Q (audio quality), MOS-S (semantic alignment), MOS-T (temporal alignment) — reaching 4.14±0.68, 4.12±0.77, and 4.15±0.75 respectively (5-point scale) on MovieGen-Audio-Bench. The paper does not disclose the number of evaluators, the recruitment method, the listening environment (whether monitoring headphones were used), or the scoring guidelines — these are fairly critical to the credibility of the MOS. [Uncertain]
【Resource-allocation orientation】As with UniVerse-1, this work follows an allocation pattern of "fully automated training data, semi-manual evaluation," with human effort concentrated on results verification rather than data quality assurance.

## Audio-Video Alignment

### Audio-Video Synchronization Detection Method (lip sync, event alignment)

Audio-video alignment detection is the stage with the highest methodological value in this work's data pipeline, and it forms a complete closed loop between the data side and the model side:
【Data side: dual-tool, dual-dimension detection (Stage 6)】
- ImageBind — responsible for semantic alignment. Audio and video are each encoded into ImageBind's shared multimodal embedding space, and their similarity is computed to judge "is this sound semantically the sound that should belong to this picture." A typical mismatch it can identify is: the picture shows chopping vegetables in a kitchen but the audio track is pop music, or the picture shows an outdoor landscape but the audio track is indoor narration/dubbing. Such post-added music/narration samples are extremely common in web video and are the primary contamination source for V2A training data — ImageBind is exactly the antidote to it.
- AV-align — responsible for temporal alignment. Detects whether the onset of an audio event and the change point of a visual event correspond on the time axis. A typical mismatch it can identify is: semantically correct but with a systematic time lag (the audio track offset by several hundred milliseconds overall), or a mismatch between sound-event density and picture-event density.
【The corresponding mechanism on the model side】Samples filtered as aligned on the data side are learned via three mechanisms on the model side: (1) Synchformer's frame-level sync features are injected via gated modulation, providing an explicit time-axis anchor; (2) interleaved RoPE interleaves audio and visual tokens by time, positioning cross-modal tokens at the same instant adjacent to each other; (3) joint self-attention lets audio and video tokens attend directly to each other. Data filtering guarantees "what is learned is correct," while architectural design guarantees "it can actually be learned" — the responsibilities of the two sides are clearly divided.
【Evaluation side】DeSync (the degree of desynchronization computed based on Synchformer, lower is better) is used to measure temporal alignment, and ImageBind cosine similarity (IB, higher is better) is used to measure visual-semantic alignment. Results across three benchmarks: on Kling-Audio-Eval, DeSync 0.54 / IB 0.38 (MMAudio is 0.56 / 0.30); on VGGSound-Test, DeSync 0.53 / IB 0.36; on MovieGen-Audio-Bench, DeSync 0.74 / IB 0.35 (MMAudio is 0.80 / 0.27). The IB metric improves 26.7% relative to baseline, one of the largest-magnitude improvements.
【A circularity risk to note】ImageBind is used both to filter data and to evaluate the IB metric, and Synchformer is used both for model condition injection and to evaluate the DeSync metric — these two instances of "what is used in training is also used in evaluation" will systematically inflate the performance shown on the corresponding metrics. The paper does not discuss this evaluation bias; readers should discount accordingly when making cross comparisons.

### Synchronization Detection: Specific Metrics and Thresholds (SyncNet/Synchformer/LSE/in-house, threshold values, e.g. MOVA LSE-D≤9.5 and LSE-C≥4.5, SkyReels-V4 SyncNet |offset|≤3 ∧ conf>1.5) ⚠️

【Metrics named, thresholds entirely absent】This is the core conclusion of this field. The paper explicitly names two detection tools (ImageBind for semantics, AV-align for timing), but gives no filtering threshold value for either — no lower bound on ImageBind similarity, no bar on the AV-align score, and no statement of whether the two are combined via an "AND" relationship (both must pass) or via weighted combination or tiered handling. [Uncertain]
【Comparison of disclosure with comparable work】UniVerse-1 gives SyncNet conf > 2.0; MOVA gives LSE-D ≤ 9.5 and LSE-C ≥ 4.5, with separate thresholds set for SynchFormer and ImageBind. HunyuanVideo-Foley is highly similar in tool selection to MOVA (likewise a dual-tool combination of temporal + semantic), but its threshold disclosure is markedly lower — the tool names are given, the numbers are not.
【A metric-system difference caused by task difference】This work does not involve lip sync, so it does not use the SyncNet / LSE-C / LSE-D metric family for face-speech synchronization at all, using instead AV-align and Synchformer/DeSync, geared toward general acoustic events. The applicable objects of these two metric systems differ, and their values are not comparable: the LSE family measures the correspondence between lip shape and phonemes, while AV-align/DeSync measures the temporal correspondence between arbitrary visual events and acoustic events, the latter being a harder judgment problem (because "what counts as a visual event" is itself ambiguous).
【Evaluation threshold vs. filtering threshold】The DeSync values on the evaluation side (0.53~0.74, a desynchronization estimate in seconds) are the model's measured output results, not a data-filtering gate — the two should not be conflated.
【Threshold calibration method not stated】The paper does not state whether any threshold was calibrated via human spot-checking, ablation, or empirical setting. [Uncertain]

### Separate Handling of Temporal vs. Semantic Synchronization (time alignment and content-semantic matching as two independent filtering conditions)

This work explicitly treats temporal synchronization and semantic synchronization as two orthogonal dimensions handled separately, and this is the clearest and most commendable aspect of its data pipeline design:
【Explicit dual-dimension separation】The paper states, "leverage ImageBind and AV-align to address the semantic and temporal alignments" — two tools, two dimensions, a one-to-one correspondence with no ambiguity in the division of labor:
- Semantic dimension (ImageBind): answers "does the sound content match the picture content" — this is a time-independent, holistic judgment; even if the audio track is shifted by several seconds overall, semantic similarity barely changes;
- Temporal dimension (AV-align): answers "are the sound events and picture events aligned on the time axis" — a judgment independent of content semantics; even if the sound's semantics are entirely correct, as long as there is a systematic time lag, it should be judged as failing.
【Why the two must be separated】The two types of mismatch arise from entirely different causes and consequences: semantic mismatch mainly comes from post-added music, narration, or replaced audio tracks (a data-source problem); temporal mismatch mainly comes from audio-video encoding delay, editing-track misalignment, or unsynchronized cross-device recording (a technical problem). A single metric cannot cover both — ImageBind is insensitive to time lag, and AV-align is insensitive to content semantics; the detection blind spots of the two are exactly complementary. Using only one of them would let the other class of contamination flow entirely into the training set.
【Cross-work positioning】MOVA likewise performs this separation (SynchFormer handles timing, ImageBind handles semantics); UniVerse-1 lacks both (only SyncNet for speech clips, zero alignment detection for non-speech data, semantic dimension entirely blank). This work belongs to the same fairly complete tier as MOVA, and for the V2A task this separation is even more critical than for joint-generation tasks — because the entirety of V2A's learning signal is the "picture→sound" mapping; if the mapping relation itself is contaminated, the model will directly learn the wrong correspondence.
【Continuation on the model side】The dual-dimension separation also has a counterpart in the architecture: semantic information is carried by SigLIP-2 visual features via joint attention, while temporal information is carried by Synchformer's frame-level features via the gated-modulation pathway — the two streams of information enter the model through different channels, echoing the dual-dimension detection on the data side structurally. This consistency of "however the data side filters, the model side models accordingly" is a fairly complete aspect of this work's design.

### Audio Quality Filtering (SNR, silence detection and silence-ratio threshold, no-audio-track removal, off-screen source removal, background-music separation) ⚠️

Audio quality filtering is the absolute focus of this work's cleaning pipeline, comprising four clearly layered gates:
【1. No-audio-track removal】The first step of the pipeline discards videos without an audio stream, a one-vote veto. All training data carries a native synchronized audio track.
【2. Silence-ratio threshold (a proportional criterion)】The silence ratio is computed for each 8-second clip; those exceeding 80% are discarded. A design feature is the use of a continuous proportional metric rather than a binary "does it contain silence" judgment, with a loose threshold (tolerating up to 80% silence) — this looseness is deliberately left as room for the Foley task: a typical Foley training sample is precisely a shape of "a long quiet stretch + a single brief burst of event sound" (such as one door-closing sound in a silent room); if handled the UniVerse-1 way of "remove upon detecting any silence," the most valuable samples would be mistakenly killed. The 80% bar is in fact used only to remove near-totally-silent junk clips. The energy floor and time resolution used for silence determination are not disclosed. [Uncertain]
【3. Bandwidth / effective sample rate detection】Only samples with an effective sample rate above 32 kHz are retained. The word "effective" is key — confirmed via spectral analysis that there is real energy in the high-frequency band, rather than merely reading the file-header-declared value, so it can identify and remove pseudo-HD audio disguised as upsampled from low-bitrate sources. A 32 kHz effective sample rate corresponds to a 16 kHz audible-frequency ceiling, a necessary condition for ensuring sufficient spectral information for high-frequency-rich Foley sounds such as cymbals, glass, metal friction, and cloth rubbing, and it corresponds directly to the model's 48 kHz output specification — the bandwidth ceiling of the training data determines the frequency ceiling the model can generate. This criterion is fairly uncommon in comparable work and is a highlight of this work's audio-quality control.
【4. Audio aesthetic scoring + SNR】The AudioBox-Aesthetics toolkit serves as the primary metric (able to output four dimensions: PQ production quality / PC production complexity / CE content enjoyment / CU content usefulness), with SNR as a supplementary metric. No threshold value is given for either, and it is not stated which of the four dimensions are actually used. [Uncertain]
【Audio processing not performed】
- No background-music separation (source separation) — detected music is only tagged, not stripped, so training samples' Foley sound effects may be mixed with background music, bringing the model a risk of the wrong association that "event sounds are always accompanied by music," which the paper does not discuss;
- No off-screen-voice/narration source removal — this relies indirectly on ImageBind semantic alignment for filtering, but narration is often semantically relevant to the picture (a narration describing the picture content), which could fool semantic detection;
- No dedicated detection of recording defects such as clipping, distortion, or pops (partially may be covered by AudioBox PQ);
- No description of loudness normalization.
【Overall assessment】The filtering design on the audio side is markedly more careful than on the visual side, and the bandwidth detection and the proportional silence threshold both reflect an understanding of the Foley task's characteristics. The main shortcomings are undisclosed thresholds and the absence of source separation.

### Classification and Separate Handling Strategies for Speech/Sound-Effects/Music ⚠️

【Classify without discarding: the core processing principle of this work】Speech, music, and sound-effects — the three types of audio in this work — are all "fully detected, fully tagged, fully retained, and mixture-controlled by tag," a clear difference from comparable work's approach of "discard or route by type."
【Classification tools (pipeline Stage 7)】Two stages in series: (1) a speech-music detection model, doing coarse-grained three-way classification into speech / music / other; (2) an audio classification model, doing finer-grained acoustic-event classification. Neither is named as a specific model, and the taxonomy and the number of categories are both undisclosed. [Uncertain]
【The role of the three types of audio in this task】
- Sound effects (Foley/event sound) — the model's core target output, the true object all data processing work serves;
- Speech — not the target output, but must be identified. Ideally, the model should learn to keep the human voice vacant in scenes where someone is talking, generating only ambient and action sounds. Retaining a moderate amount of speech samples (rather than discarding all of them) helps the model see real acoustic scenes containing speech and learn acoustic layering; but retaining too much will cause the model to lean toward generating vague speech-like sound (babble), severely harming usability. Getting this balance point right is exactly the key problem "category distribution management" is meant to solve — unfortunately the paper discloses no actual mixture ratio or effect. [Uncertain]
- Music — likewise not the target output. Background music is extremely common in web video; without controlling its proportion, the model would tend to add music rather than sound effects to any picture. Detecting music and only tagging it without separating the source shows the team chose the route of "control via mixture" over "strip via signal processing" — lower cost but lower purity.
【The methodological value of this "classify + distribution management" route】Compared with MOVA (retain only speech, discard the rest) and UniVerse-1 (binary route by presence/absence of speech, downgrade-but-keep non-speech), this work is the only one of the three that treats audio type as an "adjustable mixture variable" rather than a "keep/discard criterion." In theory this is a finer-grained approach — it does not sacrifice data diversity, and the proportions of each type can be adjusted via sampling weight, adjustable even without re-cleaning the data. But this advantage entirely depends on the reasonableness of the mixture strategy, and the paper says not a word about the mixture strategy, leaving the actual value of this design impossible to assess.
【The model side's ability to distinguish types】The text condition is injected via the CLAP encoder, so in theory users can influence the output via a prompt describing the desired sound type, but the paper does not evaluate the model's responsiveness to negative instructions such as "sound effects only, no music."

## Training Coordination

### Multi-Stage Training Curriculum and Data-Curriculum Scheduling (basis for stage division: resolution/duration/quality score/modality; low-res→high-res, image→video, short→long)

【No multi-stage curriculum — flat single-stage training】The entire 100,000 hours of data for the TV2A main model is mixed and trained all at once in a single training stage, over 200k steps, on 128 H20 GPUs, with an effective batch size of 2048, using the AdamW optimizer, a learning rate of 1e-4, and an independent CFG dropout of 0.1 applied per modality. There is no resolution curriculum, duration curriculum, quality curriculum, or modality curriculum.
【Why this work can skip a curriculum】The main motivations for curriculum learning in video generation are cost optimization under compute constraints (build semantics quickly at low resolution, refine details at high resolution) and training stability. This work sidesteps this need for three reasons:
1) The data shape itself is already normalized — all samples are strictly a fixed 8 seconds, audio is uniformly 48 kHz, and the latent frame rate is fixed at 50 Hz, so there is no variation dimension available for staged grading;
2) The visual side is not generated, so there is no need for a resolution ramp-up;
3) The sequence length is short (8 seconds × 50 Hz = 400 audio latent tokens), so training cost is inherently manageable, with no need to spread it out via a curriculum.
【The sole two-stage structure is between the audio VAE and the main model】The DAC-VAE is trained independently first, for 700k steps using about 100,000 hours of audio data (32 H20 GPUs, batch size 256); once training is complete it is frozen, and then the TV2A main model is trained for 200k steps. This is the standard "train the VAE first, then the diffusion model" two-stage approach, an architectural necessity rather than a data curriculum.
【An alternative to curriculum for stability: REPA representation alignment】The paper explicitly lists REPA (Representation Alignment) as one of the three major contributions, its role stated as "efficiently improving audio quality and generation stability." The approach aligns the diffusion model's internal hidden-layer representations with representations extracted by a pretrained self-supervised audio encoder, ATST-Frame, via cosine similarity (the loss is negative cosine similarity), effectively providing an additional supervision signal at the representation level for an intermediate layer, accelerating the establishment of semantic structure. This functionally partially replaces the role of curriculum learning — curriculum learning lowers optimization difficulty via "easy first, hard later," whereas REPA directly provides an optimization direction via "external representation guidance." This is an idea of substituting representation supervision for a data curriculum, which is the mainstream approach in the diffusion-model field in 2025 (originating from the SiT/REPA line of work).
【REPA configuration ablation】For encoder choice, ATST-Frame (PQ 6.28) outperforms EAT (PQ 6.24), and combining the two actually degrades performance (PQ 6.00) — indicating that multiple self-supervised representation supervision signals can interfere with each other; for the application-layer position, applying it at the shallower layer 8 (PQ 6.34, DeSync 0.74) outperforms layer 12 (6.28 / 0.81) and layer 16 (6.32 / 0.78), i.e., representation guidance should be applied at a layer where features are not yet highly specialized.

### Data Mixture Changes Across Training Stages (pretraining/annealing/high-quality SFT subset) ⚠️

Since there is only a single training stage, the dimension of "mixture changing across training stages" does not exist. The data mixture is static, applying throughout:
【The only adjustment mechanism for the static mixture is the category tag】At Stage 7 of the pipeline, a speech-music detection model and an audio classification model tag each clip with category labels, based on which the category distribution is "managed" and "balanced representation" is "ensured." This is this work's sole data-mixture mechanism, but the paper gives neither the target mixture nor the actual mixture, and does not state whether it is implemented via sampling weights or via truncation at dataset-construction time. [Uncertain]
【No annealing】The paper describes no stage of switching to a high-quality subset near the end of training — fairly common in comparable work (such as using a high-quality small subset for the final several thousand steps), but absent here.
【No SFT stage】After 200k steps of training, the model is final, with no subsequent fine-tuning.
【An alternative "quality mixture" mechanism: the high-quality tag】Although there is no data-mixture switch across training stages, a form of "inference-time quality selection" is achieved via the high-quality tag in the caption — high and low quality data are mixed during training (tags labeled faithfully), while inference always appends the high-quality tag, pulling the generation distribution toward the high-quality end. This is effectively similar to "using a high-quality subset for annealing," but at zero cost and without sacrificing training data volume. This is the most ingenious design in this work along the data-mixture dimension: it defers the mixture decision to inference time, and makes it continuously controllable rather than a one-off.
【Comparison with UniVerse-1's LQLS】UniVerse-1 uses "restricting low-quality data to only contribute loss at high-noise timesteps (t>800)" to isolate the influence of low-quality data; HunyuanVideo-Foley uses "quality tags + forced tagging at inference" to achieve a similar aim. Both belong to the idea of "don't discard low-quality data, control how it influences instead," but at different implementation levels: the former operates at the loss-function level (takes effect during training, not adjustable), the latter at the conditioning-input level (takes effect at inference, adjustable). The latter is more flexible, the former more thorough.

### Post-Training Data (scale and screening criteria of the SFT curated set, number of preference pairs and annotation method, reward-model training data) ⚠️

No post-training data. The TV2A main model undergoes no post-training of any kind after 200k steps of training:
- No SFT curated set — there is no fine-tuning stage over a post-training high-quality subset;
- No RLHF / DPO preference alignment — no preference pairs are constructed, no reward model is trained, and no human-feedback-based optimization is performed at all;
- No distillation or inference-acceleration post-training — no mention of step distillation, CFG distillation, etc.;
- No domain fine-tuning for specific scenarios (such as film, games, animation).
【The relationship between the XL and XXL tiers is unstated】XXL (default) and XL, two size tiers, are released open source, but the paper only describes one set of training configuration (18 MMDiT + 36 unimodal DiT, hidden 1536). Whether the two tiers are trained independently from scratch, or XL is obtained from XXL via pruning/distillation, is unstated by either the paper or the model card; XL's architectural hyperparameters are also undisclosed. [Uncertain]
【Human feedback is used only for evaluation, not for training】The three subjective ratings — MOS-Q / MOS-S / MOS-T (4.14±0.68, 4.12±0.77, 4.15±0.75 respectively on MovieGen-Audio-Bench) — serve only as effect verification and are not fed back as a training signal. This is somewhat unfortunate — since human effort was already organized for subjective evaluation, extending it to collect preference pairs would be low marginal cost, yet this work did not do so.
【A trend judgment】Compared with video-generation models that have already begun introducing preference alignment in the same period, post-training practice in the V2A field is not yet mature, and this work remaining at purely supervised training reflects a field-wide norm rather than an individual shortcoming.

### Data Processing Infrastructure and Throughput (NeMo Curator/Data-Juicer/in-house, GPU speedup, processing scale, cost) ⚠️

The paper's disclosure of data-processing infrastructure is nearly zero, a gap relative to its positioning of "scalable data pipeline" as the primary contribution:
【What is undisclosed】No data-processing framework of any kind is mentioned (no Ray, no Spark, no NeMo Curator, no Data-Juicer); no throughput of the cleaning pipeline is given (hours of video/GPU-day); no GPU speedup ratio is given; no compute-cost share for each filtering stage is given; no total processing cost or processing duration is given; no storage scheme is described (the raw data volume for 100,000 hours of 48 kHz audio plus corresponding video is on the order of petabytes, and the pre-computation caching strategy for latents and features is also unstated). [Uncertain]
【Inferable cost structure】The per-unit cost of each stage in the seven-stage pipeline varies enormously: audio-track detection and silence-ratio computation are near-zero cost (pure signal processing); bandwidth detection requires FFT analysis, low cost; scene detection requires frame-by-frame decoding, moderate cost; AudioBox aesthetic scoring requires neural-network inference, moderate cost; ImageBind + AV-align need to encode both audio and video, the most expensive stage; GenAU caption generation is similarly expensive. The pipeline places cheap filters early and expensive alignment detection and annotation last — exactly the standard cost-optimization ordering — this design itself is the main source of "scalability," but the paper gives no quantitative account of it.
【Training infrastructure (disclosed)】
- TV2A main model: 128 NVIDIA H20 GPUs, effective batch size 2048, 200k steps;
- DAC-VAE: 32 NVIDIA H20 GPUs, batch size 256, 700k steps.
Neither total training duration, GPU-days, parallelism strategy (no mention of FSDP/DeepSpeed/sequence parallelism), nor communication optimization is disclosed. The use of H20 (a China-market-compliant model, with less compute than H100/H800) rather than flagship cards reflects real compute-availability constraints — this also indirectly indicates that the configuration of 128 cards × 200k steps was a pragmatic choice under constrained compute.
【Inference-side infrastructure (disclosed)】XXL requires about 20GB VRAM for regular inference, 12GB in offload mode; XL requires 16GB / 8GB. The September 2025 XL + offload update explicitly targets lowering the deployment bar, enabling the model to run on consumer-grade GPUs.

## Performance Comparison

### Quantitative Impact of Data-Strategy Ablations (distinguish: filter-strictness ablation / caption-density-style ablation / data-mixture ablation, and the corresponding evaluation metrics) ⚠️

【Conclusion: no data-side ablation at all】This is the clearest empirical shortcoming of this work. The paper's ablation experiments (Tables 5-7) are entirely about model architecture and training strategy, none touching data:
【Ablations actually performed (three groups, all architecture/training strategy)】
1) Architecture-component ablation (on MovieGen-Audio-Bench):
 - joint attention only: PQ 6.32 / IB 0.31 / DeSync 1.05 / CLAP 0.32;
 - removing interleaved RoPE: PQ 6.36 / IB 0.31 / DeSync 0.79 / CLAP 0.30;
 - removing the unimodal DiT blocks: PQ 6.23 / IB 0.31 / DeSync 0.79 / CLAP 0.30;
 - full architecture: PQ 6.38+ / IB 0.32+ / DeSync 0.78+ / CLAP 0.30+.
 The most notable finding is interleaved RoPE's contribution to temporal synchronization — with joint attention alone, DeSync is as high as 1.05; adding interleaved RoPE brings it down to 0.78~0.79, an improvement of about 25%, proving that position-encoding-level audio-video temporal alignment is the main source of synchronization ability. The unimodal DiT blocks mainly contribute audio quality (removing them drops PQ from 6.38 to 6.23).
2) REPA encoder choice: ATST-Frame (PQ 6.28) > EAT (PQ 6.24) > the EAT+ATST combination (PQ 6.00). The combination is actually the worst, indicating that multiple self-supervised representation supervision targets conflict with each other.
3) REPA application-layer position: layer 8 (PQ 6.34 / DeSync 0.74) > layer 16 (6.32 / 0.78) > layer 12 (6.28 / 0.81). Shallow-layer guidance outperforms deep-layer guidance.
4) DAC-VAE reconstruction-quality comparison (a table, not a strict ablation): the 128-dimensional DAC-VAE achieves PESQ 4.45 / SI-SDR 14.76 on AudioSet, significantly outperforming discrete DAC (4.17 / 11.08) and Stable Audio VAE (2.33 / 3.32); STOI 0.99 on LibriTTS. This proves the reconstruction-fidelity advantage of continuous latents over RVQ discrete tokens.
【The completely missing list of data ablations】Each of the following is a design the paper claims was done, yet never verifies the value of:
- Is the 100,000-hour scale necessary? No scaling curve, no controlled training with different data volumes;
- What is the effect of the strictness/looseness of the 80% silence threshold? No control;
- Is the 32 kHz effective-sample-rate bar necessary? This is the most deserving of ablation — it directly relates to the ability to generate high-frequency detail, and the paper explicitly attributes it as one source of the audio-quality advantage, yet no experiment supports this;
- What is the contribution of AudioBox aesthetic filtering? No control;
- What is the contribution of ImageBind + AV-align alignment filtering? This is the most expensive stage of the data pipeline, and its actual improvement magnitude on the IB and DeSync metrics is entirely unknown;
- What is the effect of category-distribution management (balanced representation)? The core mechanism the paper claims, zero verification;
- What is the gain from the high-quality tag strategy? Appendix A.1 qualitatively claims it "enhances high-frequency detail preservation," but no A/B control data is given at all. This is the cheapest ablation to run (just run the same model with/without the tag at inference) — yet it too was not done.
【Assessment】The paper lists "scalable data pipeline" as its first of three contributions, yet the entire ablation budget was invested in architecture — leaving every one of the data-side designs (including its most distinctive bandwidth bar and quality tag) stuck in a state of "plausible but unverified." Readers cannot judge how much of the 100,000 hours of data was necessary, or which of the seven filtering stages actually contributed. [Uncertain]

### Evidence for Quality vs. Quantity (cases of small, refined data outperforming large, messy data) ⚠️

Overall, this work is a case of "dual investment in both quantity and quality," but it provides no evidence separating the two contributions, so no supportive conclusion of "small and refined beats large and messy" can be extracted from it:
【Evidence pointing toward "quality first" (all qualitative)】
- An effective sample rate >32 kHz is a fairly strict high-frequency-fidelity bar, which should eliminate a broad swath of web-video audio tracks; the team chose to keep the high bar rather than loosen it to increase data volume;
- The dual gatekeeping of AudioBox aesthetic scoring + SNR;
- ImageBind + AV-align dual-dimension alignment filtering, which is the most expensive stage yet was kept;
- The high-quality tag + forced tagging at inference, which in essence further tilts toward the high-quality distribution at the inference stage.
【Evidence pointing toward "quantity first"】The 100,000-hour scale is the first selling point in the paper's abstract, and it is explicitly characterized as "scalable" rather than "curated/refined" — the wording places scale ahead of precision. For reference, the public dataset VGGSound is only about 550 hours; this work's scale is about 180x that.
【A piece of reverse evidence for "not discarding low-quality data"】The existence of the high-quality tagging mechanism itself indicates that the team chose to retain data of varying quality and distinguish it via tags, rather than directly discarding low-to-medium-quality data. This points to the same conclusion as UniVerse-1's LQLS strategy — under a pursuit of scale, "annotating a quality dimension and selecting at inference time" is more cost-effective than "one-size-fits-all filtering." This effectively dissolves the binary opposition of "quality vs. quantity": rather than making a trade-off, quality is turned into a conditionable variable.
【Key omission】There is no controlled experiment of "small-scale curated vs. large-scale coarse" of any kind, no data-scale scaling curve, and no filter-strictness ablation. So this work can serve as evidence neither for "quality over quantity" nor as a counter-example to it — it can only show that the combination of "large scale + strict audio filtering" achieves SOTA, with the contribution of each factor individually not separable. [Uncertain]
【A cross-observation】This work's lead margin on audio-quality metrics (MOS-Q 4.14 vs. MMAudio 3.58, PQ 6.59 vs. 6.17) is noticeably larger than its lead margin on the temporal-synchronization metric (DeSync 0.74 vs. 0.80). Audio quality is the dimension most directly affected by data bandwidth and aesthetic filtering, while synchronization depends more on architectural design (interleaved RoPE, Synchformer). This differentiation pattern is consistent with a design division of "data side drives audio quality, architecture side drives synchronization," which can be viewed as indirect circumstantial evidence for the effectiveness of the data strategy, but this is an inference rather than a conclusion stated in the paper. [Uncertain]

### The Alignment Relationship Between Training-Data Domain Distribution and Evaluation-Benchmark Taxonomy (e.g. VABench's seven major categories) ⚠️

【No verifiable alignment relationship between the training-data taxonomy and the evaluation taxonomy】This is the core conclusion of this field, for the reason that the training-side taxonomy was never disclosed:
【Training side】At Stage 7 of the pipeline, an audio classification model tags category labels and manages distribution, but what the taxonomy is, how many categories there are, and on what ontology it is based (the AudioSet 527-class ontology? a custom scheme?) is entirely undisclosed, so it cannot be compared against any evaluation taxonomy. [Uncertain]
【Evaluation side: three benchmarks, all constructed by others】This work publishes no evaluation benchmark of its own, relying entirely on third-party benchmarks — differing from UniVerse-1 (self-built Verse-Bench) and MOVA (self-built Arena evaluation set):
1) Kling-Audio-Eval — from the Kuaishou Kling team's Kling-Foley work (arXiv:2506.19774, June 2025), the newest V2A-specific evaluation set at the time, which itself has a taxonomy. HunyuanVideo-Foley achieves on it: FD_PANNs 6.07 (MMAudio 9.01, a 32.6% reduction), FD_PASST 202.12, KL 1.89 (MMAudio 2.17, a 12.9% reduction), IB 0.38 (MMAudio 0.30, a 26.7% improvement), DeSync 0.54 (MMAudio 0.56), PQ 6.12 (MMAudio 5.94).
2) VGGSound-Test — a classic V2A evaluation set, the test split of a roughly 550-hour source dataset, with a taxonomy based on VGGSound's 300+ sound-event ontology. Results: PQ 6.40 / IB 0.36 / DeSync 0.53. The paper specifically notes that the relative disadvantage on FD/KL metrics on this set stems from VGGSound recordings being made with "non-professional equipment" — i.e., the reference audio in this set is inherently lower quality, and because this model's training data has been strictly filtered for bandwidth and aesthetics and tends to generate high-fidelity audio, it instead suffers on distribution-distance metrics against a low-quality reference. This is a rather notable observation worth flagging: when the training data's quality orientation does not match the evaluation set's quality level, distribution-matching metrics (FD/KL) will systematically penalize the higher-quality model. This constitutes a substantive mismatch between the training-data distribution and the evaluation benchmark, and is also the only training-vs-evaluation distribution relationship issue this work explicitly discusses.
3) MovieGen-Audio-Bench — from Meta Movie Gen, oriented toward film-grade sound-effect scenarios, the closest of the three to actual application (film post-production Foley work). Results: PQ 6.59 / IB 0.35 / DeSync 0.74, subjective MOS-Q 4.14±0.68 / MOS-S 4.12±0.77 / MOS-T 4.15±0.75, comprehensively ahead of MMAudio (3.58 / 3.63 / 3.47).
【A substantive judgment on taxonomy alignment】Since the training taxonomy is undisclosed, one can only say: the three evaluation benchmarks cover three levels — general sound events (VGGSound), V2A-specific scenarios (Kling-Audio-Eval), and film Foley scenarios (MovieGen-Audio-Bench) — a fairly comprehensive coverage; this work's advantage is largest on MovieGen-Audio-Bench, the closest to actual application, and it suffers on some metrics on VGGSound-Test, the lowest in audio quality — this pattern is highly self-consistent with a strategy of "training data screened for high audio quality." But there is no evidence of whether the training-side category-distribution management was designed with these evaluation categories in mind. [Uncertain]
