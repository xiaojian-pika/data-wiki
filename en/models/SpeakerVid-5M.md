## Basic Information

### Name

SpeakerVid-5M (full paper title: SpeakerVid-5M: A Large-Scale High-Quality Dataset for Audio-Visual Dyadic Interactive Human Generation)

### Publishing Organization/Company

Tsinghua University (Shenzhen International Graduate School, Tsinghua University) jointly with StepFun (阶跃星辰) and the Hong Kong University of Science and Technology (HKUST, including the Guangzhou campus). Author list: Youliang Zhang, Zhaoyang Li, Duomin Wang, Jiahe Zhang, Deyu Zhou, Zixin Yin, Xili Dai, Gang Yu, Xiu Li. The Project Lead is Duomin Wang (StepFun), and the corresponding author is Xiu Li (Tsinghua University). Gang Yu is the head of StepFun's vision team.

### Release Date (technical report/paper/open-source date)

First submitted to arXiv on July 14, 2025 (arXiv:2507.09862, cs.CV). Accompanying resources were subsequently released in stages: the HuggingFace dataset repository dorni/SpeakerVid-5M-Dataset was created on July 18, 2025 and last updated on August 4, 2025; the GitHub data-cleaning code repository Dorniwang/SpeakerVid-5M-Code and the project homepage https://dorniwang.github.io/SpeakerVid-5M/ went live around the same time.

### Type (model/dataset/toolchain/evaluation benchmark)

Primarily a dataset (a large-scale audio-visual dyadic interactive human generation dataset), accompanied by two derivative outputs: (1) an autoregressive video-chat baseline model (0.8B trainable parameters); (2) a companion evaluation benchmark, VidChatBench (500 test pairs with a six-dimensional metric system). It also open-sources a complete data curation code repository, so it also has toolchain characteristics. It is not itself a generative model, but rather one of the upstream data suppliers for audio-video jointly-generative models such as MOVA.

### Degree of openness (whether weights/code/data/pipeline are each open-source) ⚠️

This falls into the typical academic-dataset openness pattern of "metadata and annotations fully open, raw video not hosted":
[Data (annotations and index)] Open source. HuggingFace dorni/SpeakerVid-5M-Dataset provides all_data_list.json (YouTube video IDs + names of the segmented clips, where the clip name is the unique key for locating annotations) and SFT_set.json (a list of the high-quality subset), plus five annotation folders: merge_anno (clip-level metadata: timestamps, spatial bboxes, clear/DOVER quality scores), asr (Whisper transcripts and confidence), l_score (face/hand clarity, i.e. blur score), anno (MLLM-structured captions generated by Qwen-VL), and dwpose (actual skeleton sequences not uploaded due to excessive size, only the computation code is provided).
[Data (raw video)] Not hosted. Users must download videos themselves via yt-dlp based on the YouTube video ID, which carries a risk of reproducibility decay due to link rot.
[Data-processing pipeline code] Open source — one of the most valuable parts of this entry. The GitHub repository Dorniwang/SpeakerVid-5M-Code releases the code for the complete six-stage cleaning pipeline: base annotation (synchronized audio-video extraction + single-person detection), DWpose skeleton annotation, ASR annotation, blur score computation, luminance computation, and scene detection + speaker diarization (partly precomputed, optional).
[Baseline model weights] Neither the paper nor the code repository gives an explicit statement about weight release. [Uncertain]
[License] Explicitly restricted to "non-commercial, scientific research, and educational purposes only," explicitly prohibiting commercial use; content is sourced from the public internet and copyright belongs to the original creators, with a takedown policy provided for copyright holders to request removal. No standard SPDX license such as Apache/CC was adopted.

### Whether it supports simultaneous audio-video generation, and how it is implemented (native joint/cascaded/MoE fusion)

At the dataset level: natively paired audio-video (each clip comes with a native audio track synchronized to the visuals; samples with no audio track or with audio-video desynchronization are removed during cleaning), making it qualified corpus for "joint audio-video generation" training, and also one of the few current audio-video datasets organized primarily around dyadic interaction.
At the baseline model level: it supports simultaneous audio-video generation, implemented as a natively joint autoregressive framework rather than a cascade. Specifically: Qwen2.5-Omni serves as the multimodal understanding backbone → simultaneously predicts video tokens and audio tokens; the video side is encoded with a 3D VAE (temporal stride 4, spatial stride 8), and the audio side uses the CosyVoice2 audio tokenizer; this is followed by a spatial transformer for frame-by-frame refinement and a diffusion MLP for visual detail enhancement. Trainable parameters: 0.8B. A noise-injection strategy is introduced during training to mitigate autoregressive error accumulation.
This dataset has been directly adopted as training corpus by multiple downstream jointly audio-video generative models — a typical example being MOVA, which lists SpeakerVid-5M as one of its Phase 1 data sources and calls it the core source of its lip-sync capability.

## Data Scale and Distribution

### Training data magnitude (number of videos/hours/tokens, pretraining vs. SFT separated)

The paper reports figures in terms of "clip count + hours + number of speaker IDs," without giving a token count:
[Raw collection] 153K audio-visual videos, totaling 64,386 hours of raw footage.
[Final dataset total] Over 5.2M (5.2 million) video clips, over 8,743 hours.
[Single branch (including talking and listening)] 5.2M clips / 8.7K hours / 83K unique speaker IDs.
[Dialogue branch] 770K clip pairs / 1.8K hours / 16K unique speaker IDs.
[High-quality SFT subset] 571K clips / 1,368 hours.
[Pretraining vs. SFT split] Baseline model pretraining uses 7,375 hours (i.e., 8,743 − 1,368, the remainder after excluding the HQ subset), while SFT/fine-tuning uses the high-quality subset of 571K clips / 1,368 hours. This is a clearly defined two-stage scale design of "large-scale pretraining + small, refined post-training," with the HQ subset accounting for about 15.6% of the total duration.

### Data source composition (in-house/public datasets/web crawling/licensed acquisition/synthetic data)

Single source: YouTube web crawling, with no in-house filmed data, no licensed acquisition, and no synthetic data.
[Collection method] Manually collected high-quality two-person dialogue YouTube videos, spanning nearly two decades from 2006 to June 2025 (the time of writing the paper).
[Genre composition] Interviews, news reports, seminars/lectures, television programs, variety shows, debates, educational videos.
[YouTube channel category composition] Entertainment, people and blogs, comedy, news and politics, education, science.
[Relationship to public datasets] Does not reuse existing datasets such as CelebV-HQ, HDTF, MultiTalk, or OpenHumanVid — it is an entirely independently collected new corpus. Paper Table 1 compares it against the above datasets: compared to OpenHumanVid's 13.4M clips / 16.7K hours, SpeakerVid-5M does not have an advantage in total volume, but is unique along dimensions such as "dyadic interaction pairing," "speaker-ID scale," "proportion of 1080P content," and "structured body-composition annotation."
[Synthetic data] None.

Disclosure is incomplete, a typical academic-dataset compliance posture:
[Stated] (1) Explicitly restricted to non-commercial research and education use, explicitly prohibiting commercial use; (2) states that content comes from the public internet and copyright belongs to the original creators; (3) provides a takedown policy under which copyright holders may request removal; (4) does not host raw video, only publishing YouTube video IDs and annotations, thereby shifting copyright risk to users who must download the content themselves — a common way of avoiding direct distribution of copyrighted content.

### Clip-duration distribution and segmentation strategy

Variable-length segmentation is used, with the length band strictly confined to a narrow range:
[Segmentation strategy] First, PySceneDetect performs scene splitting, and clips are then trimmed to between 3 and 14 seconds; overly fragmented clips shorter than 3 seconds and overly long clips longer than 14 seconds are excluded or truncated.
[Estimated average duration] Single branch: 8.7K hours / 5.2M clips ≈ 6.0 seconds/clip; dialogue branch: 1.8K hours / 770K pairs ≈ 8.4 seconds/pair (if counted per individual track within a pair, roughly 4.2 seconds per track). Overall: 8,743 hours / 5.2M clips ≈ 6.05 seconds, near the lower end of the 3–14 second range.
[Comparison with fixed-duration schemes] Unlike MOVA's fixed 8.05-second window, SpeakerVid-5M retains the variable-length character that comes from preserving original semantic boundaries — segmentation points are jointly determined by scene changes and speaking turns, more closely matching the granularity of "one natural conversational turn."
[Distribution chart] Figure 3 provides a duration-distribution histogram, but the body text does not give specific percentages for each duration bucket.
[Time span of the multi-turn branch] The multi-turn branch aggregates a history window of length T, [x−T, x], preceding the current turn's timestamp x to aggregate prior turns; adjacent clips whose time gap is smaller than a threshold δt are judged to be a continuous conversation and can be concatenated into longer, more natural conversational sequences. Hence, the effective context duration of the multi-turn branch can far exceed the 14-second upper bound of a single clip.

### Resolution/aspect-ratio distribution and bucketing strategy ⚠️

[Native resolution] The dataset preserves the native resolution of the source videos, and the resolution tier is extremely high: 93% of videos are 1080P or higher, and 98% exceed 720P. This is one of its core quality advantages relative to older datasets such as CelebV-HQ and HDTF; Figure 3 provides the resolution-distribution chart.
[Cropping strategy] There is no uniform resolution normalization or letterboxing/padding; instead, temporal and spatial cropping is performed for each speaker based on YOLO human detection and tracking results — i.e., a sub-region centered on a single speaker is cropped from the original frame. As a result, the actual aspect ratio of a clip is determined by the human bounding box rather than a fixed 16:9 or 9:16.
[Body-composition bucketing] The paper uses "body composition" rather than aspect ratio as its primary framing-bucketing dimension; the caption explicitly labels half-body vs. full-body, as well as facing direction/body orientation (frontal/side), covering full-body, half-body, and side-view framings — this is a differentiating annotation item relative to datasets like CelebV-HQ in Table 1, which focus primarily on the head.
[Training side] The baseline model uniformly normalizes frames to 480×768 resolution (a vertical aspect ratio approximating 5:8) during both training and inference, with the 3D VAE using temporal stride 4 and spatial stride 8. That is, the data side is high-definition and diverse, while the training side is uniformly downsampled.
[Bucketing strategy] The paper does not describe an aspect-ratio-based multi-bucket training (aspect-ratio bucketing) strategy. [Uncertain]

### Category/domain distribution and mixture strategy (proportional control and concept balancing across people, actions, scenes, styles, etc.) ⚠️

The paper provides qualitative categories and distribution charts, but no proportion figures:
[Interaction-form dimension (the dataset's primary organizational axis)] This is SpeakerVid-5M's most distinctive way of dividing domains — it splits the data into four major branches by interaction role rather than visual content: (1) the dialogue branch (two-person dialogue); (2) the single branch (monadic talking); (3) the listening branch (non-speaking-side reaction behavior during dialogue); (4) the multi-turn branch. All four branches derive from the same underlying pool of raw videos, via different organization and pairing methods. This "speaking / listening / one-way / multi-turn" taxonomy directly corresponds to the capability breakdown of downstream tasks.
[Content-genre dimension] Interviews, news reports, seminars, television programs, variety shows, debates, educational videos.
[YouTube channel-category dimension] Entertainment, people and blogs, comedy, news and politics, education, science. Figure 3(c) graphically shows the topic distribution and year distribution (2006–2025), but the body text does not list percentages.
[Concept-balancing mechanism] The paper does not describe any explicit category-mixture control or concept-balancing strategy; on the collection side, the only qualitative principle is "manually selecting high-quality two-person dialogue videos."
[Strong person-centric bias] All data consists of real human speaking/listening scenes; it contains no object motion, natural scenery, animation, or other non-human domains — it is a highly vertical person-and-dialogue dataset, not a general-purpose video-generation dataset. [Uncertain]

### Audio-category distribution and mixture (proportions and control strategy for speech/foley/music/ambient sound/silence) — a dimension unique to AV models ⚠️

SpeakerVid-5M is a purely speech-oriented dataset, and its audio-category mixture is implicit and extreme:
[Design orientation] All branches are built around human speaking and listening; the absolute majority of the audio-track content is human dialogue, and there is no subset or mixture ratio set aside specifically for foley, music, or ambient sound.
[Implicit non-speech removal mechanism] The audio-quality filter includes a rule that discards any clip with a no-speech probability > 0.8 (from Whisper's no-speech probability), which directly excludes pure sound effects, pure music, pure ambient sound, and silent segments from the dataset; samples with an ASR confidence below −1.5 are likewise removed. As a result, the final corpus is, in terms of audio category, nearly 100% speech-dominant clips.
[Audio peculiarity of the listening branch] The visual subject of the listening branch is the non-speaking party, but its paired audio track is still the other person's speech — so the audio side remains speech, only without a corresponding lip-sync relationship to the visual subject. This is the only "audio-visual role mismatch" design within the dataset, and it is deliberate (used to train the listener's reaction generation).
[Processing not performed] The paper does not describe background-music separation (BGM separation), speech enhancement, SNR estimation, or any sound-effect/music classifier (such as EAT), nor does it give proportion statistics for speech/non-speech/silence. Compared with MOVA, which explicitly reports that "speech segments account for 69.47% of the preprocessed clips," SpeakerVid-5M is an information gap on this dimension.
[Downstream impact] Precisely because of its purely speech nature, downstream models such as MOVA position it as a dedicated data source for lip-sync capability, while general sound-effect and music capability must be obtained from other datasets such as VGGSound and WavCaps. [Uncertain]

### Narrative-structure distribution (single-shot vs. multi-shot, average clip duration, shot-count distribution, whether native audio tracks are present) ⚠️

[Single-shot vs. multi-shot] The dataset is a strictly single-shot corpus. The first step of segmentation uses PySceneDetect to detect significant changes in color and brightness to locate transitions, and cuts at those transitions, ensuring no shot changes occur within a clip; subsequent YOLO tracking for spatial cropping further ensures continuity of the subject within a clip. As a result, there are no multi-shot samples, and no shot-count distribution — a clear contrast with MOVA, which deliberately retains a "multi-scene clip" category.
[Average clip duration] About 6.0 seconds (within the 3–14 second range); see duration_distribution for details.
[Whether native audio tracks are present] All clips include native, synchronized audio tracks. The dataset was audio-visual paired from the moment of collection (the raw-collection figure is stated as "153K audio-visual videos"), and after SyncNet lip-sync verification and Whisper audio-quality filtering, samples with no audio track or audio-visual desynchronization are removed.
[Higher-level narrative structure: conversational turns] SpeakerVid-5M introduces a "conversational turn" structural layer that is rare in video datasets: the dialogue branch pairs the clips of two speakers from the same time period into a pair; the multi-turn branch further chains multiple turns along the timeline — the contextual type aggregates the ASR transcripts of preceding turns into multi-turn dialogue context, while the sequential type judges adjacent clips with a time gap smaller than the threshold δt to be a continuous conversation and concatenates them. This means the dataset's narrative structure is not a "shot sequence" but rather a "conversational-turn sequence" — a distinctive narrative organization geared toward interactive generation tasks.
[Turn-count distribution across branches] The paper does not give turn-count distribution statistics for the multi-turn branch. [Uncertain]

Disclosure is minimal, one of the most obvious statistical gaps in this dataset:
[Known information] The data source is entirely public YouTube videos, collected under the criterion of "high-quality two-person dialogue videos," in genres such as interviews/news/seminars/variety shows/debates/education, with no language restriction specified. Whisper is used for ASR transcription, and Whisper itself has language-identification capability; the cleaning pipeline mentions filtering based on "detected language mismatches," indicating that the pipeline does internally record a language label.

## Cleaning Pipeline

### Overall structure of the cleaning funnel (number of filtering stages, order of stages)

The overall structure is a funnel of "five-step structured processing → five-dimensional quality filtering → multimodal annotation → four-branch organization," and the entire pipeline's code has been open-sourced (Dorniwang/SpeakerVid-5M-Code, six-stage scripts):
[Stage 1: Structured processing (5 steps, executed in strict order)]
  1) Scene Splitting: PySceneDetect detects visually significant transitions based on changes in color and brightness, splits the video, and trims clips to 3–14 seconds.
  2) Speaker Diarization: the 3D-Speaker tool performs voiceprint clustering, selecting the two dominant speaker IDs by speaking duration/frequency (together accounting for more than 80% of total speaking time); other speakers are discarded.
  3) Human Detection & Tracking: YOLO performs spatio-temporal tracking, cropping each person temporally and spatially to obtain sub-clips centered on a single individual.
  4) Lip Synchronization: SyncNet computes the audio-visual overlap, using a confidence score to bind the speaker ID on the audio side to the human bounding box on the visual side — this step is the key adjudication of "which person in the frame does this voice belong to."
  5) ID Correction: ArcFace extracts facial features and computes cross-clip facial cosine similarity to verify speaker-identity consistency; outlier samples that show higher similarity to a different ID are reassigned.
[Stage 2: Quality filtering (five dimensions in parallel)] Luminance, video quality (DOVER), clarity (clarity = a bitrate-density measure B/(W×H)), motion blur (Laplacian variance of face/hand regions), audio quality (Whisper confidence/no-speech probability/compression ratio).
[Stage 3: Multimodal annotation] Structured captions from Qwen2.5-VL, topic classification from Qwen-3, Whisper ASR, DWpose skeletons, SyncNet metrics, Laplacian blur scores, multi-persona motion-intensity scoring from Qwen2.5-VL.
[Stage 4: Branch organization] Reorganized into four branches by interaction form — talking/listening/dialogue/multi-turn — and an SFT subset of 571K clips is cut out by HQ thresholds.
[Design characteristic] Unlike general-purpose video datasets, the core of this pipeline is not "filtering out bad videos" but "parsing interaction structure" — the three steps of diarization, SyncNet binding, and ArcFace correction are all answering "who is speaking, who is listening, where are they in the frame, and is this the same person across clips," while quality filtering plays a supporting role.

### Quantitative funnel retention rates (input/output volume at each filtering stage and final retention rate, e.g., Apollo's 27%) ⚠️

The paper does not provide a stage-by-stage retention table; only an end-to-end estimate can be made from the entry and exit figures:
[Entry] 153K videos / 64,386 hours of raw footage.
[Exit] Over 5.2M clips / 8,743 hours (including 8.7K hours for the single branch + 1.8K hours for the dialogue branch, which overlap in samples; the total is counted as 8,743 hours).
[End-to-end duration retention rate] 8,743 / 64,386 ≈ 13.6%. This retention rate is notably lower than MOVA's 26.39% and Apollo's 27%, but the bases are not fully comparable — the bulk of SpeakerVid-5M's loss is not quality filtering but structural loss: keeping only the two dominant speakers (other people discarded), keeping only periods with clear speaking/listening behavior, and the loss of frame area after YOLO single-person cropping — all of which substantially reduce effective duration.
[HQ subset retention rate] 1,368 / 8,743 ≈ 15.6% (relative to the final dataset); 1,368 / 64,386 ≈ 2.1% (relative to raw footage). That is, from raw footage to high-quality dialogue data usable for SFT, the effective retention rate is roughly one-fiftieth.
[Not disclosed] The input/output volume and stage-by-stage elimination rate for each individual step (scene splitting, diarization, SyncNet binding, ArcFace correction, and each of the five quality-filtering dimensions) are not given. Although Figure 3 shows distribution histograms of DOVER scores and SyncNet confidence, the elimination ratios cannot be back-derived from them. This is a relatively weak link in this dataset's disclosure system. [Uncertain]

### Shot-segmentation method (PySceneDetect/in-house model/shot-aware splitting)

PySceneDetect (SceneDetect) is used as the sole shot-segmentation tool; no in-house segmentation model is used:
[Detection principle] Analyzes changes in frame color and brightness to locate "visually significant transitions," cutting at the transition points.
[Length constraint] Segmented clips are trimmed to between 3 and 14 seconds; clips that are too short or too long are discarded or truncated.
[Coupling with speaker structure] Scene splitting is only the first step; what truly determines the final clip boundaries is a subsequent triple constraint: (1) 3D-Speaker's speaker time intervals; (2) the spatio-temporally continuous segments from YOLO human tracking; (3) the valid audio-visual binding interval from SyncNet. Hence SpeakerVid-5M's segmentation is essentially a triple-aware process — "shot-aware + speaker-aware + track-aware" — rather than pure scene segmentation.
[Comparison with MOVA] MOVA jointly uses PySceneDetect scene cut points and Silero VAD speech boundaries to generate fixed 8.05-second windows, deliberately retaining multi-shot samples; SpeakerVid-5M instead crops along speaker trajectories after PySceneDetect cuts, producing strictly single-shot, variable-length clips. Both are shot-aware, but with different goals: the former serves "learning to handle transitions," the latter serves "learning human interaction."
[Code availability] The code for scene detection and speaker diarization is provided as step 6 in the open-source repository (marked optional; some results are precomputed).

### Quality filtering (aesthetic scoring, clarity, OCR text filtering, black-border/watermark/logo detection) ⚠️

Five-dimensional threshold-based filtering, all thresholds public, with a stricter HQ threshold set as well:
[1. Luminance] Clips with a luminance score < 10 or > 210 are removed (within the 0–255 grayscale range), used to exclude overly dark and overexposed frames.
[2. Video quality (DOVER)] Uses the fused score from the DOVER video quality assessment tool, removing anything < 0.25.
[3. Clarity Score] A custom metric, defined as clarity = B/(W×H), i.e., bitrate divided by resolution area — measuring bit density per pixel, effectively identifying "high-resolution but actually low-definition upsampled/heavily re-compressed" pseudo-HD videos. The lowest 5% by score are removed after ranking. This is one of the more distinctive custom quality metrics in this dataset.
[4. Motion blur] A 128×128 patch is cropped from each of the face and hand regions, and Laplacian variance is computed as the clarity/blur score; clips are removed if the average blur score of either the face or the hand is < 0.1. Face and hand are scored independently in two separate passes, a design specifically made for downstream gesture-generation tasks.
[5. Audio quality] Three parallel veto rules, removed if any one is met: Whisper transcription confidence < −1.5; no-speech probability > 0.8; compression ratio > 2.5 (used to identify ASR repetition degradation/hallucinated output).
[HQ / SFT subset thresholds (stricter)] Hand blur score > 0.5, face blur score > 0.7, DOVER > 0.6, motion-intensity score > 2, ASR confidence > −1. All five must be satisfied to qualify, yielding 571K clips / 1,368 hours.
[Filtering not performed] The paper does not describe a standalone aesthetic score, burned-in subtitle/OCR detection and filtering, watermark/logo detection, or black-border detection. DOVER itself includes an aesthetic-perspective branch, but the paper only uses its fused score without splitting it out. [Uncertain]

### Motion filtering (optical-flow/motion-score thresholds, removal of static and shaky footage)

SpeakerVid-5M does not perform traditional optical-flow/motion-magnitude threshold filtering; instead it turns motion intensity into a searchable annotation dimension, using it as a filtering criterion only at the HQ subset stage:
[Motion-intensity annotation method] Qwen2.5-VL is used for multi-persona scoring — three prompts with different personas are designed, each rating the same video from a different perspective on a 1–5 scale: (1) an expert perspective, assessing movement amplitude and body-motion frequency; (2) an audience perspective, assessing the emotional fluctuation and audience reaction reflected in body language; (3) an annotation-expert perspective, assessing gesture usage and interaction frequency. Outliers are removed and the average score is taken as the final motion-amplitude annotation. This is a typical case of using an MLLM in place of an optical-flow scorer, and uses a multi-persona ensemble to reduce the variance of a single scoring pass.
[Use as a filtering criterion] Enabled only when constructing the HQ / SFT subset: motion score > 2 (on a 5-point scale) is required for inclusion, i.e., excluding near-static, lifeless clips. No motion lower bound is imposed on the full dataset.
[Indirect control of static/shaky footage] The motion-blur filter (face/hand Laplacian variance < 0.1 removed) removes blurry frames caused by intense shaking or fast motion; the spatio-temporal cropping from YOLO tracking keeps the subject stably within the frame, indirectly suppressing strong camera shake.
[Not used] No optical flow (optical flow) computation, no RAFT/UniMatch-type motion scorers, no dedicated static-shot detector. Given that the corpus itself consists of interview/dialogue-type close-up human videos, motion amplitude is naturally limited, so the need for traditional motion filtering is lower.

### Deduplication method (exact deduplication and embedding-based semantic deduplication recorded separately) ⚠️

Neither the paper nor the data card mentions any deduplication step: no exact deduplication based on video hashing/fingerprinting, no embedding-based (CLIP/DINO, etc.) semantic deduplication, and no description of near-duplicate detection across clips or across source videos.
[Objective risks] (1) The same YouTube video will be split into multiple clips, and multiple segments of the same speaker in the same scene are highly similar — structural near-duplication; (2) the data source spans YouTube content from 2006–2025, and reposts, edited versions, and multi-platform re-uploads of the same interview are extremely common on YouTube — if deduplication is only performed by video ID during collection, content-level duplicates cannot be identified; (3) 83K speaker IDs correspond to 5.2M clips, an average of about 63 clips per speaker; head-tier celebrities (a typical subject of interview/news content) likely contribute far more clips than average, creating an identity-level long-tail imbalance.
[The only related mechanism] The ArcFace ID-correction step computes cross-clip facial cosine similarity, but its purpose is "ensuring annotation consistency for the same ID," which is the opposite direction of "removing duplicate content" — it is identity aggregation, not deduplication.
[Conclusion] Deduplication is a clear gap in this dataset's disclosure system. [Uncertain]

### VLM/LLM as quality inspector (multimodal large-model quality scoring and mismatch removal; the 2026 trend from shallow scorers toward large-model semantic judgment)

SpeakerVid-5M sits in an intermediate form of "large models deeply involved in annotation, but quality adjudication still handled by specialized models," similar in division of labor to MOVA:
[Actual use of MLLM as a scorer (the one instance)] Qwen2.5-VL is used as the motion-intensity scorer, employing a three-persona ensemble score (expert/audience/annotation-expert personas, each on a 1–5 scale), removing outliers and averaging. This is a typical case of handing off "movement amplitude and interaction activity" — a subjective quality difficult to characterize with shallow metrics — to an MLLM for judgment, using a multi-perspective ensemble to reduce the instability of a single scoring pass, a more cautious approach than single-prompt scoring. This score subsequently becomes one of the hard filtering criteria for the HQ subset (> 2).
[LLM as classifier] Qwen-3 is used for dialogue-topic-category classification annotation.
[MLLM as descriptor] Qwen2.5-VL generates structured captions (camera motion, entity list, body orientation, half-body/full-body, expression, action description, etc.).
[Quality adjudication still handled by specialized models] DOVER (video quality), SyncNet (lip-audio synchronization), ArcFace (facial identity), Whisper (ASR confidence and no-speech probability), Laplacian variance (blur), the custom clarity formula (clarity) — all six of these hard-filtering categories are completed entirely by specialized discriminative models or traditional signal metrics; none is replaced by a VLM issuing a composite quality score.
[Approaches not adopted] No LLM-as-judge style cross-modal consistency verification (compare with MOVA's use of GPT-OSS-120B for audio-visual semantic self-consistency adjudication); no caption hallucination self-auditing mechanism; no use of an MLLM to re-verify filtering results.
[Overall positioning] The MLLM here is responsible for "annotation and subjective scoring," not "quality adjudication and mismatch removal" — an early/conservative form of this trend.

### Safety and compliance filtering (NSFW, copyright, faces/privacy) ⚠️

Neither the paper nor the data card describes any safety or compliance filtering step: no NSFW/violent-content detection, no copyrighted-content identification, no face blurring or privacy de-identification, no handling of minor-related content, no harmful-speech filtering (content moderation based on ASR transcripts).
[Alternative, reactive risk handling] The only compliance measure is after-the-fact and passive: restricting use to non-commercial research and education, stating copyright belongs to the original authors, providing a takedown policy, and not hosting raw video (only publishing YouTube IDs) — "shifting responsibility" rather than "proactive filtering."
[Privacy sensitivity assessment] This dataset's actual privacy risk is higher than that of general video datasets — it contains 83K unique speaker identities, per-clip ArcFace facial-feature associations, full-body DWpose skeletons, and complete Whisper speech transcripts (i.e., a searchable structure of "who said what, and when"). This combination is sufficient to constitute a biometric database usable for identity tracking, yet the paper conducts no privacy impact assessment and does not state whether the people appearing on screen gave consent (the default answer for public YouTube videos is no).
[Political sensitivity of content] The data source explicitly includes "news and politics" and "debates" categories, and ASR transcripts fully preserve any political speech contained therein, yet there is no description of any content moderation.
[Conclusion] Safety and compliance filtering is the largest gap in this dataset's disclosure system. [Uncertain]

## Annotation Methods

### Caption model used (in-house VLM/open-source model, model scale) ⚠️

All open-source models are used; no in-house captioner was developed, forming a division of labor among "one MLLM for visual description + one LLM for topic classification + one ASR model for transcription," with no fusion step:
[Structured visual caption] Qwen2.5-VL (Alibaba's Qwen 2.5 vision-language model). The paper does not specify which parameter-scale tier was used (Qwen2.5-VL has 3B/7B/72B versions, among others). [Uncertain] The HuggingFace data card describes this annotation folder as "MLLM captions from qwen-vl."
[Motion-intensity scoring] Also uses Qwen2.5-VL, but invoked independently via three-persona prompts — a different call chain from caption generation.
[Topic classification] Qwen-3 (Alibaba's Qwen 3 series LLM) annotates dialogue topic categories.
[Speech transcription] Whisper (OpenAI), outputting transcript text, confidence score, no-speech probability, and compression ratio diagnostics.
[Pose annotation] DWpose, outputting face, hand, and body keypoints.
[Identity and synchronization] ArcFace (facial recognition), 3D-Speaker (voiceprint diarization), SyncNet (lip-audio synchronization), YOLO (human detection and tracking), Deep3DFaceRecon and UniSpeech (used for expression FID and timbre similarity on the VidChatBench evaluation side).
[Comparison with MOVA] MOVA uses four models in a fused division of labor — MiMo-VL-7B-RL + Qwen3-Omni-Instruct + Qwen3-Omni-Captioner + GPT-OSS-120B; SpeakerVid-5M's annotation model chain is lighter, and each annotation track keeps independent fields without LLM fusion — lower cost but also lower semantic integration.

### Caption density and structuring level (short/long/dense description, structured fields such as camera motion, style tags) ⚠️

Follows a "structured JSON fields" approach rather than long, dense natural-language description — a notable point of divergence from generative-model datasets like MOVA/LTX-2:
[Final form] Annotations are stored and released as JSON structures alongside the dataset (the anno folder), with fields kept side by side rather than merged into prose paragraphs. Fields appearing in the paper's examples include:
  - Clarity
  - Camera Motion (camera-motion pattern)
  - Motion Intensity Level (1–5)
  - Entity List (list of on-screen entities)
  - Speech Presence (whether speech is present)
  - Observed Actions (detailed body-motion description)
  - Number of People
  - Upper-Body Only (whether only the upper body/half-body vs. full-body)
  - Facing Direction (frontal/side)
  - Facial expression summary
  - Topic category (annotated by Qwen-3)
[Density] Dominated by short field values, with only Observed Actions being a relatively longer natural-language description. Overall caption length is far shorter than MOVA's roughly 200-word dense, fused paragraph. Figure 3 provides a caption word cloud and word-frequency chart.
[Explicit style/camera-motion tags] Yes — Camera Motion, along with Upper-Body Only / Facing Direction, are explicit discretized structured fields, which is more convenient for conditional control and data retrieval than pure natural-language captions.
[Design orientation] This schema is clearly optimized for "retrievable, condition-filterable subsets" (e.g., directly filtering for samples that are "full-body + frontal + high motion intensity + has speech"), rather than being optimized as "direct text conditioning for a diffusion model." Downstream models that want to use it as a generation condition would typically need to rewrite it as a natural-language prompt themselves.
[Gap] No average caption-length statistics are given, and no human evaluation or accuracy data for caption quality is provided. [Uncertain]

### Joint audio-video caption structure (whether visual + auditory tracks are covered simultaneously, whether split into independent fields, e.g., LTX-2's full soundscape description, Script-a-Video's factorized streams, Foley-Omni's three-field schema)

SpeakerVid-5M adopts a schema of "multiple tracks kept side by side, without fusion" — the lowest fusion level in this research round:
[Visual track] Qwen2.5-VL's structured JSON caption (camera motion, entities, orientation, body composition, actions, expressions, etc.), which does not describe auditory content at all.
[Speech track] Whisper's ASR transcript text + confidence, stored in a separate asr folder.
[Synchronization track] SyncNet's three metrics (offset, confidence, embedding distance) are saved as independent numeric annotations.
[Structure track] DWpose skeleton keypoint sequences (code open-sourced, data not uploaded due to size).
[Quality track] The l_score folder's face/hand clarity scores, and the clear/DOVER scores in merge_anno.
[Key omission] There is no non-speech audio description — no textual description whatsoever of sound effects, ambient sound, background music, recording-space acoustics, or speaker timbre/accent. This contrasts sharply with MOVA's Qwen3-Omni-Captioner non-speech track, LTX-2's full soundscape description, or Foley-Omni's three-field schema. SpeakerVid-5M's audio-side annotation covers only "what was said (transcript)" and "how well synchronized it is (SyncNet values)," with nothing about "what it sounds like."
[No fusion step either] There is no cross-modal consistency verification and unified caption-synthesis step analogous to MOVA's use of GPT-OSS-120B. Each track is released side by side as separate folders, to be combined by users as they see fit.
[Assessment] This schema reflects SpeakerVid-5M's positioning — it is a "human-interaction-structure dataset" rather than an "audio-visual semantic dataset." Its value lies in the precise speaker-frame-lip-sync correspondence and rich structured metadata, not in rich joint audio-visual semantic description. Downstream users needing a joint caption must annotate it themselves.

### Dialogue transcription and speaker-attribute annotation (ASR transcription + speaker identity/language/accent/emotion) ⚠️

This is SpeakerVid-5M's strongest dimension, and its core asset that distinguishes it from other video datasets:
[Transcription] Whisper performs ASR, outputting a transcript per clip, retaining three diagnostic values used for filtering: transcription confidence (< −1.5 removed, HQ subset requires > −1), no-speech probability (> 0.8 removed), and compression ratio (> 2.5 removed, used to identify repetition degradation/hallucinated output). The pipeline also detects "language mismatch" and filters accordingly.
[Speaker diarization and identity annotation] A triple mechanism chained together, forming the technical backbone of this dataset:
  1) 3D-Speaker performs voiceprint diarization, selecting the two dominant speakers by speaking duration/frequency (together accounting for more than 80% of total speaking time); other speakers are discarded — this "only keep two main characters" decision directly defines the dataset's dyadic property.
  2) SyncNet confidence performs audio-visual binding, associating the audio-side speaker ID with the visual bounding box detected by YOLO, answering "which person in the frame does this voice belong to."
  3) ArcFace performs cross-clip identity correction, computing facial cosine similarity to verify consistency; outlier samples with higher similarity to a different ID are reassigned.
  This ultimately yields 83K unique speaker IDs in the single branch and 16K in the dialogue branch, with IDs traceable across clips throughout the entire dataset.
[Speaking/listening state determination (unique to this dataset)] Two sets of rules:
  - Co-present scene: if only one person is speaking, and the SyncNet score difference between the two exceeds a preset threshold, the lower-scoring party is judged to be "listening."
  - Non-co-present scene: if the ASR result is valid, the transcription confidence is above a threshold, but that person's video SyncNet score is below a preset threshold, they are judged to be a listener.
  This determination directly generates the listening branch — a rare design that explicitly models "who is listening" as a data label.
[Multi-turn dialogue context] The multi-turn branch aggregates the ASR transcripts of preceding turns within a time window [x−T, x] to form multi-turn dialogue context annotations; adjacent clips with a time gap smaller than δt are judged to be a continuous conversation and can be concatenated.
[Unannotated attributes] Language/language-family labels, accent, emotion category, speech rate, timbre description — these attributes, which are covered in natural language in MOVA's audio captions, have no corresponding field in SpeakerVid-5M (emotion information is only indirectly reflected through the visual-side facial expression summary). [Uncertain]

### Geometric and structured annotation (camera parameters, depth, 3D point tracks, action annotation, explicit state)

Structured annotation is a strength of this dataset, with a density far higher than most generative video datasets:
[Body pose] DWpose outputs complete keypoint sequences (skeletal sequences) for the face, hands, and body — the core geometric annotation prepared for downstream gesture generation and body-motion-driven tasks. Note: due to excessive data volume, the skeleton sequences themselves were not uploaded to HuggingFace; only the computation code was open-sourced, requiring users to run it themselves.
[Spatial boxes] Per-frame spatio-temporal bounding boxes from YOLO human detection and tracking, stored in merge_anno, and also the basis for clip spatial cropping.
[Facial identity features] ArcFace facial features and cross-clip cosine similarity, used for speaker-ID consistency verification.
[Discretized framing and orientation annotation] The caption's Upper-Body Only (half-body/full-body), Facing Direction (frontal/side), and Number of People fields explicitly discretize body composition — a differentiating annotation item relative to head-focused datasets like CelebV-HQ in Table 1.
[Camera motion] The caption's Camera Motion field annotates camera-motion patterns in text form, but as natural-language/categorical description, not parameterized camera pose (no extrinsic matrix, no trajectory coordinates).
[Motion intensity] Motion Intensity Level on a 1–5 scale (Qwen2.5-VL three-persona ensemble scoring).
[Blur and quality scores] Laplacian-variance blur scores for face/hands, clarity score, DOVER score.
[Numericized audio-visual synchronization] The SyncNet (offset, confidence, embedding distance) triple, saved per clip.
[Not provided] Camera intrinsic/extrinsic parameters, depth maps, 3D point tracks, optical-flow fields, 3D human mesh (e.g., SMPL), explicit physical-state annotation. Deep3DFaceRecon is used on the evaluation side to compute expression FID, but that is a VidChatBench evaluation tool, not a training-data annotation.

### Synthetic data construction (controlled perturbation/edit-constructed training pairs, e.g., InstructAV2AV) ⚠️

None. SpeakerVid-5M is entirely obtained from real YouTube videos through segmentation, cropping, filtering, and annotation, containing no model-generated or controlled-perturbation-constructed synthetic samples, and no "before-edit/after-edit" style training pairs (compare InstructAV2AV's controlled-perturbation construction).
[The only "constructive" component is data reorganization, not data synthesis] The way the four branches are organized has clear constructive character: the dialogue branch pairs the independent clips of two speakers from the same time period; the listening branch derives listening samples from originally speaking scenes via the SyncNet score-difference judgment; the multi-turn branch constructs multi-turn context via time-window aggregation and δt-interval concatenation. These are all re-pairing/re-sequencing of real footage, not the generation, editing, or perturbation of pixels or audio.
[Synthetic component on the annotation side] All captions, topic categories, and motion-intensity scores are automatically generated by MLLM/LLM — this is "synthetic annotation," not "synthetic content."
[Data augmentation] The paper does not describe any augmentation strategy at training time or data-construction time (e.g., temporal jitter, color perturbation, mixup). [Uncertain]

### Degree of human involvement (manual annotation, manual quality control, model pre-screening + manual review) ⚠️

The degree of human involvement is low and concentrated at the very front of the pipeline, with subsequent stages fully automated:
[Manual selection at the collection stage (the only clearly explicit human step)] The paper explicitly states this as "manually collected high-quality videos featuring two-person dialogue from YouTube" — that is, humans manually selected high-quality two-person dialogue videos from YouTube as source footage (153K videos / 64,386 hours). This step determines the dataset's genre composition and overall quality baseline, the most critical human judgment, but the paper does not specify the specific selection criteria, the number of participants, or the pass rate of manual selection.
[Threshold setting] The thresholds for the five-dimensional quality filter (luminance 10/210, DOVER 0.25, clarity bottom 5%, blur score 0.1, ASR confidence −1.5, etc.) and the HQ subset thresholds are all manually set empirical values, but the paper does not state whether these were calibrated the way MOVA did, i.e., through "manual spot-checking of retained samples under different cutoffs." [Uncertain]
[Annotation stage] Fully automated. Captions, topics, motion intensity, ASR, skeletons, and synchronization metrics are all produced by models, with no manual annotation, no manual review, and no two-stage "model pre-screening + manual acceptance" design.
[Quality assessment] The paper does not report any manual accuracy assessment of the automated annotation results (such as caption hallucination rate, diarization error rate, or a manual spot-check of speaking/listening determination accuracy), leaving the annotation quality without independent verification. The multi-persona ensemble scoring can be viewed as a model-based substitute for human consensus, but it is not equivalent to human verification.
[Evaluation stage] VidChatBench uses fully automatic objective metrics (FID, FVD, PSNR, SSIM, ArcFace cosine distance, CLIP distance, SyncNet confidence, expression FID, SIM-o), with no human-preference evaluation (human preference/Arena) design in evidence.

## Audio-Video Alignment

### Audio-video synchronization detection method (lip sync, event alignment)

Audio-video synchronization detection is the hub of the SpeakerVid-5M pipeline; its role extends beyond the usual scope of "quality filtering" to three structural functions:
[Function 1: Audio-visual identity binding (the most central)] After human detection, SyncNet computes the lip-audio overlap between each candidate human bounding box and the audio track, and uses the confidence score to bind the audio-side speaker ID to the visual-side bounding box. This step answers "which person in the frame did this voice come from," equivalent to active speaker detection, and is a prerequisite for constructing the entire dataset — without it, the voiceprint IDs obtained from diarization cannot be matched to the person on screen.
[Function 2: Speaking/listening state determination]
  - Co-present scene: if only one person is speaking, and the SyncNet score difference between the two exceeds a preset threshold, the lower-scoring party is judged to be in a "listening state."
  - Non-co-present scene: if the ASR result is valid, the transcription confidence is above a threshold, but that person's SyncNet score is below a preset threshold, they are judged to be a listener.
  This gives rise to the listening branch — a usage that elevates SyncNet from a "filter" to a "semantic state classifier."
[Function 3: Synchronization-quality filtering and annotation] SyncNet's three outputs (offset time shift, confidence, embedding distance) are saved as persistent per-clip annotations in the dataset for users to filter as needed; Figure 3 provides a distribution histogram of SyncNet confidence.
[Event-level alignment] Not involved. The dataset consists of purely speech scenes, with no need for detecting sound-effect-to-visual event alignment (e.g., footsteps, collisions), and no use of semantic-alignment tools such as Synchformer or ImageBind.
[Evaluation side] One of VidChatBench's six evaluation dimensions is audio-visual synchronization, also measured with SyncNet confidence.

### Specific synchronization metrics and thresholds (SyncNet/Synchformer/LSE/in-house, threshold values, e.g., MOVA's LSE-D ≤ 9.5 and LSE-C ≥ 4.5, SkyReels-V4's SyncNet |offset| ≤ 3 ∧ conf > 1.5) ⚠️

[Metrics used] SyncNet-family metrics, recording three items per clip: offset (audio-video time-shift in frames), confidence (synchronization confidence), and embedding distance (audio-video embedding distance, i.e., the equivalent of LSE-D). The dataset publishes these three as annotation fields rather than using them only for internal filtering.
[State of threshold disclosure] The paper repeatedly uses the phrase "pre-defined threshold" without giving specific values — the most regrettable disclosure gap in this entry:
  - In the speaking/listening determination, "the SyncNet score difference between the two exceeds a pre-defined threshold" — the difference threshold is not disclosed.
  - In the non-co-present listening determination, "the SyncNet score is below a pre-defined threshold" — this lower bound is not disclosed.
  - The five filtering criteria for the HQ / SFT subset (hand blur > 0.5, face blur > 0.7, DOVER > 0.6, motion score > 2, ASR confidence > −1) do not include a SyncNet item, indicating SyncNet was not used as a hard gate for the HQ subset.
[Comparison with similar work] MOVA explicitly gives dual thresholds of LSE-D ≤ 9.5 and LSE-C ≥ 4.5 and discloses that this filter yields about 2.5M clips; SkyReels-V4 gives SyncNet |offset| ≤ 3 and conf > 1.5. Although SpeakerVid-5M has the deepest dependence on SyncNet among the three (using it for identity binding and state classification, not just filtering), it is the only one of the three that does not disclose specific threshold values — a clear shortfall in method reproducibility. However, the open-sourced curation code repository may contain the actual threshold constants, which could serve as a supplementary avenue for verification.
[In-house metric] None; no new synchronization metric is proposed. [Uncertain]

### Separation of temporal synchronization vs. semantic synchronization (temporal alignment and content-semantic matching handled as two independent filtering conditions)

SpeakerVid-5M only handles temporal synchronization and does not perform semantic synchronization; the two are not separated into independent filtering conditions:
[Temporal synchronization] Fully covered by SyncNet — offset directly measures the audio-visual time-misalignment in frames, while confidence and embedding distance measure the frame-level correspondence strength between lip shape and phoneme. This is the dataset's sole alignment dimension, running through identity binding, state determination, and quality annotation.
[Semantic synchronization (content-level audio-visual semantic matching)] Entirely unaddressed. No use of ImageBind, the Synchformer semantic branch, CLAP, or any cross-modal semantic-similarity model to judge "whether the audio content and visual content match semantically."
[Why the absence is reasonable] The dataset consists of purely speech, purely close-up human scenes; the audio content is exactly the speech of the person on screen, so semantic matching is naturally guaranteed by SyncNet's lip-audio correspondence — as long as the lips match, the semantics necessarily match. The main value of semantic-synchronization filtering is to exclude mismatches typical of general audio-video data (e.g., "the visual is ocean waves but the audio is piano music") — such mismatches do not occur in a dyadic-talking scenario.
[Comparison with MOVA] MOVA explicitly separates temporal alignment (SynchFormer) and semantic alignment (ImageBind, IB-Score) into two independent filtering conditions, because its data covers foley, music, ambient sound, and other general audio-visual content; SpeakerVid-5M has no such need because of its vertical scenario. This is a methodological difference stemming from a difference in dataset positioning, not an oversight.

### Audio quality filtering (SNR, silence detection and silence-ratio thresholds, no-audio-track removal, voice-over-source removal, background-music separation) ⚠️

Audio-side filtering relies entirely on Whisper's diagnostic outputs, using three parallel veto rules, removed if any one is met:
[1. Transcription confidence] Whisper confidence score < −1.5 removed. The HQ / SFT subset further tightens this to > −1. This metric indirectly reflects audio intelligibility and signal-to-noise level — noisy, heavily reverberant, or far-field recordings will significantly lower the confidence.
[2. No-speech probability] no-speech probability > 0.8 removed. This single rule serves two functions simultaneously: removing silent clips and pure background-sound clips, and constraining the dataset to a purely speech corpus (clips dominated by sound effects, music, or ambient sound are eliminated by this rule).
[3. Compression ratio] compression ratio > 2.5 removed. This is a metric Whisper uses internally to detect transcription degradation — when the model falls into a repetitive-loop output (e.g., "thanks for watching thanks for watching…"), the compression ratio rises abnormally. This rule essentially removes ASR hallucination samples, a safeguard for annotation reliability rather than a direct measure of audio signal quality.
[4. Language mismatch] The pipeline also mentions filtering based on "detected language mismatches," i.e., removing samples where the language Whisper detects does not match expectations.
[Processing not performed] The paper does not describe any explicit SNR estimation and threshold, silence-ratio statistics and threshold, background-music separation (BGM separation/source separation), speech enhancement or denoising, voice-over/narration source removal, or loudness normalization. Compared to MOVA, which uses Audiobox-aesthetics' three-dimensional PQ/CU/CE aesthetic score plus silence-ratio and bandwidth thresholds, SpeakerVid-5M's audio quality control is notably thinner — it relies on the by-product metrics of a single model (Whisper) to complete all audio filtering, a low-cost but single-dimensional approach.
[No-audio-track samples] The raw-collection figure is already audio-visual paired video, and the dual filter of no-speech probability and confidence ensures that retained samples all contain valid speech, so there are no no-audio-track or no-speech samples. [Uncertain]

### Classification and differential handling strategy for speech/sound-effects/music

SpeakerVid-5M does not classify and differentially handle audio types — it excludes non-speech types wholesale via filtering, rather than classifying and then handling them differently:
[Actual strategy: convergence to a single type] The rule of removing anything with a no-speech probability > 0.8, combined with an ASR confidence floor, causes the final corpus to converge on a single audio type: human speech. Sound effects (foley), music, ambient sound, and silent clips are not classified and retained but simply eliminated. As a result, there is no audio-type branch within the dataset that requires "differential handling."
[Tools not used] No audio-type classifier (compare MOVA's use of the EAT self-supervised audio transformer to build speech/non-speech subsets routed by target capability), no source separation, no dedicated annotation or filtering path for music or sound effects.
[The only type-related design is a role dimension, not an acoustic dimension] The dataset's branch division (talking / listening / dialogue / multi-turn) distinguishes "speaker role and interaction form," not audio-type — all four branches' audio tracks are speech, with no acoustic-type routing. In the listening branch, the visual subject does not speak but the audio track is still the other party's speech — an audio-visual role mismatch, not an audio-type difference.
[Downstream consequence] Models trained on this dataset can only acquire speech-lip-sync capability, and cannot learn to generate foley, music, or ambient sound. This is consistent with MOVA's practice: MOVA positions SpeakerVid-5M as a source of lip-sync capability, while general sound-effect and music capability is injected separately from the audio-tower pretraining stage of datasets such as VGGSound, WavCaps, and JamendoMaxCaps. This pattern of "acquiring different audio capabilities from different datasets by division of labor" is precisely SpeakerVid-5M's position in the ecosystem as a vertical corpus.

## Training Integration

### Multi-stage training curriculum and data-curriculum scheduling (basis for stage division: resolution/duration/quality score/modality; low-res→high-res, image→video, short→long)

The dataset itself, in the form of "four branches + two quality tiers (full / HQ)," provides a ready-made scheduling structure for a multi-stage curriculum, and the baseline model designs a three-stage training scheme accordingly:
[Stage 1: Pretraining (single-person + pure-video objective)] Uses single-branch data, with ASR transcript text and captions as conditions, and a generation target of video modality only. This stage establishes the basic mapping from text/speech conditions to portrait video.
[Stage 2: Joint audio-video training] The generation target expands to dual video + audio modality, using filtered audio data. This stage establishes cross-modal joint generation capability.
[Stage 3: Fine-tuning / SFT (dyadic dialogue + high quality)] Uses high-quality dyadic dialogue audio-video pair data (the HQ subset), completing the capability transfer from single-person generation to dyadic interactive generation.
[Basis for curriculum scheduling] Three dimensions progress simultaneously: modality (video → video+audio), interaction complexity (single-person → dyadic dialogue), and data quality (full data → HQ subset). Unlike MOVA's curriculum, whose primary axis is "resolution + quality," the SpeakerVid-5M baseline's curriculum axis is "modality and interaction complexity" — a direct reflection of the dataset's four-branch structure.
[Resolution curriculum] None. The baseline uses a fixed 480×768 resolution throughout, with no low-res-to-high-res resolution progression.
[Duration curriculum] None. Clip length is fixed within the 3–14 second range, with no short-to-long duration progression; long context for multi-turn dialogue is provided by transcript aggregation in the multi-turn branch rather than by extending the video sequence.
[Compute] Stages 1 and 2 combined trained on 128 NVIDIA L40S GPUs for 15 days; Stage 3 fine-tuning trained on 32 NVIDIA A800 GPUs for 5 days.

### Data mixture changes across training stages (pretraining/annealing/SFT high-quality subset) ⚠️

[Changes at the scale level] A typical "large-scale low-threshold pretraining → small-scale high-threshold post-training" pyramid:
  - Pretraining stage: 7,375 hours (i.e., the remainder after subtracting the HQ subset's 1,368 hours from the total 8,743 hours). The paper explicitly describes this portion as large-scale pretraining data.
  - Fine-tuning stage: the high-quality SFT subset of 571K clips / 1,368 hours, about 15.6% of total duration.
  Notably, the paper adopts a "mutually exclusive division between the HQ subset and the pretraining set" (7,375 + 1,368 = 8,743), rather than "the HQ subset being a subset of the pretraining set" — that is, high-quality data is reserved exclusively for the post-training stage, and pretraining does not use it. This differs from most work's practice of "using the full set for pretraining and a curated subset of it for SFT," making it a relatively distinctive choice.
[Changes at the branch level] Pretraining uses the single branch; fine-tuning uses high-quality pairs from the dialogue branch. The specific usage proportions of the listening and multi-turn branches in baseline training are not stated. [Uncertain]
[Changes at the modality level] Stage 1 has a video-only target; audio targets are added starting from Stage 2 — i.e., audio data participation is introduced in a step-function jump from zero to full, rather than through gradual mixture adjustment.
[Not disclosed] The sampling weights of different data sources/branches/topic categories within each stage, whether there is an annealing stage, and whether long-tail speakers are resampled are all not stated. The paper does not provide a stage-wise data-mixture table.

### Post-training data (SFT curated-set scale and selection criteria, number of preference pairs and annotation method, reward-model training data)

[SFT curated set] 571K clips / 1,368 hours, with selection criteria requiring all five thresholds simultaneously: hand blur score > 0.5, face blur score > 0.7, DOVER fused score > 0.6, motion-intensity score > 2 (5-point scale), ASR transcription confidence > −1. Compared to the full-dataset filtering thresholds (blur score > 0.1, DOVER > 0.25, ASR confidence > −1.5, no motion requirement), the HQ thresholds are significantly tightened on every dimension, especially the blur score, raised from 0.1 to 0.5/0.7 (a 5–7x increase), and the newly added motion-intensity lower bound. The intent of this threshold combination is clear: it seeks samples with "clear faces, clear hands, good picture quality, rich motion, and clear articulation" — directly targeting the quality bottleneck for gesture and expression generation.
[Usage] Used for the baseline model's Stage 3 fine-tuning (32 A800s, 5 days), with the data described as "premium dialogue audio-video pairs."
[Preference data and reward model] None. The paper does not construct any preference pairs, does not train a reward model, and does not use DPO/RLHF-type preference optimization. The baseline's post-training consists solely of supervised fine-tuning (SFT).
[Human feedback] None. On the evaluation side, VidChatBench uses entirely automatic objective metrics, without human-preference evaluation or Arena-style comparison, so there is no human annotation reusable as preference data either.
[Comparison] MOVA likewise has no independent SFT/RLHF stage, instead using a three-stage progressive curriculum; the SpeakerVid-5M baseline, in contrast, has an explicit SFT stage but no preference optimization — an intermediate form of "has SFT, no RL."

### Data-processing infrastructure and throughput (NeMo Curator/Data-Juicer/in-house, GPU acceleration ratio, processing scale, cost) ⚠️

Disclosure is limited, but the code's open-source level is relatively high:
[Processing framework] No use of mature data-processing frameworks such as NeMo Curator or Data-Juicer, nor any mention of distributed scheduling frameworks such as Ray or Spark — an in-house, script-based pipeline. GitHub's Dorniwang/SpeakerVid-5M-Code is organized as six independent scripts: base annotation (synchronized audio-video extraction + single-person detection), DWpose skeleton annotation, ASR annotation, blur-score computation, luminance computation, and scene detection + speaker diarization (optional, some results precomputed). This step-by-script design facilitates reuse and resumable processing but has no unified scheduling layer.
[Dependency tool stack] 3D-Speaker, YOLO, DWpose, Whisper, PySceneDetect, SyncNet, ArcFace, Deepface, UniSpeech, Deep3DFaceRecon, yt-dlp — all open-source components.
[Processing scale] Input of 153K videos / 64,386 hours, output of 5.2M+ clips / 8,743 hours, with YOLO tracking, DWpose pose estimation, ArcFace features, SyncNet synchronization, Whisper ASR, Qwen2.5-VL captioning plus three persona scoring passes, and Qwen-3 topic classification each run on every clip — by clip count, the number of MLLM/LLM calls is on the order of tens of millions (5.2M clips × at least 4 VLM/LLM calls), a considerable inference cost.
[Not disclosed] The GPU model and count used for data processing, total wall-clock processing time, GPU-hours or monetary cost, GPU acceleration ratio, and throughput (clips/hour) are all missing. The paper discloses only the compute used for model training (128×L40S for 15 days + 32×A800 for 5 days), not the compute used for data processing.
[The skeleton-data volume issue] DWpose skeleton sequences were not uploaded with the dataset due to excessive volume, with only the computation code provided — indirectly indicating this annotation's data scale is considerable (per-frame full-body + hand + facial keypoints across 5.2M clips). ## Performance Comparison

### Quantitative impact of data-strategy ablations (distinguish: filtering-strictness ablation / caption-density-style ablation / data-mixture ablation, and corresponding evaluation metrics) ⚠️

The paper's ablation experiments focus on model architectural components, with no data-strategy-level ablation — the main limitation of this entry along the "performance comparison" dimension:
[Existing ablations (Table 2, on VidChatBench)] All are architectural-component ablations:
  - Conditioned baseline: FID = 56.82, FVD = 55.06
  - Adding audio generation (with spatial transformer + noise injection): FID = 38.53, FVD = 34.64
  - Dyadic setting but without the above components: FID = 49.97, FVD = 47.23
  - Full dyadic configuration (audio + spatial transformer + noise injection): FID = 32.35, FVD = 28.82
  The conclusions point to two things: the noise-injection training strategy significantly suppresses error accumulation in autoregressive generation; the spatial transformer brings a substantive improvement in visual metrics. The FID reduction from 56.82 to 32.35 is about a 43% decrease.
[Missing data ablations] The following three categories of data-strategy ablation were not conducted:
  - Filtering-strictness ablation: no comparison of "using the full 8,743 hours" vs. "using only the HQ 571K clips," so the benefit of the HQ threshold combination (blur 0.5/0.7, DOVER 0.6, motion score 2, ASR −1) lacks quantitative verification.
  - Caption density/style ablation: no comparison between structured JSON captions and natural-language captions, or of the impact of different caption field combinations on generation quality.
  - Data-mixture ablation: no comparison of different mixture ratios of the four branches (single/listening/dialogue/multi-turn), nor verification of the actual gains from the listening and multi-turn branches.
[Indirect scale evidence] The paper argues for its scale and annotation advantages via comparison with existing datasets such as CelebV-HQ, HDTF, MultiTalk, and OpenHumanVid (Table 1), but this is a dataset-attribute comparison rather than a training-effect comparison, and does not constitute data-ablation evidence. ### Evidence for quality vs. quantity (cases where small, refined data surpasses large, noisy data) ⚠️

The paper provides no direct quantitative evidence that "small and refined beats large and noisy," but its data design implicitly embraces this principle in practice:
[Implicit practice] Cutting out the HQ subset of 571K clips / 1,368 hours from the 8,743-hour total and using it exclusively for Stage 3 dialogue fine-tuning, while letting pretraining use only the remaining 7,375 hours — this "mutually exclusive division" design itself embodies the judgment that "high-quality data should be reserved for the training stage closest to the final capability." The HQ thresholds are several times stricter than the full-set thresholds on every dimension (blur score 0.1 → 0.5/0.7, DOVER 0.25 → 0.6, plus a newly added motion-score lower bound), indicating the team believes data quality matters more than quantity at the post-training stage.
[Missing verification] No controlled experiment of "training on the HQ subset alone vs. training on the full set" was conducted, so the question of "whether 1,368 hours of curated data can surpass 8,743 hours of the full set" cannot be answered. The Table 2 ablations are all architectural-component ablations unrelated to data volume.
[Indirect corroboration from end-to-end retention rate] Narrowing from 64,386 hours of raw footage to 8,743 hours (about 13.6%), then further to 1,368 hours of HQ data (about 2.1%) — this roughly one-in-fifty convergence ratio is quite aggressive among comparable datasets, reflecting the team's leaning toward prioritizing quality trade-offs. However, aggressive filtering alone is not evidence that "quality beats quantity."
[Comparison with similar work] MOVA provides curriculum-level evidence of increasing quality via three-stage scale reduction (61.5k → 37.6k → 11k hours) paired with metric improvements at each stage; SpeakerVid-5M has a design of the same shape but does not provide corresponding quantitative verification. ### Alignment relationship between training-data domain distribution and evaluation-benchmark category taxonomy (e.g., VABench's seven major categories) ⚠️

SpeakerVid-5M is one of the samples in this research round with the highest alignment between training-data taxonomy and evaluation benchmark — because the two were built by the same team from the same source, with VidChatBench cut directly from the dataset:
[Construction homology] VidChatBench comprises 500 test pairs, using unseen speaker IDs that did not appear in training — i.e., the test set and training set do not overlap at all along the identity dimension. It is not an independently collected external benchmark, but a held-out set produced by the same pipeline under the same annotation system.
[One-to-one correspondence between the six evaluation dimensions and data annotation]  Every dimension of VidChatBench's metrics can be traced to a corresponding construction basis in the dataset's annotation fields:
  1) Video quality (FID, FVD, PSNR, SSIM) ← corresponds to the data-side DOVER, clarity, luminance, and blur filtering.
  2) Identity preservation (ArcFace cosine distance) ← corresponds to the same tool and feature space used for ArcFace ID correction on the data side.
  3) Dialogue coherence (CLIP distance between generated results and LLM-ranked candidates) ← corresponds to the data-side ASR transcripts and multi-turn context aggregation.
  4) Audio-video synchronization (SyncNet confidence) ← corresponds to the same metric used for audio-visual binding and synchronization annotation on the data side via SyncNet.
  5) Emotion alignment (expression FID extracted by Deep3DFaceRecon) ← corresponds to the facial expression summary field in the data-side caption.
  6) Speaker identity/timbre (SIM-o timbre similarity, based on UniSpeech) ← corresponds to the data-side 3D-Speaker voiceprint ID system.
[Alignment of interaction-form categories] The dataset's four branches (talking / listening / dialogue / multi-turn) directly define the downstream task's capability breakdown, and VidChatBench's test pairs are organized in dyadic dialogue form, consistent with the dialogue branch's organization.
[Difference from external benchmarks like VABench] Benchmarks such as VABench are organized around seven major content categories (people, animals, nature, musical instruments, etc.), examining breadth of content coverage; VidChatBench instead is organized by "capability dimension" rather than "content category," because SpeakerVid-5M's content domain is highly singular (entirely real human dialogue), so breadth alignment does not really apply — the alignment instead occurs at a fine-grained depth dimension.
[Potential risk] This high degree of homologous construction alignment also means the benchmark may overestimate generalization ability — the test set and training set share the same collection preferences, the same cleaning thresholds, and the same systematic biases of the same annotation models; external validity across datasets has not been verified (the paper does not report results on external benchmarks such as HDTF or CelebV-HQ). [Uncertain]
