## Basic Information

### Name

OmniHuman Dataset + OHBench (OmniHuman Benchmark) — a large-scale dataset and three-tier evaluation benchmark for human-centric audio-video generation

### Publishing organization/company

A three-way collaboration between Peking University (Beijing, China), Tencent's WeChat Lab (China), and the Chinese Academy of Sciences (Beijing, China). Author list: Lei Zhu, Xing Cai, Yingjie Chen, Yiheng Li, Binxin Yang, Hao Liu, Jie Chen, Chen Li, Jing Liu (Jing LYu). Note: this work shares its name with, but is unrelated to, ByteDance's 2025 OmniHuman-1 talking-head generation model (arXiv:2502.01061) — the latter is a model, whereas this work is a dataset + evaluation benchmark; the two need to be distinguished when searching and citing.

### Release date (technical report/paper/open-source date) ⚠️

First submitted to arXiv on April 20, 2026 (arXiv:2604.18326v1), with a revised v2 submitted on May 30, 2026. Primary category cs.CV. The paper is 19 pages with 6 figures. As of July 2026, no clear conference-acceptance notation has been seen (the comments field only contains page and figure counts). The code and evaluation toolchain have been released on GitHub (github.com/julia-cherry/OmniHuman), and dataset annotations have been released on HuggingFace (julia527/omnihuman). [Uncertain]

### Type (model/dataset/toolchain/benchmark)

A trinity of dataset + evaluation benchmark + data-processing toolchain, containing no generative model. It consists of three parts: (1) the OmniHuman dataset — a human-centric audio-video dataset of 1 million videos / 1,800 hours / 80,000 identities, with hierarchical annotations; (2) a fully automated data-collection and multimodal-annotation pipeline — four-stage filtering + tracking + audio-visual attribution + two-stage caption generation; (3) OHBench — a three-tier (global/relational/individual), seven-dimension evaluation system, comprising 509 evaluation videos and an accompanying metric toolkit. The paper itself trains no new model; it only uses fine-tuning of LTX-2 as a validation experiment for data effectiveness.

### Degree of openness (whether weights/code/data/pipeline are each open-sourced) ⚠️

Among comparable human-centric datasets, its degree of openness is relatively high, but it carries the inherent limitation that "the video body itself is not distributed":
【Code】Open-source. The GitHub repository github.com/julia-cherry/OmniHuman provides the OHBench evaluation toolkit, covering evaluation scripts, configuration files, and Python dependency specifications for metrics such as imaging quality, dynamic degree, identity consistency, audio-video alignment, audio quality, speech quality, and dual-person interaction.
【Data (annotations)】Open-source. The HuggingFace dataset julia527/omnihuman totals roughly 62.7 GB of sharded tar archives, containing three types of assets: sample_json (per-sample audio-visual annotations: captions, subjects, speech, audio), metadata (JSONL index files for scanning and loading samples), and tracking_npz (per-frame SMPL/MANO body and hand tracking data).
【Data (video body)】Not distributed. The raw videos are not included in the release — each sample gives only a YouTube source URL plus precise clip start/end times (clip_start_sec / clip_end_sec), requiring users to download and locate the footage themselves. This is a common way of hedging copyright risk (following the same route as HD-VILA and Panda-70M), but it also means that as source videos are taken down, the dataset will continuously erode (link rot), and the actual data obtained by different users will gradually diverge.
【Evaluation assets and weights】The HuggingFace repository julia527/omnihuman_benchmark provides OHBench's model checkpoints and evaluation assets, mostly in .pt / .onnx format (i.e., packaged inference weights for third-party discriminative models such as MUSIQ, RAFT, ArcFace, SyncNet, and DNSMOS).
【Pipeline】Disclosed at the methodological level (the order of the four filtering stages, the tools used at each stage, the algorithmic chain of the tracking and attribution modules, and the structure of the two-stage captioning are all described), but threshold values are largely absent (see pipeline_overview and funnel_retention_rate for details), and the cleaning scripts themselves have not been released. Reproducibility sits somewhere between "knowing what was done" and "being able to redo it."
【License】The arXiv paper is under a perpetual non-exclusive license; neither the HuggingFace dataset page nor the GitHub repository carries an explicit license statement or terms of use, so the downstream scope of permitted use (commercial use allowed or not, restricted to research) is unclear. [Uncertain]

### Whether joint audio-video generation is supported, and the implementation approach (native joint / cascaded / MoE fusion)

This entry is a dataset and evaluation benchmark rather than a generative model, so it does not generate audio-video content itself; but its entire design serves "joint audio-video generation" as the target use case, making it one of the few resources in this survey natively constructed on the data side for the AV joint paradigm:
【AV-native nature on the data side】All samples are required to carry a raw audio track synchronized with the picture, verified through SyncNet-based attribution (see av_sync_detection for details); audio is separated into four sources via Demucs and the vocal and background components are annotated separately; captions cover both the visual track (appearance, actions, expressions) and the auditory track (speech content, emotion, background sound, music attributes) at once.
【Tasks supported on the evaluation side】OHBench explicitly supports a range of human-centric generation tasks: joint audio-video generation (audio-video joint generation, i.e., I2AV), speech-driven video generation (speech to video), video dubbing, controllable human video editing, and downstream speech-generation tasks. Of these, I2AV is the primary evaluation task, evaluating 10 models in total (5 closed-source: Veo3.1, Wan2.5, Sora2, Kling2.6, SeedDance-1.5-pro; 5 open-source: UniVerse-1, UniAVGen, Ovi, MOVA, LTX-2); in the speech-to-video task, InfiniteTalk performs best on some metrics.
【Neutrality toward generation paradigms】Neither the data nor the evaluation presupposes any particular one of "native joint / cascaded / MoE fusion" implementations, accommodating both joint-generation models (Ovi, MOVA, LTX-2) and cascaded/dubbing-style models (InfiniteTalk-type) alike — consistent with its positioning as a general-purpose benchmark.
【Empirical support】By fine-tuning LTX-2 (a native AV joint-generation model) with OmniHuman data and achieving across-the-board improvement on OHBench, the paper demonstrates that this data does provide a genuine gain for AV joint-generation models (see data_ablation for details).

## Data Scale and Distribution

### Training data volume (video count/hours/token count, pretraining and SFT reported separately) ⚠️

【Core scale】1 million videos, totaling 1,800 hours, covering 80,000 distinct identities. These three numbers together represent the complete scale figure given by the paper, more complete than most comparable works (which often give only a video count).
【Back-calculated average clip duration】1,800 hours ÷ 1 million clips ≈ 6.48 seconds per clip, i.e., the data is dominated by short clips on the order of 6 seconds, consistent with the training windows (5–10 seconds) of current AV joint-generation models. This back-calculated value can be cross-checked against the duration-distribution chart in Figure 3(d), but the paper's main text does not directly give an average duration.
【Identity density】80,000 identities / 1 million clips ≈ an average of 12.5 clips per identity, an identity diversity significantly higher than traditional talking-head datasets such as HDTF and CelebV-HQ (which typically have only hundreds to a few thousand identities) — this is a key advantage for a model's identity generalization ability, and is one of the differentiators the paper highlights in Table 1.
【Pretraining / SFT split】The dataset itself makes no split between pretraining and SFT — it is a general-purpose training resource, and the split is left to the user. The paper's own validation experiment used only 20% of it (180,000 single-person + 20,000 two-person = 200,000 samples) to fine-tune LTX-2, an SFT-style usage (see data_ablation for details).
【Evaluation subset】OHBench comprises 509 videos in total: 331 single-person, 128 two-person, and 50 person-object interaction. This subset is selected from OmniHuman, and the paper explicitly states there is a domain gap relative to the training set — i.e., out-of-distribution samples were deliberately chosen to avoid the evaluation being contaminated by the training set. This is a detail in the benchmark's construction that deserves credit.
【Not disclosed】The pre-filtering raw collection volume is not given at all, so the figure of 1 million has only a numerator and no denominator (see funnel_retention_rate for details); token count is not applicable; the specific counts of the single-person/two-person/person-object categories within the 1 million clips are only shown graphically in Figure 3(b), with no numeric value given in the main text. [Uncertain]

### Data source composition (proprietary/public datasets/web crawling/licensed acquisition/synthetic data) ⚠️

【Sole source: YouTube web video】The HuggingFace dataset page shows each sample carrying a YouTube source URL and clip start/end seconds — solid evidence for this dataset's provenance: the data is web-crawled YouTube content, with no proprietary footage, no licensed acquisition, no synthetic data, and no reuse of existing public datasets.
【Absence of this statement in the paper's main text】It is worth pointing out that the paper's main text does not state where the videos come from, only vaguely referring to the use of a "fully automated pipeline for high-quality data collection." The provenance information is confirmed only through the field structure of the HuggingFace release — a not-insignificant disclosure gap, since readers cannot judge the legal basis or potential distribution skew of the data from the paper alone.
【Collection orientation: targeted acquisition by scene and content type】Judging from the 8 scene categories it covers (home spaces, offices, natural environments, urban/rural landscapes, performance venues, retail, industrial areas, etc.) and the 8 content categories (talk shows, education, cooking, sports, music, gaming, reviews, film/TV), the collection appears to have been carried out by targeted retrieval against preset categories rather than undifferentiated crawling — this is a direct response to the pain point of "insufficient scene diversity" in existing datasets that the paper is addressing (traditional talking-head datasets concentrate on studio, front-facing, half-body shots; this dataset deliberately expands into diverse real-world scenes).
【Relationship to OpenHumanVid, etc.】Table 1 lists OpenHumanVid, SpeakerVid-5M, CelebV-HQ, and others as comparisons rather than upstream sources, indicating that samples from these datasets are not reused.
【Synthetic data】None. Neither the video side nor the audio side uses any synthetic or TTS-generated content (in contrast to UniTalking, which uses IndexTTS2 to synthesize 6.9 million reference audio clips). [Uncertain]

### Data compliance and provenance (proportion of licensed data, rights-cleared datasets, C2PA, etc.) ⚠️

Compliance and provenance is the weakest link in this work's disclosure, and its risk exposure is higher than that of an ordinary video dataset:
【At the paper level: zero compliance statements】The full text contains no ethics statement, no copyright discussion, no portrait-rights/privacy discussion, no informed-consent statement, no mention of C2PA or any content-provenance mark, and no statement addressing deepfake-abuse prevention. The paper also has no dedicated Limitations section discussing the above issues.
【Circumvention measure at the release level】It adopts an "annotations only, no video" distribution model (each sample gives only a YouTube URL + timestamps) — a standard academic method of hedging video copyright risk, which shifts the legal responsibility for downloading and use onto the user. This provides a degree of buffer on the copyright dimension, but is ineffective on the portrait-rights and privacy dimensions: the faces, 134-point full-body skeletons, SMPL/MANO 3D body and hand parameters, speech transcripts, and emotion labels of 80,000 real natural persons are all released in full, structured form, and these annotations themselves can serve as high-quality material for deepfakes — with a substantial portion of the filmed subjects never having consented to their use for training generative models.
【License gap】Neither the HuggingFace dataset page nor the GitHub repository carries an explicit license statement; the scope of use (research vs. commercial), redistribution conditions, and opt-out mechanism (a channel for data subjects to request removal) are all entirely absent. For a dataset of real people released publicly at the million-sample scale, this gap is more concerning than the methodological omissions.
【Comparison with upstream work】OpenHumanVid, to prevent misuse, requires downloaders to submit identity information for review and approval; OmniHuman has no access control of any kind.
【Proportion of licensed data】0% (entirely web-crawled, publicly visible content, with no licensed-acquisition portion). [Uncertain]

### Clip duration distribution and segmentation strategy ⚠️

【Distribution chart】The clip-duration distribution is given in Figure 3(d); the main text gives no specific percentages, mean, median, or quantiles. [Uncertain]
【Back-calculable average】From 1,800 hours / 1 million clips, an average of roughly 6.5 seconds per clip can be derived, pointing to a distribution dominated by 5–10-second short clips. This scale aligns closely with the native generation windows of current AV joint-generation models (Ovi 5 seconds, LTX-2 about 10 seconds, the Wan series 5 seconds), suggesting the segmentation granularity was designed around downstream training needs.
【Segmentation strategy】Duration is determined naturally by the outcome of TransNetV2's shot segmentation, rather than by manually set fixed-length windows — i.e., one clip corresponds to one complete shot (see shot_segmentation for details). This is the opposite of the "first cut fixed-length windows, then check whether they cross shots" approach; the benefit is that each clip is inherently free of internal transitions, at the cost of an uncontrollable duration distribution requiring extra upper/lower bound trimming (the paper does not state whether such bounds were set). [Uncertain]
【An implied lower-duration-bound constraint】The audio-governance stage discards samples with "abnormal duration," indicating that upper/lower duration bounds do exist as an admission rule, but the specific values are not disclosed. [Uncertain]
【Per-sample duration is queryable】The HuggingFace metadata includes each sample's fps, duration, and resolution fields, as well as clip_start_sec / clip_end_sec, so the complete duration distribution is empirically measurable by users — this to some extent compensates for the paper's disclosure shortfall.

### Resolution/aspect-ratio distribution and bucketing strategy ⚠️

【Admission threshold】The paper explicitly states that "all videos are of high-definition quality or higher," i.e., there is a hard resolution floor at 720p or above, but the specific pixel-count threshold is not given, nor is it stated whether the determination is by short edge, long edge, or total pixel count. [Uncertain]
【Distribution chart】The resolution distribution is given in Figure 3(c); the main text gives no specific percentage for each tier. [Uncertain]
【Aspect ratio】The paper does not discuss aspect-ratio distribution, does not describe a bucketing strategy, and does not state whether uniform cropping or padding was applied. Given that the data source is YouTube and the content types span talk shows, gaming, and reviews (mostly 16:9 landscape) as well as cooking and education (which may include vertical short-video content), the actual distribution is likely landscape-dominant but mixed with vertical content — however there is no data to support this. [Uncertain]
【Frame-rate normalization】Explicitly unified to 30 FPS (together with 44.1 kHz audio, as the standardized spec). This is one of the few explicit numeric specifications in the entire text, and frame-rate unification is a necessary precondition for frame-by-frame annotation (134 keypoints, SMPL/MANO tracking) and audio-video sync determination (a ±3-frame offset tolerance only has a well-defined meaning at a fixed frame rate).
【Spatial cropping】At the spatio-temporal cleaning stage, OCR and logo detection are used to estimate text-contaminated regions, and frame cropping is performed to remove subtitles and channel logos — this means that some samples' final aspect ratio will deviate from the original due to cropping; the paper does not state how the resulting aspect-ratio change is handled. [Uncertain]
【Per-sample queryable】The metadata contains a resolution field, so users can compile the complete distribution themselves.

### Category/domain distribution and mixture strategy (proportional control and concept balancing across people, actions, scenes, styles, etc.) ⚠️

Domain diversity is the primary founding motivation of this dataset — the paper lists "limited global scene and camera diversity" as the first structural flaw in existing datasets, and the entire dataset is designed to address it:
【Scene categories (8)】Home spaces, offices, natural environments, urban/rural landscapes, performance venues, retail, industrial areas, and others — eight scene types.
【Content categories (8)】Talk shows, educational, cooking, sports, music, gaming, reviews, and film/TV — eight content types.
【Human-configuration dimension (3 types)】Single-person, two-person, and person-object interaction. This is the core dimension distinguishing this dataset from all prior work — the paper lists "sparse interaction modeling (both human-human and human-object)" as the second structural flaw, and specifically annotates interaction labels, speaker IDs, and emotion for two-person interactions, and object information for person-object interactions. Table 1 shows that all prior comparison datasets (ActivityNet, TikTok-v4, OpenHumanVid, CelebV-HQ, VoxCeleb2, HDTF, SpeakerVid-5M) are blank in both the "person-object interaction" and "object annotation" columns — OmniHuman is the only one covering both.
【Camera and shot dimension】Annotations cover shot scale and camera motion; in Table 1, only OpenHumanVid and SpeakerVid-5M simultaneously have both of these. In the evaluation, it was found that "models degrade in performance on shot transitions from close-up to wide shot," indicating that the shot-scale annotation does indeed support fine-grained diagnosis.
【Mixture strategy: not disclosed】The specific proportions of the above 8+8+3 categories within the 1 million clips are not given numerically, except for the single-person/two-person ratio which appears in Figure 3(b). No concept balancing, resampling, long-tail suppression, or quota-control mechanism is described either — i.e., the paper proves it "covers these categories" but does not prove that "each category's distribution is balanced." Given that talk-show/review-type content is far more abundant on YouTube than industrial-area scenes, the actual distribution is very likely severely long-tailed. [Uncertain]
【Echo with the evaluation system】OHBench's 509 evaluation videos are composed at a ratio of 331 single-person / 128 two-person / 50 person-object, corresponding one-to-one with the dataset's three human-configuration categories, forming an explicit alignment between the training distribution and the evaluation category system (see benchmark_taxonomy_alignment for details).

### Audio category distribution and mixture (proportions and control strategy for speech/foley/music/ambient sound/silence) — a dimension unique to AV models ⚠️

The audio side adopts a strategy of "separation rather than filtering," which is this dataset's most valuable design choice on the audio dimension:
【Core approach: Demucs four-source separation】Demucs is used to perform four-source separation (the standard Demucs output being vocals / drums / bass / other) on every audio track, after which "the vocal track is used as the target track, and the remaining tracks are mixed together as the background track" — i.e., the final output is a "vocal track + background track" two-track structure. This differs from both UniTalking (which excludes samples containing background sound) and UniVerse-1 (which buckets by speech/non-speech): OmniHuman neither excludes nor buckets, but decomposes the mixed audio into two tracks that can be separately annotated and separately used, leaving the decision on mixture ratio to the downstream user.
【The practical value of this design】(1) It enables training controllable generation: a model can learn "with/without background music" conditional control; (2) it supports the video-dubbing task, which needs a clean vocal track as supervision; (3) it avoids the waste of "discarding an entire otherwise high-quality video just because it has background music" — given that the proportion of YouTube content with BGM is extremely high, adopting a UniTalking-style exclusion strategy would cause the retention rate to collapse catastrophically.
【Music-attribute annotation】Three attributes are separately annotated for background music: type, mood, and relative volume. "Relative volume" is a particularly pragmatic addition — it quantifies the energy ratio between the music and the vocals, letting downstream users filter samples by "music-dominant" versus "vocal-dominant" as needed. This is a rare instance of fine-grained music annotation among the samples surveyed here.
【Background-sound labels】The video-level annotations include the two fields background sound labels and music attributes, listed under the global tier.
【Speech】Speaker diarization is performed via 3D-Speaker, transcription via FunASR-Nano, with emotion and timestamps annotated (see dialogue_transcription_attributes for details).
【Undisclosed mixture ratios】The time-duration proportions of speech/music/sound effects/ambient sound/silence within the 1,800 hours are entirely undisclosed; the proportion of samples with/without BGM is undisclosed; the handling of pure-silence segments is only vaguely covered under "low-quality removal." [Uncertain]
【Audio normalization】Unified to a 44.1 kHz sample rate.

### Narrative structure distribution (single-shot vs. multi-shot, average clip duration, shot-count distribution, presence of native audio track) ⚠️

【Predominantly single-shot, guaranteed by segmentation】Using TransNetV2 for shot segmentation, each clip corresponds to a single continuous shot, so training samples are essentially single-shot segments. Combined with an average clip duration of roughly 6.5 seconds, the data does not carry cross-shot narrative.
【But shot-level metadata is retained】Although the samples themselves are single-shot, the annotations include shot scale (e.g., close-up/half-body/full-body/wide shot) and camera motion fields — this makes "shot language" a controllable condition rather than discarded information. The finding that "models degrade in performance on shot transitions from close-up to wide shot" during evaluation is precisely diagnosable thanks to the shot-scale annotation.
【Shot-count distribution】Not applicable (each sample is single-shot).
【Average clip duration】In the range of roughly 6.5 seconds (back-calculated from 1800h / 1M), distribution shown in Figure 3(d), no numeric value in the main text. [Uncertain]
【Presence of native audio track】Mandatory. The audio-governance stage discards samples with "missing tracks," and SyncNet-based attribution verification requires that the audio track corresponds to a person in the picture, so all samples carry a native audio track that is co-sourced and synchronized with the picture.
【Interaction structure as a substitute narrative dimension】Rather than pursuing cross-shot narrative, this dataset pursues richness of "relational structure" within a single shot — two-person dialogue (including speaker turn-taking and listener reactions) and person-object interaction constitute its distinctive structural content. This effectively shifts narrative complexity from "shot composition along the time axis" to "multi-subject relationships within space" — an orthogonal route relative to multi-shot datasets such as MuSS.

### Language/accent distribution (data foundation for multilingual lip-sync capability) ⚠️

【Language】Predominantly English, accounting for up to 80%. This is the only language-related figure given by the paper. The composition of the remaining 20% is entirely unstated — whether it is concentrated in a few mainstream languages or spread across a long tail cannot be determined. [Uncertain]
【Accent】No accent annotation or statistics whatsoever. Given that the data source is globally sourced YouTube content with English content at 80%, the actual data must inevitably contain American, British, Indian English, and other accents, but there is neither annotation nor distribution statistics for this. [Uncertain]
【Existence of language annotation】In the HuggingFace dataset's sample_json, the speech field contains "emotion, language, and timing information" — i.e., each sample is individually language-labeled, so the complete language distribution is empirically measurable by users, even though the paper does not aggregate it. This is the same situation as with the duration/resolution distributions — the annotation exists but the aggregate statistic is absent.
【Caption language】Captions are provided in two versions, English and Chinese — i.e., the annotation text itself is bilingual, but this is separate from the language of the audio content (80% English audio + bilingual English/Chinese captions). Bilingual captions are a practical convenience for the Chinese-speaking community.
【Language capability of the ASR model】FunASR-Nano (from the Alibaba DAMO Academy's FunASR family) performs best on Chinese while also supporting multiple languages; WER computation on the evaluation side uses SenseVoice (also a multilingual ASR model), so neither constitutes a language restriction.
【Implication for lip-sync capability】The 80%-English skew means that a model trained on this data will have a phoneme-viseme mapping dominated by the English phonetic system, with potentially weaker lip-shape accuracy for tonal languages (Chinese) and other phonetic systems — the paper does not discuss this potential bias. [Uncertain]

## Cleaning Pipeline

### Overall structure of the filtering funnel (number of stages, ordering)

Overall this is a fully automated pipeline structured as "four-stage filtering → structured perception → hierarchical annotation → verification," one of this work's core contributions. The stage ordering follows a "light-to-heavy" cost principle (in the paper's own words: a lightweight-to-heavy filtering strategy):
【Stage 1: Temporal-Spatial Cleaning】
- TransNetV2 performs shot segmentation, cutting long videos into single-shot clips;
- OCR and logo-detection algorithms estimate text-contaminated regions, and frames are cropped to remove subtitles and channel logos;
- Standardization to 30 FPS and 44.1 kHz.
【Stage 2: Audio Governance】
- Samples with a missing audio track, abnormal duration, or low quality (silence ratio, volume threshold) are discarded;
- Demucs performs four-source separation, with the vocal track as the target and the remaining sources mixed as the background track.
【Stage 3: Aesthetic Filtering】
- Frame-level CLIP aesthetic scoring quickly discards low-quality clips (fast, coarse);
- Video-level DOVER assessment of composition and clarity (slow, fine-grained);
- OCR text-density analysis and watermark detection.
【Stage 4: Motion and Temporal Consistency】
- UniMatch optical-flow analysis of motion quality, discarding static, shaky, or abnormally moving clips;
- Perceptual hashing + SigLIP cosine similarity to filter out semantically inconsistent frames.
【Stage 5: Structured Perception (not filtering — builds the annotation foundation)】
- YOLOv11 detects human instances → NMS refinement → MOTRv2 models cross-frame association via query propagation, yielding identity tracklets;
- DWPose-L extracts 134 full-skeleton keypoints (body, face, and feet), with dedicated hand detection and optimization;
- 3D-Speaker performs speaker diarization to obtain M speech segments; SyncNet resolves audio-visual attribution, greedily matching each audio segment to the visual ID tracklet with the highest response; ArcFace face embeddings complete identity assignment.
【Stage 6: Hierarchical Annotation】Two-stage caption generation with Qwen3-Omni as the reasoning core + Gemini-3 for background-plausibility and interaction-semantics adjudication (see caption_model / caption_structure for details).
【Stage 7: Consistency Verification】Multiple checks: the number of structured subject labels must match the count output by the tracking module; the number of speakers and the transcript content must stay within an acceptable edit-distance margin relative to the upstream ASR transcript. Only a video that passes all checks is retained.
【Structural evaluation】
- Strengths: a sensible ordering of stages (the cheap shot-segmentation and audio-track-presence checks come first, the expensive DOVER, optical flow, tracking, and MLLM annotation come later); the "perceive → annotate → reverse-verify" closed loop is uncommon — using the tracking module's output to verify the count in MLLM annotations, and using ASR transcripts to verify the speech content in captions, is a low-cost form of automated hallucination suppression (see model_as_data_judge for details);
- Weaknesses: threshold values are almost entirely undisclosed across the whole pipeline (CLIP aesthetic score, DOVER score, silence ratio, volume, optical flow, SyncNet score, and edit-distance bounds are all described qualitatively as "preset threshold," "acceptable margin," and similar phrases); no input/output volume is given for any stage; there is no deduplication step; and there is no safety-filtering step.

### Quantitative funnel retention rate (input/output volume and final retention rate at each filtering stage, e.g. Apollo's 27%) ⚠️

Entirely missing — the most severe gap in this work's data disclosure:
【Known】The final state: 1 million clips / 1,800 hours / 80,000 identities.
【Unknown】The raw collection volume (how many YouTube videos, how many hours, were crawled); the input and output volume of each of the four filtering stages; the attrition rate at each stage; the attrition volume from the tracking and audio-visual attribution stages; the attrition from the final consistency check; the overall end-to-end retention rate. The numerator is known while the denominator is entirely absent, making it impossible to compute a retention figure comparable to Apollo's 27% or MOVA's 26.39%, and impossible to judge the actual strictness of each filtering stage.
【Qualitative inference (with no basis in the paper)】Combining several strong constraints in the pipeline, one can judge that the overall attrition must be substantial: (1) the high-definition-or-above resolution floor would eliminate a large amount of old and low-bitrate content; (2) the requirement that audio be present and co-sourced with a person in the picture (SyncNet attribution + a ±3-frame offset) would eliminate the vast majority of YouTube content with voiceover, post-dubbing, or pure BGM — this is likely the single strongest filter; (3) the consistency check requiring the MLLM-annotated subject count to exactly match the tracking result should have a low pass rate for cluttered multi-person scenes. Taken together, the overall retention rate is very likely on the order of single-digit percentages, but this is speculation, not a stated conclusion. [Uncertain]
【Impact on reproducibility】The paper emphasizes "a fully automated pipeline" as one of its contributions, but with neither thresholds nor retention rates given, a third party attempting to rerun the pipeline as described in the paper would end up with a dataset of a different scale and quality distribution than the original, so the pipeline's reproducibility is not substantively realized. By comparison, UniVerse-1 gives all its thresholds and MOVA gives its stage-by-stage retention rates — OmniHuman lags behind on this point.

### Shot-splitting method (PySceneDetect/in-house model/shot-aware splitting) ⚠️

【Method】TransNetV2 — a dedicated deep-learning shot-boundary-detection model (compared with PySceneDetect's pixel/histogram-difference method, its recall is significantly higher for soft transitions such as gradual transitions, fade-ins/outs, and cross-dissolves — a more suitable choice for YouTube content dense with human editing artifacts). It sits at the very front of Stage 1, a precondition for all subsequent processing.
【Evaluation of the choice】This is a clearly superior choice compared with peer work — UniTalking has no segmentation step at all, and most works use PySceneDetect. Talk-show, review, and film-clip content on YouTube commonly carries heavy transition effects, and threshold-based segmentation would produce a large number of clips spanning transitions — TransNetV2 is the appropriate remedy.
【Post-segmentation handling】The output clips are used directly as sample units, with duration determined by the shot's own length (average roughly 6.5 seconds). The paper does not state whether overlong shots are further truncated, or whether upper/lower duration bounds were set (although the audio-governance stage's "abnormal duration" removal implies bounds exist, no values are given). [Uncertain]
【Backstop for transition residue】Stage 4's perceptual hashing + SigLIP cosine similarity filtering for "semantically inconsistent frames" can be regarded as a secondary backstop for segmentation misses — if a clip still contains a cross-scene semantic jump internally, it will be caught here. This "segmentation + semantic-consistency review" double-safeguard design is more robust than relying on a segmenter alone.
【Threshold】TransNetV2's decision threshold is not disclosed. [Uncertain]

### Quality filtering (aesthetic scoring, sharpness, OCR text filtering, letterboxing/watermark/logo detection) ⚠️

Visual quality filtering is concentrated in Stages 1 and 3, the part of the pipeline with the highest density of tools, using a clear light-to-heavy two-stage approach:
【Aesthetics and image quality: light and heavy stages】
- Light stage: frame-level CLIP aesthetic scoring (a CLIP-feature-based aesthetic predictor, i.e., a LAION-Aesthetic-type method), scoring each frame quickly, used to "rapidly discard low-quality clips." Its advantage is extremely low cost, allowing it to run at full scale; its drawback is that it only looks at single frames, not temporal information;
- Heavy stage: video-level DOVER (Disentangled Objective Video Quality Evaluator, a dedicated VQA model that disentangles video quality into an aesthetic branch and a technical branch), assessing composition and clarity. DOVER's computational cost is far higher than CLIP scoring, so it is placed afterward, processing only the surviving samples.
This "CLIP coarse pass + DOVER fine pass" two-stage structure is a fairly mature cost-effectiveness trade-off.
【Text contamination: a triple treatment of detection + cropping + density filtering】This is the most meticulous part of this pipeline relative to peer work, spread across two stages:
- Stage 1: OCR and logo-detection algorithms estimate "text-contaminated regions," after which frames are cropped to remove subtitles and channel logos — note this is "cropping out" rather than "discarding the whole video," maximally preserving data;
- Stage 3: OCR-based text-density analysis, wholesale discarding of samples that remain overly text-heavy even after cropping.
The comparison across three strategies is instructive: UniTalking discards on sight of any text (most wasteful), MOVA does not process text but annotates it as a controllable attribute (most data-preserving, but leaves the noise for the model to handle), and OmniHuman "crops where possible, discards only what cannot be cropped" (a middle ground with the heaviest engineering effort). For a data source like YouTube where burned-in subtitles are extremely common, the data-preservation value of the cropping strategy is considerable.
【Watermark detection】Stage 3 explicitly includes watermark detection, alongside OCR text-density analysis. The specific method and judgment criteria are not stated. [Uncertain]
【Resolution floor】High-definition or above (see resolution_aspect_distribution).
【Face clarity: a standalone metric】Frame-level annotation includes a face-clarity score, defined as Cs = Var(ΔR), i.e., variance of the Laplacian response — a classical image-blur metric. Notably, this score is retained as an annotation field rather than used only for filtering, meaning downstream users can filter subsets by face clarity themselves, offering more flexibility than a one-size-fits-all filter.
【All thresholds missing】The CLIP aesthetic-score threshold, DOVER score threshold, text-density threshold, and face-clarity threshold are all left without numeric values. [Uncertain]
【Not done】Letterboxing detection and removal is not mentioned; exposure/color-cast detection is not mentioned.

### Motion filtering (optical flow/motion-score thresholds, removal of static and shaky footage) ⚠️

【Tool】UniMatch — a unified optical-flow/stereo-matching/depth-estimation model, used here for optical-flow estimation to "analyze motion quality." A relatively newer choice compared with traditional RAFT or frame-differencing methods.
【Filtering target: both upper and lower bounds set】Three categories are explicitly excluded: static, shaky, and abnormal clips. This is an improvement over UniTalking (which only excludes static content, with no upper bound), i.e., OmniHuman sets both a motion floor (against photo-like static footage or subjects that never move) and a motion ceiling (against handheld shakiness, extreme jitter, and the resulting motion blur and unlearnable samples). For a dataset sourced from YouTube footage, excluding shaky samples is necessary — a large amount of vlog and outdoor content is handheld.
【Coordination with the semantic-consistency filter】The same stage also includes the perceptual-hashing + SigLIP cosine-similarity "semantically inconsistent frame" filter. The division of labor is clear: optical flow governs "whether pixel-level motion is reasonable," while SigLIP governs "whether the semantic content is coherent" — for example, a clip with smooth optical flow but a subject fully replaced partway through would not be caught by optical flow, but would be caught by SigLIP. This "low-level motion + high-level semantics" dual temporal-consistency check is uncommon among comparable works.
【Threshold】The upper/lower bound values for optical-flow magnitude, the SigLIP cosine-similarity threshold, and the perceptual-hashing Hamming-distance threshold are all undisclosed. [Uncertain]
【Echo with the evaluation】OHBench's global tier includes a Dynamic Degree (DD) metric, using RAFT optical flow to measure the motion intensity of generated video — i.e., the motion-filtering dimension of the training data corresponds to the motion-diagnostic dimension of the evaluation (though one uses UniMatch and the other RAFT). In the LTX-2 fine-tuning experiment, DD improved by 10.7%, indirectly suggesting that the motion-filtered data did let the model learn more thorough motion.

### Deduplication method (exact deduplication and embedding-based semantic deduplication recorded separately) ⚠️

【Explicit deduplication step: none】The paper describes no sample-level deduplication step whatsoever — no video-fingerprint/pHash-level exact deduplication, no CLIP/SigLIP-embedding-level semantic deduplication, and no cross-source duplicate check.
【A related technique used for another purpose】Stage 4 uses perceptual hashing + SigLIP cosine similarity, but its stated purpose is explicitly "to filter semantically inconsistent frames," i.e., an intra-clip temporal-consistency check, not cross-sample duplicate detection. The technical means is highly similar to deduplication but the purpose differs, so it cannot count as deduplication.
【Specific forms of duplication risk】For a dataset sourced solely from YouTube, duplication risk has specific characteristics: (1) multiple uploads of the same content (reposts, reuploads, compilations) are extremely common on YouTube; (2) series videos from the same uploader (same studio, same camera position, same person) can produce large numbers of highly similar clips; (3) 80,000 identities / 1 million clips implies an average of 12.5 clips per identity — if the identity distribution is heavily long-tailed, top creators could contribute hundreds of near-homogeneous clips.
【Identity-level deduplication and quotas: also absent】The paper describes no sampling quota or long-tail-suppression mechanism by identity. Although the figure of 80,000 identities is eye-catching, its distribution shape (uniform or not) is entirely unknown — if it follows a power law, the actual effective identity diversity would be far lower than the nominal value. [Uncertain]
【Partial backstop in the evaluation set】OHBench's 509 videos are selected from OmniHuman but explicitly required to have a "domain gap" relative to the training set, which avoids train-eval leakage at the evaluation level, but this does not address redundancy issues within the training set itself.

### VLM/LLM as data quality judge (multimodal large-model quality scoring and mismatch removal; the 2026 trend of shifting from shallow scorers to large-model semantic judgment) ⚠️

OmniHuman is one of the samples in this survey most aligned with the "2026 large model as data quality judge" trend, and its use of large models has a clear tiered division of labor:
【Gemini-3: semantic adjudicator】Used for "background plausibility and interaction assessment" — i.e., a top-tier closed-source multimodal model judges the semantic plausibility of the scene and the naturalness of person interactions. This is a typical case of using a large model in place of a shallow scorer for semantic-level judgment, a dimension that shallow metrics (aesthetic score, clarity) fundamentally cannot cover.
【Gemini-3 / Gemini-3-pro: the primary judge on the evaluation side】In OHBench they handle four dimensions scored on a 1–10 subjective scale: Background Plausibility (global tier), Interaction Naturalness (relational tier, including eye contact, body gestures, response accuracy), Object Consistency (temporal stability of appearance/position/state), and Contact Naturalness (spatial accuracy/temporal synchronization/force realism). This is the most aggressive step in this work — handing over dimensions of semantic/physical plausibility that have traditionally required human scoring entirely to Gemini-3, and using this as the metric basis for claiming "high consistency with human perception."
【Qwen3-Omni: an annotation generator, not an adjudicator】As the reasoning core for caption generation, it is responsible for extracting attributes and synthesizing narrative, not for quality adjudication.
【The most valuable design: a cross-validation closed loop】The consistency check at the end of the pipeline is this work's substantive design for "guarding against MLLM hallucination," and it relies not on an even larger model but on redundancy across modalities:
- The count of structured subject labels must exactly match the number of people output by the tracking module (YOLOv11 + MOTRv2) — using a visual-geometry pipeline to check the MLLM's counting hallucination;
- The number of speakers in the caption and the transcript content must stay within an acceptable edit-distance margin relative to the upstream ASR (FunASR-Nano) transcript — using ASR results to check the MLLM's speech-content hallucination;
- Only a video passing all checks is retained.
This approach of "using the output of a deterministic, dedicated model to constrain the output of a generative large model" is, in principle, more reliable than MOVA's use of GPT-OSS-120B for hallucination_check (i.e., using a large model to check a large model), because the error modes of tracking and ASR are independent of the MLLM's hallucination modes.
【Limitations】The "acceptable" edit-distance bound is not given a numeric value; Gemini-3's judgment thresholds and prompts are not disclosed; heavy reliance on a closed-source API model (Gemini-3) makes the reproducibility and long-term stability of the entire pipeline dependent on a third-party service, and the paper does not mention the cost of calling a closed-source API at million-sample scale. [Uncertain]

### Safety and compliance filtering (NSFW, copyright, face/privacy) ⚠️

【Completely absent】The paper involves no safety or compliance filtering of any kind: no NSFW/pornography/violence content detection, no minor-content identification, no copyright filtering, no facial-privacy de-identification, no voiceprint-privacy handling, no hate-speech or harmful-content filtering, and no model-card-level usage restriction statement. The full text also has no ethics-statement section.
【The special risk exposure of this dataset】Compared with other entries, the consequences of this gap are more severe here:
1) The data source is undifferentiated YouTube crawling — although the YouTube platform has its own content moderation, its moderation standard ("suitable for public playback") is entirely different from a training-data standard ("suitable for use in training a generative model"); for example, a large amount of adult-adjacent, borderline, or violent gameplay-livestream content is compliant on the platform but unsuitable as training data;
2) The release contains ArcFace face embeddings, 134-point skeletons, SMPL/MANO 3D parameters, speech transcripts, and emotion labels for 80,000 real people — a complete kit directly usable for identity forgery, with no admission review;
3) The content types explicitly include "film/TV," the category with the most sensitive copyright status, and even URL-based distribution cannot fully hedge this;
4) Among the 8 content categories, "education" and "gaming" contain substantial amounts of children-related content on YouTube, with no minor-identification mechanism.
【The only indirect mitigation】Releasing only annotations and URLs, not the video body, provides a buffer on the copyright dimension (see provenance_licensing for details), but offers no mitigation for content safety or portrait privacy.
【Comparison with upstream work】OpenHumanVid has a download-approval mechanism; OmniHuman has no access control of any kind. [Uncertain]

## Annotation Methods

### Captioning model used (in-house VLM/open-source model, model scale) ⚠️

All off-the-shelf models are used, with no in-house captioner, forming a two-tier structure of "an open-source all-modal model as the workhorse + a top-tier closed-source model as the semantic judge":
【Qwen3-Omni — the annotation reasoning core】Alibaba's open-source all-modal large model (accepting video, audio, and text simultaneously), serving as the inference core for caption generation, responsible for Stage-1 hierarchical feature extraction: global video context + a fine-grained attribute set (appearance, motion, expression, speech, music, sound effects). Choosing an all-modal model rather than a pure vision VLM is a key decision in this work — because what needs to be annotated inherently spans both visual and auditory modalities (background-sound labels, music attributes, and speech emotion can only be annotated by actually hearing the audio), a pure VLM cannot handle it. The parameter scale used is not disclosed. [Uncertain]
【Gemini-3 / Gemini-3-pro — semantic determination】Responsible for background-plausibility and interaction assessment, the hardest semantic/physical-level judgment in the annotation process, and also the scoring model for OHBench's subjective dimensions. Using a closed-source API model indicates the team judged open-source models to be not yet reliable enough on this dimension.
【FunASR-Nano — ASR】The lightweight tier of the DAMO Academy's FunASR family, responsible for speech transcription, producing text with speaker IDs and timestamps. Choosing the Nano tier is a cost consideration at million-sample scale.
【3D-Speaker — speaker diarization】Identifies the M active speech segments in the audio and their speaker indices.
【SyncNet — audio-visual attribution】Resolves which speech segment belongs to which person in the picture.
【ArcFace — identity embedding】Face-feature extraction, used for identity assignment and reference-face selection.
【YOLOv11 + MOTRv2 — detection and tracking】Human-instance detection (with NMS refinement) and cross-frame association (via query propagation).
【DWPose-L — pose】134 full-skeleton keypoints (body + face + feet), with dedicated hand detection and optimization.
【Comparison with peer work】The scale and specialization of the annotation-model lineup are among the highest in this survey's samples: MOVA uses MiMo-VL-7B + Qwen3-Omni×2 + GPT-OSS-120B (four large models but no geometric pipeline); UniTalking uses Qwen3-VL + Whisper-V3 + Qwen3-Omni (three large models, zero geometric annotation); OmniHuman uses 2 large models + 7 specialized discriminative/geometric models, its distinctive feature being that it connects geometric perception (tracking, pose, identity) with semantic annotation (captioning) and has them cross-check each other.
【Annotation prompts】None disclosed. [Uncertain]

### Caption density and structuring level (short/long/dense descriptions; structured fields such as camera motion, style tags) ⚠️

Adopts a structure of "hierarchical annotation + two-stage generation + placeholder anchoring," the most distinctive design at the methodological level in this work:
【Three-tier annotation system (the paper's core organizing principle)】
- Video-level / global tier: scene type, shot scale, camera motion, background, lighting, background-sound labels, music attributes (type/mood/relative volume);
- Frame-level / interaction tier: human-human interaction labels (including speaker ID and emotion), human-object interaction annotations, DWPose-L's 134 full-skeleton keypoints, the face-clarity score Cs = Var(ΔR), lip-sync quality assessment;
- Individual-level / attribute tier: person-ID assignment (face-embedding similarity > 0.55), body movement, appearance, expression state, speech transcript with emotion and timestamps, speech-quality annotation.
The three tiers respectively correspond to the three major flaws the paper identifies in existing datasets (insufficient scene diversity / sparse interaction modeling / insufficient individual-attribute alignment); the structure maps one-to-one with the problem diagnosis, a very clean piece of narrative organization in the paper.
【Structured output form】Each video produces a set of per-subject structured records: {(ID_i, B_i, K_i, X_i, A_i, C_i)}, where ID is identity, B is bounding box, K is keypoints, X is attributes, A is audio-related, and C is hierarchical caption. This is a schema "organized by person" rather than "organized by video" — especially important for multi-person scenes, since it naturally supports relational statements such as "person 2 is speaking while person 1 is listening."
【Two-stage caption generation】
- Stage one: Qwen3-Omni extracts fragmented attributes (a scattered set covering appearance, motion, expression, speech, music, sound effects, and so on);
- Stage two: the fragmented attributes are synthesized into a coherent long-form narrative caption.
That is, "structure first, then verbalize" — compared with letting an MLLM write a long caption in one pass, this approach decouples "what is seen" from "how it is described," significantly reducing attribute omission and confabulation in long-text generation.
【Placeholder anchoring mechanism】Captions reserve fixed-position anchors, such as [speech_m]-style placeholders, which are later replaced with actual content (e.g., the real dialogue transcribed by ASR). This design solves a specific problem: an MLLM restating speech content within a long caption is extremely prone to hallucination or paraphrasing; by changing the design so that "the MLLM is only responsible for leaving a slot in the right place, and the real content is filled in by ASR," dialogue hallucination is eliminated by construction. This is a very practical small design that improves annotation reliability in this work.
【Identity-alignment mechanism】Identity alignment based on reference face images, using a ⟨REF_i⟩ suffix marker to bind each person mentioned in the caption to a specific reference face — making references in the caption such as "the man on the left" or "the woman in red" have a determinate visual anchor, which is essential for controllable generation in multi-person scenes. The reference face is selected by "taking the frame with the highest average confidence for facial keypoints."
【Caption language】Provided in two versions, English and Chinese.
【Not disclosed】Caption length statistics, word-count distribution, example raw text, and the annotation prompts are all not given. [Uncertain]

### Joint audio-video caption structure (whether both visual and auditory tracks are covered simultaneously; whether split into independent fields, e.g. LTX-2's full-soundscape description, Script-a-Video's factorized streams, Foley-Omni's three-field design) ⚠️

OmniHuman's joint audio-visual caption structure takes a hybrid approach of "structured multi-field coexistence + final synthesis into a single narrative," and is the broadest in field coverage among this survey's samples:
【Auditory-side fields】Background-sound labels, the music-attribute triple (type/mood/relative volume), per-speaker speech transcripts, speech emotion, speech timestamps, speech-quality annotation, and lip-sync quality assessment.
【Visual-side fields】Scene type, shot scale, camera motion, background, lighting, person appearance, body movement, expression state, human-human interaction, human-object interaction, 134 keypoints, face clarity.
【Fusion method】Stage one is performed by Qwen3-Omni (an all-modal model consuming both audio and video simultaneously), extracting all of the above attributes — note that this extraction is itself cross-modal from the start, rather than a visual model annotating the visual side and an audio model annotating the audio side and then concatenating the results; Stage two synthesizes all the fragments into a single long-form narrative caption, with visual and auditory content interwoven within the narrative rather than presented as separate parallel segments.
【Positioning relative to three existing routes】
- UniVerse-1: "annotation is split, and training is split too" (the three fields always remain independent);
- MOVA: "annotate separately, then synthesize into a single paragraph using a 120B LLM";
- UniTalking: "keep both the factorized and fused end products, randomly choosing one of the two during training";
- OmniHuman instead follows "extract structured fields cross-modally in one pass using an all-modal model → synthesize into a single narrative caption," with the structured fields themselves also released alongside the dataset (the sample_json's captions / subjects / speech / audio fields listed side by side). This means users can obtain both the fused natural-language caption and the raw structured fields for their own re-composition — a practical advantage over solutions that release only the final caption.
【The most distinctive point: music's "relative volume" field】Explicitly quantifies the energy relationship between background music and vocals, allowing downstream users to filter data by soundscape composition (e.g., vocal-dominant samples only for training a dubbing model, music-rich samples only for training full-soundscape generation). This granularity has not been seen in comparable work.
【Hallucination protection】Achieved via the placeholder mechanism (speech content filled in by ASR) and the consistency check (subject count aligned with tracking results, transcript content aligned with ASR) — see model_as_data_judge for details — this is a reliability advantage of this schema relative to comparable work.
【Limitations】Whether the caption and the structured fields are fully consistent has not been comprehensively verified (only subject count and speech content were checked); although sound effects are listed among the attributes extracted in Stage one, no corresponding independent annotation field is described, and the granularity at which they appear in the final caption is unclear. [Uncertain]

### Dialogue transcription and speaker-attribute annotation (ASR transcription + speaker identity/language/accent/emotion) ⚠️

Dialogue and speaker attributes are the most thoroughly annotated part of this dataset, and the core increment relative to prior work such as OpenHumanVid:
【Transcription】FunASR-Nano performs ASR, producing speech text with speaker ID and timestamps attached. The transcript serves two purposes: as annotation content in its own right, and as ground truth for checking the MLLM's caption (via edit distance).
【Speaker diarization】3D-Speaker performs diarization, identifying M active speech segments and their respective speaker indices. This is the precondition for annotating two-person scenes.
【Speaker-to-picture attribution (the key step of this work)】SyncNet resolves audio-visual attribution, greedily matching each audio segment to the visual ID tracklet with the highest response; ArcFace face embeddings then confirm identity (similarity > 0.55 judged as the same person, with tracking-loss tolerance of up to a 5-frame gap). This step binds "speaker m in the audio" to "person i in the picture," a necessary condition for two-person dialogue data to be usable — without it, the model would have no way of knowing whose mouth should move. Table 1 shows that among prior comparison datasets, only SpeakerVid-5M had any speaker annotation at all.
【Speaker-attribute annotation】
- Emotion: annotated per speaker and per speech segment, appearing both at the individual tier (speech transcript with attached emotion) and the interaction tier (human-human interaction labels including speaker ID and emotion);
- Language: the speech field in sample_json carries a language label;
- Timing: start/end timestamps for speech segments;
- Speech quality: a standalone speech-quality annotation at the individual tier;
- Lip-sync quality: a lip-sync quality assessment in the frame-level annotation.
【Not annotated】Speaker gender, age, and ethnicity are not annotated; a textual description of timbre/voiceprint is not seen (unlike MOVA's detailed timbre descriptions); accent is not annotated; speaking rate and volume are not annotated per speaker (music has relative volume, speech does not). [Uncertain]
【Multi-speaker support】Fully supported, and one of the design focuses of the dataset: 128 two-person evaluation videos, two-person interaction labels, a two-person ID-consistency evaluation metric (IC*, using ArcFace cosine similarity), and a listener-realism metric (LR, evaluating the accuracy of audio-visual attribution and the naturalness of the listener's expression). This "listener" dimension is particularly rare — most speaker datasets only care about the person speaking, whereas OmniHuman explicitly evaluates whether the non-speaking person behaves naturally, directly addressing the most common failure mode in two-person dialogue generation (both people appearing to talk at once).
【Evaluation-side metrics】Pronunciation accuracy is computed via SenseVoice's WER; speech realism via DNSMOS's OVRL score; lip sync via SyncNet.

### Geometric and structured annotation (camera parameters, depth, 3D point tracks, action annotation, explicit state) ⚠️

Geometric and structured annotation is OmniHuman's most standout advantage among all entries in this survey — most AV generation datasets score zero here, whereas OmniHuman has built a complete geometric pipeline:
【Human detection and tracking】YOLOv11 detects human instances → NMS refinement → MOTRv2 models cross-frame association via query propagation, outputting per-person identity tracklets and bounding boxes (B_i). Tracking-loss tolerance is 5 frames (beyond which the track is considered broken).
【2D skeleton: 134 keypoints】DWPose-L extracts 134 full-skeleton keypoints across body, face, and feet, with dedicated hand detection and optimization — separately optimizing the hands is a pragmatic detail, since general-purpose pose estimators are generally least accurate on hands, and hand movement is precisely the key to human-object interaction and gestural expression.
【3D parametric human body: SMPL / MANO】The HuggingFace release's tracking_npz explicitly contains "per-frame SMPL/MANO body & hand tracking" — i.e., the dataset also provides per-frame parameters for 3D parametric body and hand models. This is an important asset present in the released materials though not emphasized in the paper's main text, providing direct support for downstream applications such as pose-controllable generation, 3D-consistency constraints, and motion retargeting. Note that the paper's main text mentions only DWPose's 2D keypoints — how the SMPL/MANO parameters were obtained (which estimator was used, how they were fused with the 2D keypoints) is entirely unstated. [Uncertain]
【Identity embedding】ArcFace face features, used for identity assignment (similarity > 0.55) and cross-frame/cross-sample identity consistency. The reference-face selection rule is "the frame with the highest average confidence for facial keypoints."
【Face clarity】Cs = Var(ΔR), the Laplacian-response variance, retained as a queryable annotation field.
【Shot-language parameters】Shot scale and camera motion as video-level annotation fields — while these are labels rather than continuous parameters, they are already sufficient to support shot-level controllable generation and diagnostics.
【Human-object interaction annotation】Frame-level annotation includes person-object interaction annotations and object annotation (the Object Anno. column in Table 1), the only entry among all comparison datasets to have this.
On the evaluation side this corresponds to two metrics: Object Consistency and Contact Naturalness (spatial accuracy/temporal synchronization/force realism).
【Not provided】Camera intrinsics/extrinsics (no camera calibration or pose estimation), depth maps, 3D point tracks, optical-flow fields (UniMatch's optical flow is used only for filtering, not retained as annotation), and expression coefficients (3DMM/FLAME blendshapes — although SMPL is present, no parametric facial-expression coefficients are seen). [Uncertain]

### Synthetic data construction (controlled perturbation/editing to construct training pairs, e.g. InstructAV2AV)

【None】The dataset consists entirely of real, collected YouTube video, with no synthetic or controlled-editing-constructed training pairs used at all: no generation/editing samples on the video side, no TTS-synthesized content on the audio side (in contrast to UniTalking's use of IndexTTS2 to synthesize 6.9 million reference audio clips), and no controlled-perturbation-constructed instruction-editing pairs (not an InstructAV2AV-style route).
【The one "constructive" operation: derived tracks from source separation】Demucs's four-source separation splits the original mixed audio track into a vocal track and a background track, producing two derived signals that do not independently exist in the raw data. Strictly speaking this is signal-processing decomposition rather than data synthesis, but it does functionally construct new possible training pairings — for example "vocal track + video" can train a dubbing model, "background track + video" can train ambient-sound generation, and "video → vocal + background" can train full-soundscape generation. This is a low-cost, zero-hallucination-risk way of gaining data benefit, and unlike a TTS-synthesis route it introduces no train/inference domain gap.
【Frame cropping also introduces a slight distribution shift】The frame-cropping operation that removes subtitles/logos changes the composition and aspect ratio of some samples, but this is preprocessing rather than synthesis.
【Judgment on the design orientation】This dataset positions itself around "complex, real-world physical scenes," deliberately pursuing a real-world distribution, so not introducing synthetic data is self-consistent with its founding logic — synthetic data would introduce distribution shift, which would run counter to the problem it diagnoses (insufficient scene diversity).

### Degree of human involvement (human annotation, human QC, model pre-screening + human review) ⚠️

【Data side: the paper claims full automation with no human involvement】The pipeline is explicitly positioned as a "fully automated pipeline for high-quality data collection and multi-modal annotation," with full automation itself being one of the paper's claimed contributions. The four-stage filtering, tracking and pose estimation, audio-visual attribution, hierarchical annotation, and consistency verification are all carried out by models, with the paper mentioning no human annotation, human spot-checking, or human review step at all.
【The quality backstop for automation relies on cross-validation rather than human effort】Using tracking results to check the MLLM's subject count, and using ASR transcripts to check the caption's speech content (via edit distance), is a design that substitutes "modal redundancy" for "human review" (see model_as_data_judge for details). In principle this is more reliable than a fully automated pipeline with no checks at all, but it still cannot cover dimensions that cannot be cross-validated, such as attribute-description accuracy, interaction-label correctness, and emotion-annotation consistency.
【Human involvement in threshold calibration is unstated】How the thresholds for each filtering stage (CLIP aesthetics, DOVER, optical flow, SyncNet, the 0.55 similarity, the edit-distance bound) were determined is not mentioned anywhere in the paper — whether they were calibrated via human spot-checking (as MOVA explicitly describes: "manually inspecting the retained samples under different cutoffs") is unknown. Values like 0.55, 5 frames, and 3 frames look like empirical choices, but there is no record of a calibration process. [Uncertain]
【Evaluation side: subjective dimensions handed to Gemini-3 rather than humans】This is this work's most aggressive, and most debatable, choice regarding human involvement. OHBench's core claim is to "introduce metrics that are highly consistent with human perception," but the implementation is to have Gemini-3 / Gemini-3-pro score on a 1–10 scale, rather than organizing human evaluation.
【The key gap: insufficient evidence for human-consistency】In the paper's main text, the core claim of being "highly consistent with human perception" is only given a qualitative statement (claiming that the supplementary material contains "evidence that our metrics align better with human judgment"), with no user-study details given in the main text — no number of raters, no rater background, no Spearman/Kendall correlation coefficients, no numeric correlation comparison against existing metrics such as VBench, and no inter-rater reliability (IRR). For an evaluation benchmark whose core selling point is "human-perception consistency," this is precisely the part that should be quantified but is instead missing — the biggest methodological soft spot in this work. [Uncertain]
【Points of comparison】MOVA constructed a 732-sample bilingual (Chinese/English) Arena human-evaluation set; UniTalking conducted a 20-rater × 50-prompt blind preference study — both are limited in scale but at least involve real human participants; OHBench shows no equivalent evidence in its main text.

## Audio-Video Alignment

### Audio-video synchronization detection method (lip sync, event alignment)

In OmniHuman, audio-visual synchronization is given a role beyond the ordinary — it serves not only as a quality-filtering condition but also as the generative mechanism for the structured annotation of "speaker attribution," one of this work's most valuable designs:
【Conventional use: sync-quality filtering】SyncNet is used to determine lip-audio alignment, with samples failing to meet the bar discarded.
【Distinctive use: audio-visual attribution】In multi-person scenes, knowing merely that "the audio is synchronized with the picture" is insufficient — one must also know "who said this." OmniHuman's solution is a complete attribution chain:
1) 3D-Speaker performs speaker diarization, yielding M active speech segments and their speaker indices;
2) YOLOv11 + MOTRv2 yields the visual ID tracklet of each person in the picture;
3) SyncNet responses are computed between every audio segment and every visual tracklet;
4) Greedy matching: each audio segment is assigned to the visual ID tracklet with the highest response;
5) ArcFace face embeddings confirm identity consistency (similarity > 0.55).
That is, SyncNet is upgraded from a "scorer" to a "matcher" — using the relative magnitude of sync response to solve the attribution problem, which carries far more information than a simple threshold. This is also the technical basis on which OmniHuman is able to provide speaker annotation and support two-person dialogue data.
【Retention condition】A sample is retained only if "all detected subjects" have an S_sync above a preset threshold and a time offset within ±3 frames. Note the wording "all detected subjects" — this is a unanimous-pass rule rather than a majority-pass rule, a fairly strict constraint for two-person and multi-person scenes, and it explains why the dataset covers only single-person, two-person, and person-object categories and no scenes with more people (the more people involved, the lower the probability of everyone passing).
【The meaning of ±3 frames】At the uniform 30 FPS, ±3 frames = ±100 milliseconds. This tolerance roughly matches the human perceptual threshold for audio-visual desynchronization (generally, audio lagging by less than 100ms or leading by less than 50ms is hard to notice) — a reasonable engineering value.
【Byproduct: lip-sync quality retained as annotation】Frame-level annotation includes a lip-sync quality assessment — i.e., sync quality is not used only for filtering, but is also retained as a queryable field, letting downstream users filter a stricter subset accordingly.
【Event-level alignment: not addressed】The dataset's domain is human-centric speech content, with no event-alignment detection for foley sound effects (no AV-align, no Synchformer). But on the evaluation side, ImageBind is used to measure the temporal offset of audio-visual events (the V-A metric), which to some extent covers non-speech audio-visual correspondence.
【Sync metrics on the evaluation side】OHBench's individual tier uses SyncNet to measure lip-audio-alignment accuracy; the global tier uses ImageBind to measure the temporal offset of audio-visual events. The two divide the labor between "lip-level" and "event-level," with complementary granularity.

### Specific synchronization-detection metrics and thresholds (SyncNet/Synchformer/LSE/in-house, threshold values, e.g. MOVA's LSE-D≤9.5 and LSE-C≥4.5, SkyReels-V4's SyncNet |offset|≤3∧conf>1.5) ⚠️

【Metric used on the data side】SyncNet response score S_sync + time offset, jointly determined.
【Values disclosed】
- Time-offset tolerance: ±3 frames (at the uniform 30 FPS, i.e., ±100 milliseconds) — the only clearly given numeric value on the sync dimension;
- Face-embedding similarity threshold: 0.55 (ArcFace cosine similarity, used for identity assignment, working together with sync determination to complete attribution);
- Tracking-loss tolerance: 5 frames.
【Key values not disclosed】The threshold for S_sync itself is only described in the paper as being "above a preset threshold" — i.e., the most core sync-score bar is left blank. This is a noticeably coarser disclosure granularity than works such as MOVA (LSE-D ≤ 9.5 and LSE-C ≥ 4.5) and SkyReels-V4 (|offset| ≤ 3 and conf > 1.5), which give explicit dual thresholds. It is worth noting that OmniHuman gives the offset threshold (3 frames) but omits the confidence threshold — disclosing exactly half of the two necessary conditions. [Uncertain]
【Strictness of the decision logic】"All detected subjects must satisfy" — a unanimous rule rather than an any-one rule; this is more important information than the threshold value itself, meaning that in a two-person scene, if even one person's speech attribution is uncertain, the entire sample is discarded.
【SyncNet variant unstated】It is not specified whether the original SyncNet, which implementation of SyncNet-python, or a retrained version is used; nor is it stated whether S_sync is reported as a confidence or a distance measure. [Uncertain]
【Sync metrics and thresholds on the evaluation side】In OHBench:
- Lip-Sync (individual tier): SyncNet, measuring the lip-audio-alignment accuracy of generated video, with no qualifying threshold given (reported as a continuous score);
- V-A / Audio-Visual Sync (global tier): ImageBind, measuring the temporal offset between visual and auditory events, reported as a continuous score.
【A consistency issue with the training-data threshold】Data filtering uses SyncNet + ±3 frames, and the evaluation also uses SyncNet — the same model both screens the data and judges the resulting effect, presenting a mild risk of circular reasoning (a model trained on SyncNet-filtered data will naturally do well on a SyncNet-based metric). The paper does not discuss this. [Uncertain]

### Separate handling of temporal sync vs. semantic sync (temporal alignment and content-semantic matching as two independent filtering conditions) ⚠️

OmniHuman achieves a fairly clear separation between the temporal and semantic dimensions, and this separation is embodied on both the data side and the evaluation side:
【Data side: separate handling at three levels】
- Temporal layer (frame-level alignment): SyncNet's time offset, a hard constraint of ±3 frames. Governs "whether the moment of speaking is correct";
- Attribution layer (source-identity sameness): SyncNet response greedy matching + ArcFace similarity of 0.55. Governs "whether this sound was produced by this person in the picture" — a layer absent in most works (UniTalking uses LightASD to do something similar, but only as a binary filter, whereas OmniHuman performs segment-by-segment assignment);
- Semantic layer (content plausibility): Gemini-3 assesses background plausibility and interaction plausibility. Governs "whether this scene and this interaction make sense semantically/physically."
The three criteria are entirely independent — offset is signal-level, attribution is matching-level, and semantics is comprehension-level, each handled by a model of a different nature (a dedicated sync model / a matching algorithm / a large model), so they do not obscure one another. This layering adds one more level than UniTalking's two layers (LightASD attribution + LipSync timing) — a semantic-judgment layer.
【Evaluation side: likewise separated】
- Temporal sync: V-A (ImageBind, audio-visual event temporal offset) and Lip-Sync (SyncNet, lip-level);
- Semantic matching: T-A (CLAP, semantic similarity between audio and text) — measures whether the generated sound semantically matches the text description, independent of timing;
- Interaction semantics: subjective Gemini-3 dimensions such as IN (interaction naturalness), LR (listener realism), ES (emotion similarity), and CN (contact naturalness), measuring the semantic/behavioral coordination between multiple subjects.
【A noteworthy semantic dimension: emotional coordination】ES (Emotion Similarity) evaluates "coordinated emotional expression" between two people — a cross-subject semantic consistency that is neither temporal alignment nor a single-subject attribute, with no precedent seen among comparable benchmarks.
【Limitations】It is not stated whether the semantic-layer determination on the data side (Gemini-3's background plausibility/interaction assessment) functions as a hard filtering condition or merely as an annotation field, and no scoring threshold is given. [Uncertain]

### Audio quality filtering (SNR, silence detection and silence-ratio thresholds, removal of tracks with no audio, removal of off-screen sound sources, background-music separation) ⚠️

Audio governance sits at Stage 2 of the pipeline, the only stage among the four filtering stages dedicated specifically to audio:
【Removal conditions (three types)】
- Missing tracks: silent videos are directly discarded, guaranteeing that the dataset is 100% populated with native audio tracks;
- Abnormal duration: samples where the audio track's duration does not match the video's duration, or falls outside a preset range, typically corresponding to technical faults such as container errors or truncated audio tracks;
- Low quality: the paper indicates the criteria include silence ratio and volume thresholds, but no specific values are given. [Uncertain]
【Source separation rather than filtering: the core strategy】Demucs is used for four-source separation, taking vocals as the target track and the other three sources mixed as the background track. This step does not discard any sample; instead it converts the "background-noise interference" problem from a "filtering problem" into a "representation problem" — a sample with BGM is no longer noise but becomes two separately usable tracks of data. This is the most critical trade-off on the audio side of this dataset, and the reason it can sustain a million-sample scale on a BGM-saturated data source like YouTube (adopting a UniTalking-style "discard if there's background sound" policy would collapse the retention rate).
【Handling of off-screen sound sources】There is no explicit "off-screen-sound removal" step; instead this is achieved implicitly through SyncNet attribution matching — if a speech segment cannot be matched to any visual tracklet in the picture (voiceover, off-screen sound, post-dubbing), the sample is discarded because "all subjects must satisfy the sync condition." The effect is equivalent to off-screen-sound removal, but the mechanism is attribution failure rather than dedicated detection.
【SNR】No mention of a signal-to-noise-ratio metric or threshold. The volume threshold can be viewed as a partial substitute, but is not equivalent. [Uncertain]
【Audio quality recorded in annotation】Individual-tier annotation includes "speech quality annotations" — i.e., audio quality is not used only for filtering but is also retained as a queryable field, letting downstream users filter a high-audio-quality subset accordingly.
【Sample-rate normalization】Unified to 44.1 kHz.
【Audio-quality metrics on the evaluation side】OHBench global tier: the mean of the four Audiobox Aesthetics dimensions (AbS, comprising content enjoyment, content usefulness, production complexity, production quality), KL divergence, and Fréchet Distance (FD); individual tier: DNSMOS's OVRL score (Speech Realism) and SenseVoice-computed WER (pronunciation accuracy). Using Audiobox-Aesthetics for audio-aesthetic evaluation is a relatively recent choice, more information-rich than the traditional single FAD metric.

### Classification and separate handling of speech/sound-effects/music ⚠️

【Core mechanism: binary regrouping after Demucs four-source separation】The original mixed audio track is separated by Demucs into four sources (vocals / drums / bass / other), then regrouped into two tracks: the vocal track (target) and the background track (the remaining three sources mixed). This is the infrastructural basis for how this dataset handles audio types.
【Speech】Extracted separately as the target track and subjected to a complete processing chain: 3D-Speaker separation → FunASR-Nano transcription → SyncNet attribution matching → emotion annotation → timestamps → speech-quality scoring. Speech is the most thoroughly annotated audio type.
【Music】Not discarded, but instead annotated with three attributes: type, mood, and relative volume. "Relative volume" makes the energy ratio between music and vocals a filterable dimension. The music signal itself is fully preserved within the background track.
【Background sound/ambient sound】The background sound labels field in video-level annotation; whether the specific label system is free text or a closed category set is not stated. [Uncertain]
【Sound effects】Explicitly listed in the Stage-one attribute-extraction checklist (appearance / motion / expression / speech / music / sound effects), indicating that Qwen3-Omni does extract sound-effect information; but no corresponding independent annotation field is described, and it is unclear whether it ultimately gets folded into the caption narrative or listed as a standalone field. Compared with Foley-Omni's dedicated three-field design, sound effects are a secondary dimension here — consistent with the dataset's human-centric positioning. [Uncertain]
【Silence】Filtered as one of the low-quality conditions (a silence-ratio threshold), not retained as an independent category.
【Proportion of each type】No time-duration proportion statistics are given at all. [Uncertain]
【Comparison with two existing routes】UniTalking follows "keep only speech, discard everything else" (a purification route); UniVerse-1 follows "bucket by speech/non-speech and control the ratio at 15.4% : 84.6%" (a mixture-ratio route); OmniHuman follows "neither discard nor bucket — decompose via source separation and annotate separately" (a decoupling route). The third route has the highest data-utilization efficiency and the greatest downstream flexibility, at the cost of shifting the responsibility for soundscape composition entirely onto the user — the dataset itself makes no commitment about soundscape composition.

## Training Integration

### Multi-stage training curriculum and data-curriculum scheduling (basis for stage division: resolution/duration/quality score/modality; low-res→high-res, image→video, short→long) ⚠️

This entry is a dataset and evaluation benchmark, not a model, and contains no training-curriculum design of its own. Relevant information can only be observed indirectly from its sole validation experiment and its data structure:
【Training setup of the validation experiment】Fine-tuning LTX-2 with a 20% subset of OmniHuman (180,000 single-person + 20,000 two-person = 200,000 samples), a single-stage SFT fine-tune with no multi-stage curriculum, no resolution progression, and no duration progression. The paper does not disclose the specific hyperparameters, training steps, or compute resources used for this fine-tuning. [Uncertain]
【The data structure's capacity to support curriculum design】Although the dataset itself does not prescribe a curriculum, its annotation system provides users with rich layered bases for building their own curriculum:
- Layering by quality: CLIP aesthetic score, DOVER score, face-clarity Cs, and speech-quality annotation are all queryable fields, from which a high-quality subset can be cut for use during annealing or SFT;
- Layering by complexity: single-person → two-person → person-object interaction forms a natural difficulty progression, the most natural curriculum dimension of this dataset;
- Layering by resolution/duration: the metadata contains fps, duration, and resolution, supporting the classic low-res→high-res, short→long curriculum;
- Layering by modality: the separation of vocal and background tracks supports a modal progression of "learn speech sync first, then full soundscape";
- Layering by shot language: shot-scale and camera-motion labels support a progression from simple fixed camera positions to complex camera work.
This pattern of "the dataset provides layered metadata, the curriculum is assembled by the user" is a reasonable positioning for a dataset-type work.
【A curriculum clue revealed by evaluation】The evaluation shows that "models degrade in performance on shot transitions from close-up to wide shot" and that "identity distortion is more severe in two-person scenes" — these two findings point directly to where curriculum design should focus effort (shot-scale diversity and multi-person complexity), reflecting the dataset's diagnostic capability.

### Changes in data mixture ratio across training stages (pretraining/annealing/SFT high-quality subset) ⚠️

This entry contains no mixture-ratio design of its own for training stages. Observable related information:
【Mixture ratio of the validation experiment】When fine-tuning LTX-2, a composition of 180,000 single-person : 20,000 two-person = 9 : 1 is used. This is the only explicit data mixture ratio appearing in the paper, but the paper does not explain the rationale for this ratio's selection, nor does it conduct a mixture-ratio ablation (e.g., how would 5:5 or 7:3 fare). A ratio of 9:1 is roughly close to the dataset's own natural single-person/two-person distribution (Figure 3(b)), so it is more likely proportional sampling than a deliberately configured ratio. [Uncertain]
【The rationale for using 20% is unstated】Why only 20% was used rather than the full dataset is not explained by the paper — it could be a compute-budget limitation, or it could be a deliberate demonstration that "even using just one-fifth already shows significant improvement." If it were the latter, this could have been a compelling argument, but the paper does not frame it that way. [Uncertain]
【Person-object interaction samples not included in fine-tuning】The fine-tuning samples include only single-person and two-person data, excluding the person-object interaction category, while the evaluation set includes 50 person-object interaction videos. This means the LTX-2 fine-tuning experiment is effectively zero-shot on the person-object dimension, and its performance on the OC / CN metrics deserves separate scrutiny, but the paper does not break down results by category. [Uncertain]
【Pretraining/annealing/SFT split】Not applicable (the dataset makes no such split; it is left to the user).

### Post-training data (scale and screening criteria of the curated SFT set, number of preference pairs and how they are annotated, reward-model training data)

This entry is a dataset and benchmark, and provides no post-training-data assets:
【Curated SFT set】The dataset does not pre-designate a "curated high-quality subset," nor does it give a recommended quality-score cutoff. But since scores such as CLIP aesthetic score, DOVER, face clarity, and speech quality are all retained as annotation fields, users can construct a curated set at any level of strictness themselves — actually more flexible than a fixed, pre-designated subset.
【Preference pairs / DPO data】None. The dataset contains no paired preference annotation, no human preference ranking, and no better/worse sample pairs.
【Reward-model training data】None. But OHBench's metric system can functionally serve as a partial substitute for a reward model: most of its seven dimensions (IQ, DD, V-A, T-A, Lip-Sync, ID Fidelity, WER, SQ) are automatically computable continuous scores, in principle directly usable as a reward signal for RL or best-of-n; the subjective dimensions scored by Gemini-3 (BP, IN, LR, ES, OC, CN, AC) could serve as an LLM-as-judge-style reward. The paper does not claim this use case, but it is an evident extension value of OHBench.
【The paper's own post-training experiments】Only a single LTX-2 SFT fine-tuning experiment; no RLHF/DPO-related experiments.

### Data-processing infrastructure and throughput (NeMo Curator/Data-Juicer/in-house, GPU acceleration ratio, processing scale, cost) ⚠️

Data-processing infrastructure is one of the least-disclosed dimensions of this work:
【Framework】No existing data-processing framework such as NeMo Curator or Data-Juicer is used, nor is it stated whether an in-house scheduling system exists. The pipeline is described as "a chain of model calls," with the engineering-implementation level (distributed scheduling, failure retries, intermediate-result storage, incremental processing) not addressed at all. [Uncertain]
【Throughput and cost】No data given at all: no GPU-hour figures, no processing speed, no speedup ratio, no total cost, no processing timeline. [Uncertain]
【Inferable cost scale (with no basis in the paper)】This pipeline's computational burden is heavyweight among comparable works, since every surviving sample must run through: TransNetV2 + OCR + logo detection + Demucs four-source separation + CLIP aesthetics + DOVER + UniMatch optical flow + SigLIP + YOLOv11 + MOTRv2 + DWPose-L + SMPL/MANO fitting + 3D-Speaker + SyncNet + ArcFace + FunASR-Nano + Qwen3-Omni + Gemini-3 — 18 models in total. Of these, million-scale video inference with Qwen3-Omni and million-scale API calls to Gemini-3 are the two largest cost items — especially the latter, which involves a closed-source commercial API; the cost of calling it at million-sample scale would be considerable, and the paper's complete silence on this is a clear information gap.
【A light-to-heavy cost-design consciousness】The paper explicitly proposes a lightweight-to-heavy filtering strategy, showing a clear cost consciousness on the team's part: cheap models (CLIP scoring) do the heavy lifting of elimination up front, while expensive models (DOVER, tracking, MLLM, Gemini-3) process only the small number of survivors afterward. This is the most effective lever for controlling total cost, but its actual savings cannot be quantified due to the absence of stage-by-stage retention rates.
【Engineering quality of the release】The GitHub repository provides a complete evaluation toolkit (scripts, configuration, dependencies, checkpoints), and HuggingFace provides sharded tar files with a JSONL index to support streaming scan-and-load — the release's engineering completeness is relatively high, but this pertains to evaluation and consumption-side infrastructure, not data-production-side infrastructure.

## Comparative Results

### Quantitative impact of data-strategy ablations (distinguishing: filtering-strictness ablation / caption-density-and-style ablation / data-mixture ablation, and the corresponding evaluation metrics) ⚠️

This work's validation of data effectiveness takes the form of "a single fine-tuning experiment + across-the-board metric improvement," with moderate sufficiency of evidence:
【Experimental setup】Using 20% of OmniHuman (180,000 single-person + 20,000 two-person = 200,000 samples) to fine-tune the open-source AV joint-generation model LTX-2, comparing full-metric performance on OHBench before and after fine-tuning.
【Reported improvement magnitudes】
- Audio quality: KL divergence improved by 25.9%, Fréchet Distance improved by 12.3%, aesthetic score (Audiobox Aesthetics) improved by 11.9%;
- Multimodal alignment: text-audio alignment (T-A, CLAP) improved by 25.0%, video-audio alignment (V-A, ImageBind) improved by 11.1%;
- Video quality: dynamic degree (DD, RAFT optical flow) improved by 10.7%;
- The paper states "performance gains documented across all metrics."
【Interpretation of the results】The three largest improvements are concentrated in the audio and audio-visual-alignment dimensions (KL 25.9%, T-A 25.0%, FD 12.3%, V-A 11.1%), rather than visual quality — highly self-consistent with the dataset's distinctive features: OmniHuman's true increment relative to existing data lies in its fine-grained audio-side annotation (Demucs separation, music attributes, speech attribution, emotion) and the strictness of its audio-visual attribution, while visual quality is constrained by the base model itself. This distribution can be regarded as credible circumstantial evidence for the data's contribution.
【The missing ablations (this work's main methodological shortcoming)】The paper only performs a binary "with/without OmniHuman data" comparison, with no data-strategy ablation along any dimension:
- No filtering-strictness ablation (what would happen if the DOVER / SyncNet thresholds were relaxed);
- No caption-density/style ablation (the effect of hierarchical captions vs. simple captions);
- No data-mixture ablation (the impact of the single-person:two-person ratio, or of including person-object interaction samples);
- No annotation-dimension ablation (how much each of skeleton annotation, music attributes, and speaker attribution contributes individually);
- No data-volume ablation (a scaling curve for 20% vs. 50% vs. 100%).
For a paper whose primary contribution is a dataset and pipeline, the absence of ablations addressing "which filtering stage in the pipeline is most critical" and "which type of annotation is most valuable" means many of its design choices (two-stage captioning, the placeholder mechanism, 134 keypoints) lack quantitative support. [Uncertain]
【Cross-sectional comparison experiment (not an ablation)】On the I2AV task, 10 models are evaluated: closed-source Veo3.1, Wan2.5, Sora2, Kling2.6, SeedDance-1.5-pro; open-source UniVerse-1, UniAVGen, Ovi, MOVA, LTX-2. In the speech-to-video task, InfiniteTalk is best on some metrics.
【Diagnostic findings (the value of the benchmark)】(1) Models generally degrade in performance when the shot transitions from close-up to wide shot; (2) identity distortion is significantly more severe in two-person scenes than in single-person scenes. These two findings are exactly the value proposition of the three-tier evaluation system's design — a traditional single composite score cannot pinpoint specific failure modes such as "shot-scale transitions" and "multi-person identity." Detailed case analysis is placed in the supplementary material.

### Evidence for quality vs. quantity (cases where small, curated data outperforms large, messy data) ⚠️

This work does not directly argue that "small and curated beats large and messy," but it offers two pieces of indirect evidence:
【Evidence one: a 20% subset already produces across-the-board improvement】Fine-tuning used only one-fifth of the dataset (200,000 out of 1 million clips), yet already achieved improvement on every metric in OHBench, with improvements in the audio and alignment dimensions reaching 11%–26%. If the paper had intended it, this could have served as direct evidence for "the efficiency of curated data," but the paper does not frame it this way, nor does it provide a comparison curve between 20% and 100% — so strictly speaking this only shows "a small amount of data is already effective," not that "a small amount of curated data beats a large amount of messy data." [Uncertain]
【Evidence two: the improvements concentrate on the dimensions corresponding to fine-grained annotation】The metrics with the largest improvements (KL 25.9%, T-A 25.0%, FD 12.3%, V-A 11.1%) all fall on audio quality and audio-visual alignment, precisely the two directions in which OmniHuman has invested the most annotation precision relative to existing datasets; whereas the improvement in the visual-quality dimension is comparatively mild. This correspondence indirectly supports the claim that "annotation quality determines the direction of capability gain."
【This dataset's founding motivation is not itself "small and curated"】The paper's problem diagnosis is "structural flaws" (insufficient scene diversity, sparse interaction modeling, insufficient attribute alignment) rather than "the data is too dirty," and its solution is "filling in the missing structural dimensions" rather than "cleaning the data more thoroughly." Its stance in the quality-vs-quantity debate is therefore closer to "dimensional completeness first" — i.e., the bottleneck is held to lie not in how much data there is or how clean it is, but in which structural dimensions are covered (person-object interaction, speaker attribution, shot language, music attributes). This is a third position orthogonal to "small and curated," and it is the most distinctive viewpoint of this entry relative to other dataset-focused works.
【Lack of a direct comparison】No same-scale controlled experiment (e.g., "OmniHuman's 200,000 clips vs. 200,000 clips from another dataset") was performed, so its quality advantage relative to OpenHumanVid, SpeakerVid-5M, and others is supported only qualitatively by Table 1's capability matrix (presence/absence of certain annotation types), with no quantitative evidence. [Uncertain]

### Alignment between training-data domain distribution and the evaluation-benchmark category system (e.g. VABench's seven major categories) ⚠️

The alignment between training-data distribution and the evaluation category system is this work's most structurally rigorous aspect — the dataset and the benchmark are threaded through by the same three-tier ontology, a typical example of "the dataset and benchmark co-designed together":
【The three-tier ontology runs through everything】The paper's problem diagnosis, the dataset's annotations, and the evaluation system correspond strictly one-to-one:
- Diagnosis 1, "limited global scene and camera diversity" → data-side video-level annotation (scene type/shot scale/camera motion/background/lighting/background sound/music attributes) → evaluation-side global tier (video quality IQ/DD/BP, audio quality AbS/KL/FD, multimodal alignment V-A/T-A);
- Diagnosis 2, "sparse interaction modeling (human-human + human-object)" → data-side frame-level annotation (human-human interaction labels including speaker ID and emotion, human-object interaction annotation, 134 keypoints) → evaluation-side relational tier (human-human: IN/LR/ES/IC*; human-object: OC/CN);
- Diagnosis 3, "insufficient individual-attribute alignment" → data-side individual-level annotation (ID, appearance, movement, expression, speech transcript with emotion, speech quality) → evaluation-side individual tier (subject-video: ID Fidelity/Attribute Consistency/Lip-Sync; subject-audio: WER/SQ).
This "problem–data–evaluation" triple alignment gives the benchmark diagnostic power rather than being a mere scoring tool: when a particular metric drops, it can be traced directly back to the corresponding annotation dimension in the dataset.
【Correspondence between the evaluation set's composition and the dataset's categories】OHBench's 509 videos are composed of 331 single-person / 128 two-person / 50 person-object, corresponding one-to-one to the dataset's three human-configuration categories, with the ratio broadly reflecting task-difficulty progression rather than the natural data distribution.
【An important counter-design: a deliberate domain gap】Although the evaluation videos are selected from OmniHuman, they are explicitly required to have a domain gap relative to the training set — i.e., deliberately avoiding the same distribution between the evaluation and training sets. This is a necessary self-constraint in works where the dataset and benchmark share the same origin, preventing the benchmark from becoming an overfitting test on one's own data. However, the paper does not state how the domain gap is defined or measured (by scene category? by content type? by source channel?), nor does it quantify the size of the gap. [Uncertain]
【Relationship to VBench-type benchmarks】The paper explicitly criticizes existing metrics (such as VBench's aesthetic score) as "often inconsistent with human perception," with its improvement path being to introduce large models such as Gemini-3 for semantic/physical-level judgment in place of shallow scorers. This is a common trend among 2026 evaluation benchmarks (sharing the same origin as MOVA's use of a large model for adjudication), but as noted in human_in_loop, the quantitative evidence for its "consistency with human perception" is missing from the main text, which limits the persuasiveness of this core claim.
【A complete list of the seven dimensions (an analogy to VABench's seven major categories)】OHBench's three tiers and seven dimensions: three global-tier dimensions (video quality, audio quality, multimodal alignment) + two relational-tier dimensions (human-human interaction, human-object interaction) + two individual-tier dimensions (subject-video quality, subject-audio quality). Compared with a traditional benchmark organized only by "quality/consistency/diversity," organizing by a "global-relational-individual" spatial hierarchy is a new organizing paradigm, particularly suited to multi-subject, human-centric scenes.
